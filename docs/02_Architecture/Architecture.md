 
# الهيكل العام لمنصة الحجر الصحي القومي (NQP)
 National Quarantine Platform - الإصدار النهائي 2.0 

---

## 1. رؤية المنصة (Vision)

منصة وطنية متكاملة تهدف إلى رقمنة جميع إجراءات الحجر الصحي في المنافذ الجوية والبحرية والبرية في السودان. تقدم المنصة خدماتها للمسافرين، وشركات الطيران، والجهات الحكومية، مع توفير نظام مركزي لإدارة الصحة العامة، وتقييم المخاطر، والترصد الوبائي، والتكامل مع اللوائح الصحية الدولية (IHR).

---

## 3. الطبقات المعمارية (Architecture Layers)

```
                    المستخدمون (المسافرين، الموظفين، الإدارة)
                         │
                         ▼
                الموقع الإلكتروني + بوابات المستخدمين
                         │
                         ▼
                 واجهات برمجة التطبيقات (API Layer)
                         │
                         ▼
              منطق الأعمال (Business Services Layer)
                         │
                         ▼
               بوابة التكامل (API Gateway / Service Bus)
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   الأنظمة الحكومية   الأنظمة الصحية   الأنظمة الخارجية
        │                │                │
        └────────────────┼────────────────┘
                         │
                         ▼
                قاعدة البيانات المركزية (PostgreSQL + PostGIS)
                وذاكرة التخزين المؤقت (Redis)
```

### شرح الطبقات

1.   طبقة العرض (Presentation Layer):
  الموقع العام () والبوابات الثمانية (React/). تتفاعل مع المستخدمين عبر واجهات ويب متجاوبة (RWD).

2.   طبقة واجهات API (API Layer): 
 Django REST Framework. توفر نقاط نهاية (Endpoints) موثقة (Swagger/OpenAPI) لكل خدمة.

3.   طبقة خدمات الأعمال (Business Layer):
  خدمات منفصلة (مثل خدمة تقييم المخاطر، خدمة توليد QR، خدمة الترصد). تحتوي على المنطق الأساسي للمنصة.

4.   طبقة التكامل (Integration Layer): 
 تتعامل مع الاتصال بالأنظمة الخارجية، وتحويل تنسيقات البيانات، وإدارة الطلبات غير المتزامنة عبر الـ Message Queue.

5.   طبقة تخزين البيانات (Data Layer): 
 قاعدة البيانات العلائقية (PostgreSQL) للمعاملات (Transactions)، و PostGIS للبيانات الجغرافية (متعلقات المتابعة)، و Redis للجلسات والتخزين المؤقت للـ QR Codes.

## 4. الأدوار والصلاحيات (Roles & Permissions)

بناءً على `init.sql`، تم تعريف الأدوار التالية، مع توضيح أن  دور `SUPER_ADMIN` هو المسؤول عن إدارة النظام والموقع معاً :

| المعرف (UUID) | الاسم (Role) | الوصف (Description) |
| :--- | :--- | :--- |
| `...001` |  SUPER_ADMIN  |  مدير النظام ومدير الموقع . صلاحيات كاملة (إدارة مستخدمين، منافذ، محتوى الموقع، أخبار، ووثائق). |
| `...002` | FEDERAL_MANAGER | المدير العام للحجر الصحي. صلاحيات على التقارير الوطنية والإعدادات الاستراتيجية. |
| `...003` | SECTOR_MANAGER | مدير القطاع (مثل قطاع الخرطوم). يدير المنافذ التابعة له. |
| `...004` | PORT_MANAGER | مدير المنفذ (مطار، ميناء، معبر). يدير عمليات الفحص في منفذه. |
| `...005` | OFFICER | موظف الحجر الصحي. يقوم بمسح QR، الفحص الصحي، وتقييم المخاطر. |
| `...006` | DOCTOR | طبيب العيادة. يدير السجلات الطبية والإحالات. |
| `...007` | FOLLOWUP_OFFICER | موظف المتابعة. يتعامل مع جداول المتابعة والتقارير اليومية للمسافرين. |
| `...008` | LAB_TECHNICIAN | فني مختبر. يدير العينات والنتائج. |
| `...009` | FOOD_INSPECTOR | مفتش حجر غذائي. يدير عمليات التفتيش على الشحنات الغذائية. |

## 5. التطبيقات التقنية المقترحة (Django Apps)

لتقسيم الكود بشكل منطقي، نقترح إنشاء التطبيقات التالية داخل مشروع Django:

```text
nqp_backend/
├── apps/
│   ├── accounts/         # المصادقة (Login, JWT, Profile)
│   ├── users/            # إدارة المستخدمين والصلاحيات (لـ SUPER_ADMIN)
│   ├── travelers/        # المسافرون، التسجيلات، كود QR
│   ├── screening/        # الفحص الصحي وتقييم المخاطر
│   ├── clinic/           # العيادة، الإحالات، السجلات الطبية
│   ├── laboratory/       # المختبر، العينات، النتائج
│   ├── followup/         # المتابعة الصحية والتقارير اليومية
│   ├── food_quarantine/  # الحجر الغذائي (شحنات، تفتيش، شهادات)
│   ├── surveillance/     # الترصد الوبائي وتقارير IHR
│   ├── cms/              # إدارة محتوى الموقع (الصفحات، الأخبار، FAQ)
│   ├── integration/      # التكامل مع الأنظمة الخارجية (API Gateway)
│   └── reports/          # التقارير ولوحات المعلومات (BI)
├── core/                 # الإعدادات الأساسية، النماذج المشتركة، الأدوات المساعدة
└── config/               # ملفات الإعدادات (settings.py، urls.py)
```

## 6. قائمة التقنيات (Tech Stack)

| الطبقة | التقنية (Technology) |
| :--- | :--- |
|  قاعدة البيانات  | PostgreSQL 16 + PostGIS 3.3 |
|  التخزين المؤقت  | Redis (لـ QR Codes، الجلسات، التقييد Rate Limiting) |

|  المهام غير المتزامنة  | Celery + Redis Broker |

|  توثيق API  | drf-yasg (Swagger) |
|  الحاويات (Containers)  | Docker + Docker Compose |
|  السيرفر (Server)  | Nginx (عكس الخادم) + Gunicorn (تشغيل Django) |
|  المراقبة (Monitoring)  | Prometheus + Grafana |
|  التحكم بالإصدارات  | Git + GitHub |

## 7. المصادقة والأمان (Security)

-  المصادقة:  JWT (Access Token قصير العمر + Refresh Token طويل العمر).
-  التخويل:  RBAC (التحكم بالمستخدمين عبر الأدوار والصلاحيات المخزنة في قاعدة البيانات).
-  تسجيل الدخول الثنائي (2FA):  دعم اختياري للموظفين والإدارة.
-  تسجيل التدقيق:  جميع العمليات الحساسة (تعديل بيانات، إحالات، نتائج مختبر) تُسجل في جدول `audit_logs`.
-  حماية البيانات:  استخدام HTTPS، وتجزئة كلمات المرور باستخدام `bcrypt`.
