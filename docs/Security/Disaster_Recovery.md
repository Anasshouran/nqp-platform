# التعافي من الكوارث (Disaster Recovery) - NQP

## 1. الهدف
ضمان استمرارية الأعمال (Business Continuity) واستعادة الخدمات في حال حدوث كارثة (فشل في الخادم، هجوم سيبراني، كارثة طبيعية) من خلال تطبيق خطة تعافي من الكوارث (Disaster Recovery Plan) شاملة.

## 2. سيناريوهات الكوارث

| السيناريو | الوصف | التأثير | الأولوية |
| :--- | :--- | :--- | :--- |
| **فشل الخادم الرئيسي** | تعطل الخادم الرئيسي (Master). | تعطل جميع الخدمات. | عالية جداً |
| **فشل قاعدة البيانات** | تعطل قاعدة البيانات الرئيسية. | تعطل جميع الخدمات المعتمدة على البيانات. | عالية جداً |
| **هجوم سيبراني** | اختراق النظام أو هجوم (Ransomware). | تعطل الخدمات، فقدان البيانات. | عالية |
| **كارثة طبيعية** | حريق، فيضان، زلزال. | تعطل مركز البيانات بالكامل. | عالية |
| **خطأ بشري** | حذف بيانات عن طريق الخطأ. | فقدان البيانات الجزئي. | متوسطة |

## 3. أهداف التعافي (RTO & RPO)

| المقياس | الهدف | التوضيح |
| :--- | :--- | :--- |
| **RTO (Recovery Time Objective)** | < 4 ساعات | الحد الأقصى للوقت المسموح به لاستعادة الخدمات. |
| **RPO (Recovery Point Objective)** | < 15 دقيقة | الحد الأقصى لفقدان البيانات المسموح به. |

## 4. خطة التعافي من الكوارث (Disaster Recovery Plan)

### 4.1. مرحلة الاستعداد (Preparation)
| الإجراء | الوصف | التكرار |
| :--- | :--- | :--- |
| **نسخ احتياطي منتظم** | عمل نسخ احتياطية لقاعدة البيانات والملفات. | يومي |
| **اختبار الاستعادة** | اختبار استعادة النسخ الاحتياطية في بيئة معزولة. | ربع سنوي |
| **تحديث الخطة** | مراجعة وتحديث خطة التعافي. | سنوي |
| **تدريب الفريق** | تدريب الفريق على إجراءات التعافي. | سنوي |

### 4.2. مرحلة الاستجابة (Response)
| الإجراء | الوصف | المسؤول |
| :--- | :--- | :--- |
| **إشعار الفريق** | إشعار فريق الطوارئ (CSIRT). | مسؤول الأمن |
| **تقييم الضرر** | تحديد نطاق الضرر والخدمات المتأثرة. | مدير النظام |
| **تفعيل الخطة** | تفعيل خطة التعافي حسب السيناريو. | مدير النظام |

### 4.3. مرحلة الاستعادة (Recovery)
| السيناريو | الإجراء | الوقت المتوقع |
| :--- | :--- | :--- |
| **فشل الخادم الرئيسي** | التبديل التلقائي إلى الخادم الاحتياطي (Failover). | < 5 دقائق |
| **فشل قاعدة البيانات** | استعادة قاعدة البيانات من النسخ الاحتياطي (PITR). | < ساعة واحدة |
| **فشل مركز البيانات** | استعادة من النسخ الاحتياطي في موقع جغرافي آخر. | < 4 ساعات |
| **هجوم سيبراني** | عزل النظام المصاب، استعادة من النسخ الاحتياطية. | < 4 ساعات |
