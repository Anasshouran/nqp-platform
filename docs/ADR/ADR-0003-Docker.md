# ADR-0003: اعتماد Docker للحوسبة (Containerization)

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق DevOps / الهندسة المعمارية

---

## 1. السياق (Context)

تحتاج منصة NQP إلى بيئة تشغيل متسقة (Consistent) بين التطوير والاختبار والإنتاج، مع سهولة النشر والتوسع. يجب أن تدعم بيئة التشغيل:

- **توحيد البيئات**: بيئة تطوير متطابقة مع بيئة الإنتاج.
- **سهولة النشر**: نشر سريع وخالي من الأخطاء.
- **قابلية التوسع**: إضافة نسخ (Instances) جديدة بسهولة.
- **العزل**: عزل الخدمات عن بعضها البعض (أمان واستقرار).
- **إدارة الموارد**: التحكم في استخدام (CPU، RAM).

### الخيارات المتاحة (Options)

1. **Docker (مع Docker Compose)**
2. **Virtual Machines (VMs)**
3. **Bare Metal (خوادم فعلية)**
4. **LXC/LXD (Linux Containers)**

---

## 2. القرار (Decision)

**اعتماد Docker (مع Docker Compose للتطوير و Kubernetes للإنتاج) لتشغيل جميع مكونات المنصة في حاويات (Containers).**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **توحيد البيئات** | Docker يضمن أن بيئة التطوير مطابقة لبيئة الإنتاج (تقليل مشاكل "يعمل على جهازي"). |
| **سهولة النشر** | نشر تطبيق كامل (Django + React + PostgreSQL + Redis) بأمر واحد (`docker-compose up`). |
| **قابلية التوسع** | إضافة نسخ جديدة من الخدمات بسهولة (عبر Kubernetes أو Docker Swarm). |
| **العزل** | كل خدمة تعمل في حاوية منفصلة (عزل الموارد والأمان). |
| **إدارة الموارد** | التحكم في استخدام (CPU، RAM) لكل حاوية. |
| **دعم CI/CD** | يتكامل بسهولة مع (GitHub Actions) لبناء ودفع الصور. |
| **مجتمع كبير** | وثائق غنية، ودعم واسع، ومكتبة ضخمة من الصور الجاهزة (Docker Hub). |
| **التكامل مع Kubernetes** | Docker هو الأساس لـ Kubernetes (أداة التنسيق المختارة للإنتاج). |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- توحيد البيئات (Dev/Staging/Prod).
- نشر سريع وخالي من الأخطاء.
- سهولة التوسع الأفقي (Horizontal Scaling).
- إدارة الموارد بكفاءة.
- دعم CI/CD.

### سلبية (Negative)
- منحنى تعلم لفريق التطوير (Docker, Docker Compose, Kubernetes).
- إدارة الصور (Images) والتخزين (Volumes) قد تكون معقدة مع التطبيقات الكبيرة.
- أداء أقل قليلاً مقارنة بالخوادم الفعلية (Bare Metal) بسبب الطبقة الإضافية.

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **Virtual Machines (VMs)** | تستهلك موارد أكثر (OS كامل لكل VM)، ونشر أبطأ، وتوسع أقل مرونة. |
| **Bare Metal** | لا يوفر توحيد البيئات، ونشر يدوي، وصيانة معقدة. |
| **LXC/LXD** | أقل شيوعاً، ودعم أقل، وتكامل محدود مع أدوات CI/CD. |
