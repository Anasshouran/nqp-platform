# ADR-0008: اعتماد MinIO لتخزين الملفات (File Storage)

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق الهندسة المعمارية / فريق DevOps

---

## 1. السياق (Context)

تحتاج منصة NQP إلى نظام لتخزين الملفات (File Storage) لإدارة:

- مستندات المسافرين (صور جوازات السفر، شهادات التطعيم).
- المستندات الطبية (الصور، التقارير).
- شهادات الإفراج الغذائي (PDF).
- التقارير المصدرة (PDF، Excel).
- صور الشحنات الغذائية.

يجب أن يدعم نظام تخزين الملفات:

- **قابلية التوسع**: تخزين ملايين الملفات.
- **الأمان**: تشفير الملفات، والتحكم في الوصول.
- **أداء عالي**: تحميل وتنزيل سريع.
- **سهولة التكامل**: مع Django (django-storages).
- **الاستمرارية**: نسخ احتياطي واستعادة.

### الخيارات المتاحة (Options)

1. **MinIO (Self-Hosted S3)**
2. **Amazon S3**
3. **Google Cloud Storage**
4. **Azure Blob Storage**
5. **NFS / Local Storage**

---

## 2. القرار (Decision)

**اعتماد MinIO (متوافق مع S3) كحل أساسي لتخزين الملفات في بيئات التطوير والاختبار، مع إمكانية التبديل إلى Amazon S3 في بيئة الإنتاج.**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **متوافق مع S3 API** | يمكن التبديل بسهولة بين MinIO و Amazon S3 (نفس API). |
| **مفتوح المصدر** | لا توجد تكاليف ترخيص، مناسب للبيئات المحلية والتطوير. |
| **قابلية التوسع** | يمكن توسيع MinIO لتخزين ملايين الملفات. |
| **الأمان** | دعم تشفير (Server-Side Encryption) والتحكم في الوصول. |
| **سهولة التكامل** | يتكامل مع Django عبر (django-storages) و (boto3). |
| **أداء عالي** | أداء ممتاز مع الملفات الكبيرة والصغيرة. |
| **دعم النسخ الاحتياطي** | دعم (Replication) و (Snapshot). |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- تخزين مرن وقابل للتوسع.
- أمان عالي (تشفير، تحكم في الوصول).
- تكامل سهل مع Django عبر (django-storages).
- إمكانية التبديل إلى S3 بسهولة في الإنتاج.
- تكلفة منخفضة (مفتوح المصدر).

### سلبية (Negative)
- يتطلب إدارة خادم MinIO (DevOps).
- لا يوفر تخزينًا غير محدود (يعتمد على سعة الخادم).
- قد يكون أقل موثوقية من (Amazon S3) في حال لم يتم تكوينه بشكل صحيح.

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **Amazon S3** | تكلفة عالية في بيئات التطوير والاختبار. |
| **Google Cloud Storage** | تكلفة عالية، ومرتبط بـ Google Cloud. |
| **Azure Blob Storage** | تكلفة عالية، ومرتبط بـ Azure. |
| **NFS / Local Storage** | لا يدعم التوسع بسهولة، ولا يوفر أماناً كافياً. |
