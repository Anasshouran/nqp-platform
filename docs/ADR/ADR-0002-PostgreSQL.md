# ADR-0002: اختيار PostgreSQL كقاعدة بيانات رئيسية

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق الهندسة المعمارية / فريق البيانات

---

## 1. السياق (Context)

تحتاج منصة NQP إلى قاعدة بيانات علائقية (Relational Database) لتخزين البيانات الأساسية (المسافرين، الفحوصات، السجلات الطبية، العينات، الشحنات الغذائية). يجب أن تدعم قاعدة البيانات:

- **سلامة البيانات (ACID)**: خاصة في المعاملات الحرجة (مثل: تسجيل الفحوصات، إصدار الشهادات).
- **العلاقات المعقدة**: بين الجداول (Travelers ← Screenings ← Lab Results).
- **البيانات غير المنتظمة**: تخزين البيانات شبه المهيكلة (مثل: JSON للأعراض، الملاحظات).
- **الأداء العالي**: مع ملايين السجلات.
- **قابلية التوسع**: دعم (Replication) و (Partitioning).
- **الأمان**: تشفير البيانات، التحكم في الوصول.

### الخيارات المتاحة (Options)

1. **PostgreSQL**
2. **MySQL**
3. **Microsoft SQL Server**
4. **Oracle Database**

---

## 2. القرار (Decision)

**اعتماد PostgreSQL (الإصدار 16+) كقاعدة بيانات رئيسية للمنصة.**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **دعم JSONB** | تخزين البيانات غير المنتظمة (مثل: `observed_symptoms`, `clinical_notes`) بكفاءة عالية مع دعم الفهرسة (GIN Indexes). |
| **الامتثال لمعايير SQL** | متوافق مع معايير SQL، مما يسهل الترحيل والاستعلامات المعقدة. |
| **الأداء العالي** | أداء ممتاز مع الاستعلامات المعقدة والبيانات الكبيرة (بفضل (Query Optimizer) المتقدم). |
| **دعم (Replication)** | دعم (Streaming Replication) للنسخ الاحتياطي (High Availability). |
| **دعم (Partitioning)** | دعم (Table Partitioning) لتقسيم الجداول الكبيرة (مثل: `audit_logs`, `daily_health_logs`). |
| **الأمان** | دعم (SSL/TLS)، (Row-Level Security)، و (Encryption at Rest). |
| **مفتوح المصدر** | لا توجد تكاليف ترخيص، مع دعم مجتمعي كبير وتحديثات مستمرة. |
| **التكامل مع Django** | Django ORM يدعم PostgreSQL بشكل ممتاز (مع ميزات خاصة مثل (JSONField)). |
| **قابلية التوسع** | يدعم (Horizontal Scaling) عبر (Read Replicas) و (Sharding) (مستقبلياً). |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- تخزين مرن للبيانات غير المنتظمة (JSONB).
- أداء عالي مع الاستعلامات المعقدة.
- أمان قوي للبيانات الحساسة.
- دعم ممتاز من Django ORM.
- تكلفة منخفضة (مفتوح المصدر).

### سلبية (Negative)
- يتطلب خبرة في إدارة قواعد البيانات (DBA).
- إدارة النسخ الاحتياطي والاستعادة (Backup & Recovery) قد تكون معقدة مع البيانات الكبيرة.
- لا يدعم (Sharding) المدمج (يتطلب حلولاً خارجية).

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **MySQL** | دعم محدود لـ (JSON) مقارنة بـ PostgreSQL، وأداء أقل مع الاستعلامات المعقدة. |
| **Microsoft SQL Server** | تكاليف ترخيص عالية، وليس مفتوح المصدر. |
| **Oracle Database** | تكاليف ترخيص عالية جداً، وليس مفتوح المصدر. |
| **MongoDB (NoSQL)** | غير مناسب للبيانات العلائقية والمعاملات (ACID) المطلوبة. |
