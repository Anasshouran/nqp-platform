# ADR-0005: اعتماد Redis للتخزين المؤقت (Caching) وطابور الرسائل (Message Broker)

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق الهندسة المعمارية / فريق البيانات

---

## 1. السياق (Context)

تحتاج منصة NQP إلى آلية للتخزين المؤقت (Caching) لتسريع استعلامات قاعدة البيانات، وطابور رسائل (Message Broker) لإدارة المهام غير المتزامنة (Celery). يجب أن تدعم الآلية:

- **سرعة عالية**: تخزين مؤقت فائق السرعة (In-memory).
- **قابلية التوسع**: دعم التخزين المؤقت الموزع (Distributed Caching).
- **طابور رسائل موثوق**: إدارة المهام غير المتزامنة (مثل: معالجة قوائم الركاب، إرسال الإشعارات).
- **سهولة التكامل**: مع Django و Celery.

### الخيارات المتاحة (Options)

1. **Redis**
2. **Memcached**
3. **RabbitMQ**
4. **Apache Kafka**
5. **AWS ElastiCache (Redis/Memcached)**

---

## 2. القرار (Decision)

**اعتماد Redis (الإصدار 7+) كحل موحد للتخزين المؤقت (Caching) وطابور الرسائل (Broker) لـ Celery.**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **سرعة عالية** | تخزين مؤقت (In-memory) فائق السرعة (زمن استجابة < 1ms). |
| **دعم هياكل بيانات متعددة** | يدعم (Strings, Hashes, Lists, Sets, Sorted Sets) لتلبية احتياجات متنوعة. |
| **طابور رسائل (Broker)** | يمكن استخدام Redis كـ (Broker) لـ Celery (بديل لـ RabbitMQ). |
| **قابلية التوسع** | يدعم (Redis Cluster) للتخزين المؤقت الموزع. |
| **سهولة التكامل** | يتكامل بسهولة مع Django (django-redis) و Celery (celery-redis). |
| **مفتوح المصدر** | لا توجد تكاليف ترخيص، مع دعم مجتمعي كبير. |
| **حل موحد** | استخدام تقنية واحدة للتخزين المؤقت والرسائل (تبسيط البنية التحتية). |
| **الاستمرارية (Persistence)** | يدعم حفظ البيانات على القرص (RDB/AOF) للاسترداد بعد إعادة التشغيل. |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- تخزين مؤقت فائق السرعة لتسريع الاستعلامات.
- طابور رسائل موثوق لـ Celery.
- حل موحد (تقنية واحدة للـ Cache والـ Broker).
- سهولة التكامل مع Django و Celery.
- دعم (Redis Cluster) للتوسع.

### سلبية (Negative)
- **استخدام الذاكرة**: جميع البيانات تُخزن في الذاكرة (RAM)، مما يتطلب موارد كافية.
- **فقدان البيانات**: في حال تعطل Redis دون حفظ (Persistence)، قد تفقد البيانات (يتم معالجته عبر (Persistence) و (Replication)).
- **إدارة Redis Cluster**: يتطلب خبرة في إدارة (Redis Cluster) للتوسع الأفقي.

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **Memcached** | لا يدعم هياكل البيانات المتقدمة، ولا يمكن استخدامه كـ (Broker) لـ Celery. |
| **RabbitMQ** | جيد كـ (Broker)، لكنه لا يوفر التخزين المؤقت (Caching). يتطلب تقنية إضافية. |
| **Apache Kafka** | معقد جداً للمشروع الحالي، ويستخدم بشكل أفضل للتدفقات (Streaming) الكبيرة. |
| **AWS ElastiCache** | حل سحابي، لكنه مرتبط بـ AWS، وقد لا يكون متاحاً في البيئات المحلية. |
