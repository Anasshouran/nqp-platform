# ADR-0004: اعتماد JWT للمصادقة (Authentication)

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق الأمن / الهندسة المعمارية

---

## 1. السياق (Context)

تحتاج منصة NQP إلى آلية مصادقة آمنة وقابلة للتوسع للمستخدمين (المسافرين، الموظفين، شركات الطيران، الإدارة). يجب أن تدعم آلية المصادقة:

- **عديم الحالة (Stateless)**: لتسهيل التوسع الأفقي (Horizontal Scaling).
- **الأمان**: حماية البيانات الحساسة (الصحية، الشخصية).
- **سهولة التكامل**: مع واجهات (APIs) والتطبيقات (React، Flutter).
- **دعم (Refresh Tokens)**: لتجديد الجلسات دون إعادة المصادقة.
- **فصل الصلاحيات (Authorization)**: دعم (RBAC - Role-Based Access Control).

### الخيارات المتاحة (Options)

1. **JWT (JSON Web Tokens)**
2. **Session-based Authentication (Django Sessions)**
3. **OAuth2 / OpenID Connect**
4. **API Keys (للمستخدمين الخارجيين)**

---

## 2. القرار (Decision)

**اعتماد JWT (JSON Web Tokens) مع (Refresh Tokens) باستخدام `djangorestframework-simplejwt` كمصادقة أساسية للمستخدمين.**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **عديم الحالة (Stateless)** | لا حاجة لتخزين جلسات المستخدمين في الخادم، مما يسهل التوسع الأفقي. |
| **الأمان** | توقيع (Signature) يضمن سلامة البيانات ومنع التزوير (باستخدام HMAC-SHA256). |
| **صلاحية محدودة** | (Access Token) قصير الصلاحية (30 دقيقة)، و (Refresh Token) أطول (7 أيام) لتحقيق التوازن بين الأمان وسهولة الاستخدام. |
| **سهولة التكامل** | يمكن استخدام JWT مع أي عميل (React، Flutter، Postman). |
| **دعم (RBAC)** | يمكن تضمين دور المستخدم (Role) في (Payload) لتسهيل التحقق من الصلاحيات. |
| **دعم (Refresh Tokens)** | إمكانية تجديد (Access Token) دون إعادة إدخال كلمة المرور. |
| **التكامل مع Django** | مكتبة `djangorestframework-simplejwt` توفر تكاملاً سهلاً مع Django REST Framework. |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- توسع أفقي سهل (Stateless).
- أمان عالي مع توقيع (Signature).
- صلاحية محدودة (تقليل مخاطر السرقة).
- دعم (Refresh Tokens) لتجديد الجلسات.
- سهولة التكامل مع العملاء (React، Flutter).

### سلبية (Negative)
- **إلغاء التوكن (Token Revocation)**: صعوبة إلغاء JWT قبل انتهاء صلاحيته (يتم معالجته عبر (Refresh Token) الأسود).
- **حجم التوكن**: JWT قد يكون كبيراً إذا تم تضمين الكثير من البيانات (يتم تضمين البيانات الأساسية فقط).
- **التخزين الآمن**: يجب تخزين (Refresh Token) بشكل آمن (يفضل (HttpOnly Cookies) أو (Secure Storage)).
- **انتهاء الصلاحية**: يتطلب إدارة (Refresh) في العميل.

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **Session-based** | يعتمد على الحالة (Stateful)، مما يصعب التوسع الأفقي. |
| **OAuth2 / OpenID Connect** | معقد جداً للتطبيقات الداخلية، ويستخدم بشكل أفضل للتطبيقات الخارجية (Third-party). |
| **API Keys فقط** | غير آمن للمستخدمين النهائيين، ويستخدم عادةً للأنظمة الخارجية (Integration). |
