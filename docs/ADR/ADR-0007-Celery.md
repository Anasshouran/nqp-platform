# ADR-0007: اعتماد Celery للمهام الخلفية (Background Tasks)

**التاريخ**: 2024-07-26  
**الحالة**: مقبول (Accepted)  
**المسؤول**: فريق Backend / الهندسة المعمارية

---

## 1. السياق (Context)

تحتاج منصة NQP إلى آلية لتنفيذ المهام غير المتزامنة (Asynchronous Tasks) في الخلفية، مثل:

- معالجة قوائم الركاب (Passenger Manifest) الكبيرة.
- إرسال الإشعارات الجماعية (SMS، Push، Email).
- توليد التقارير الوطنية الثقيلة (PDF، Excel).
- مزامنة البيانات مع الأنظمة الخارجية (وزارة الصحة، WHO).
- المهام الدورية (Scheduled Tasks) مثل: التقارير اليومية، مزامنة ICD-11.

### الخيارات المتاحة (Options)

1. **Celery (مع Redis كـ Broker)**
2. **Django Q**
3. **RQ (Redis Queue)**
4. **Apache Kafka**
5. **AWS SQS + Lambda**

---

## 2. القرار (Decision)

**اعتماد Celery (مع Redis كـ Broker و Result Backend) لتنفيذ المهام غير المتزامنة والمجدولة (Celery Beat).**

---

## 3. الأسباب (Rationale)

| السبب | التوضيح |
| :--- | :--- |
| **التكامل مع Django** | Celery يتكامل بسلاسة مع Django (django-celery). |
| **دعم المهام المجدولة** | Celery Beat يوفر جدولة للمهام الدورية (مثل: التقارير اليومية). |
| **دعم إعادة المحاولة (Retry)** | إعادة محاولة المهام الفاشلة مع فترات متزايدة (Exponential Backoff). |
| **دعم المهام المعقدة** | يدعم تدفقات العمل المعقدة (Chains, Groups, Chords). |
| **مرونة Broker** | يدعم (Redis، RabbitMQ، SQS) كـ (Broker). |
| **مراقبة المهام** | يمكن مراقبة المهام عبر (Celery Flower). |
| **قابلية التوسع** | يمكن إضافة (Workers) جديدة لتوزيع الحمل. |

---

## 4. العواقب (Consequences)

### إيجابية (Positive)
- معالجة غير متزامنة للمهام الثقيلة دون تعطيل واجهات API.
- جدولة المهام الدورية (Celery Beat).
- إعادة محاولة المهام الفاشلة تلقائياً.
- مرونة في اختيار (Broker) (Redis، RabbitMQ).
- مراقبة المهام عبر (Celery Flower).

### سلبية (Negative)
- يتطلب تشغيل (Workers) منفصلة (زيادة في التعقيد التشغيلي).
- إدارة (Redis) كـ (Broker) تتطلب مراقبة إضافية.
- منحنى تعلم لفريق التطوير.

---

## 5. البدائل المرفوضة (Rejected Alternatives)

| البديل | سبب الرفض |
| :--- | :--- |
| **Django Q** | أقل شيوعاً، ومجتمع أصغر، ودعم محدود للمهام المعقدة. |
| **RQ (Redis Queue)** | أبسط، لكنه لا يدعم المهام المجدولة (مثل Celery Beat). |
| **Apache Kafka** | معقد جداً للمشروع الحالي، ويستخدم للتدفقات (Streaming) الكبيرة. |
| **AWS SQS + Lambda** | مرتبط بـ AWS، وليس مناسباً للبيئات المحلية. |
