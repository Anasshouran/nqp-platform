

# 11_External_Integrations - التكامل مع الأنظمة الخارجية

## 1. الهدف الاستراتيجي
ضمان تدفق البيانات بشكل آمن وفعال بين منصة الحجر الصحي القومي (NQP) وجميع الأنظمة الخارجية المعنية بالصحة العامة، الأمن، النقل، والتجارة. يهدف التكامل إلى:
- **القضاء على العزلة المعلوماتية**: ربط المنصة بالأنظمة الوطنية (وزارة الصحة، الجمارك، الجوازات) لضمان رؤية شاملة.
- **أتمتة الإجراءات**: تقليل التدخل البشري ونقل البيانات يدوياً بين الجهات.
- **الامتثال للقوانين**: تبادل البيانات وفقاً للمعايير القانونية والأمنية المعتمدة (حماية البيانات الشخصية).
- **تحسين الاستجابة**: إيصال المعلومات الحيوية (التنبيهات، التقارير) إلى الجهات المعنية في الوقت المناسب.

## 3. مبادئ التكامل العامة (Integration Principles)

| المبدأ | الوصف |
| :--- | :--- |
| **اللامركزية في الاتصال (Decentralized)** | كل جهة تتصل عبر واجهة برمجة (API) أو (SFTP) مخصصة لها، مع فصل تام لضمان الأمان وعدم التأثير المتبادل. |

| **الأمان المشدد (Security)** | استخدام (TLS 1.3)، مفاتيح API، و (JWT) للمصادقة، مع تشفير البيانات الحساسة. |

| **التسجيل والتدقيق (Audit)** | تسجيل كل عملية تبادل بيانات في (Audit Log) مع (الجهة، الوقت، البيانات المرسلة، حالة النجاح/الفشل). |

| **التعامل مع الأخطاء (Resilience)** | إعادة محاولة إرسال البيانات في حال فشل الاتصال (مع فترات متزايدة)، مع إشعار المسؤول في حال الفشل المتكرر. |

| **تنسيق البيانات الموحد (Standardization)** | استخدام تنسيق (JSON) للطلبات الفورية، و (XML/CSV) للتقارير الدورية، مع الالتزام بمعايير (FHIR) و (IHR) عند الاقتضاء. |

# الوحدة 12: التكامل مع الأنظمة الخارجية

**الوحدة المنطقية:** الربط مع الجهات الحكومية  
**التطبيقات التقنية (Django Apps):** `integration` (للواجهات)، `surveillance` (لإرسال بلاغات IHR)  
**المستخدمون:** أنظمة خارجية (M2M).

## الجهات المتكاملة

| الجهة      |      الغرض من التكامل |     طريقة التكامل |
| :---            | :---                |     :--- |
| وزارة الصحة الاتحادية |     تبادل بيانات الحالات الوبائية       | REST API / ملفات XML     |
| نظام الترصد الوبائي الوطني |         إرسال بلاغات الأمراض  | REST API (مع مصادقة)     |
| الجوازات والهجرة |  التحقق من صحة جوازات السفر          | REST API                |
| سلطات الطيران المدني |        استقبال جداول الرحلات      | Webhook / SFTP         |
| شركات الطيران |      استقبال كشوف المسافرين (Manifest) | REST API (مع مفتاح)     |
| هيئة الموانئ البحرية |          بيانات السفن القادمة         | REST API               |
| الجمارك |    تبادل بيانات الشحنات الغذائية                  | REST API               |
| المركز الوطني للوائح الصحية (IHR) | إرسال بلاغات الأحداث الصحية |     منصة إلكترونية موحدة |

## الاعتماديات (Dependencies)

- تعتمد على `core` (للـ Authentication و Logging).
- تعتمد على `surveillance` لسحب بيانات البلاغات.

# الوحدة 11: منصة التكامل (Integration Platform)

 الوحدة المنطقية:  البنية التحتية للتكامل  
 التطبيقات التقنية (Django Apps):  `integration`, `accounts` (للمصادقة)  
 المستخدمون:  (خلفية، مطورون، مسؤولو النظام).

## المكونات الرئيسية

1.  API Gateway:  نقطة دخول موحدة لجميع الطلبات (توجيه، تسجيل، تقييد).
2.  المصادقة المركزية (JWT):  إدارة التوكنات، الصلاحيات (RBAC).
3.  طابور الرسائل (Message Queue):  معالجة المهام غير المتزامنة (إرسال الإشعارات، إنشاء التقارير).
4.  سجل التدقيق (Audit Log):  تسجيل كل عملية حساسة مع IP والمستخدم.
5.  المراقبة (Monitoring):  تتبع أداء الـ API وحالة الخدمات.

## الجداول المرتبطة (في init.sql)

- `audit_logs`
- `api_integration_logs`

## الاعتماديات (Dependencies)

- تعتمد على `core` (للصلاحيات الأساسية).
- تعتمد على جميع التطبيقات الأخرى لتوفير نقاط API الخاصة بها.

# 16. التكامل مع الأنظمة الحكومية (Government Systems Integration)

## الهدف

تمكين منصة إدارة صحة المنافذ من تبادل البيانات بشكل آمن وفوري مع الأنظمة الحكومية والجهات ذات العلاقة، بما يضمن سرعة الإجراءات، ودقة البيانات، وتقليل الإدخال اليدوي.

---

## الأنظمة المتكاملة

### 1. نظام الجوازات والهجرة (Immigration & Passport System)

**الغرض:**
التحقق من بيانات المسافرين وحركة الدخول والخروج.

**البيانات المتبادلة:**

* رقم الجواز.
* الاسم.
* الجنسية.
* بيانات التأشيرة.
* تاريخ الدخول.
* منفذ الدخول.
* حالة الدخول أو المغادرة.

---

### 2. نظام سلطة الطيران المدني (Civil Aviation System)

**الغرض:**

الحصول على بيانات الرحلات الجوية.

**البيانات المتبادلة:**

* جدول الرحلات.
* رقم الرحلة.
* وقت الوصول.
* وقت المغادرة.
* بوابة الوصول.
* حالة الرحلة.

---

### 3. أنظمة شركات الطيران (Airline Systems)

**الغرض:**

استلام بيانات الرحلات وقوائم الركاب قبل وصول الطائرة.

**البيانات المتبادلة:**

* Passenger Manifest
* بيانات الركاب.
* بيانات أفراد الطاقم.
* أرقام المقاعد.
* تحديثات الرحلات.

---

### 4. نظام العيادات الصحية بالمنافذ (Port Health Clinics)

**الغرض:**

تحويل الحالات المشتبه بها إلكترونياً إلى عيادة الحجر الصحي.

**البيانات المتبادلة:**

* بيانات المسافر.
* نتائج الفحص الأولي.
* الإحالة الطبية.
* التشخيص.
* القرار الطبي.
* المتابعة.

---

### 5. وزارة الصحة

**الغرض:**

تبادل البيانات الصحية والإحصائيات الوطنية.

**البيانات المتبادلة:**

* الحالات اليومية.
* الحالات المؤكدة.
* المؤشرات الصحية.
* التقارير الوطنية.
* التنبيهات الصحية.

---

### 6. نظام الترصد الوبائي (Epidemiological Surveillance System)

**الغرض:**

الإبلاغ عن الأمراض الخاضعة للترصد والاستجابة السريعة للفاشيات.

**البيانات المتبادلة:**

* الأمراض المبلغ عنها.
* الحالات المشتبه بها.
* الحالات المؤكدة.
* بيانات المخالطين.
* مواقع الحالات.

---

### 7. أنظمة المنافذ

تشمل:

* المطارات.
* الموانئ البحرية.
* المعابر البرية.

**الغرض:**

تبادل بيانات الحركة اليومية للمسافرين ووسائل النقل.

**البيانات المتبادلة:**

* بيانات الوصول.
* بيانات المغادرة.
* وسائل النقل.
* عدد المسافرين.
* أوقات التشغيل.

---

### 8. نظام الرسائل والإشعارات

**الغرض:**

إرسال الإشعارات للمسافرين والموظفين.

يدعم:

* SMS.
* البريد الإلكتروني.
* WhatsApp.
* الإشعارات داخل النظام.

---

### 9. نظام الهوية الوطنية (اختياري)

في حال توفره يمكن استخدامه للتحقق من بيانات المواطنين السودانيين.

**البيانات المتبادلة:**

* الرقم الوطني.
* الاسم.
* تاريخ الميلاد.
* الجنس.
* العنوان.

---

## آلية التكامل

يعتمد النظام على **Integration Layer** لتوحيد الاتصال مع الأنظمة الخارجية، باستخدام واجهات برمجية وبروتوكولات آمنة مثل:

* REST APIs
* SOAP Web Services (للأنظمة القديمة عند الحاجة)
* Secure File Transfer (SFTP)
* Webhooks للأحداث الفورية
* OAuth 2.0 / API Keys للمصادقة والتفويض

---

## فوائد التكامل

* عدم تكرار إدخال البيانات.
* تبادل المعلومات بشكل لحظي.
* رفع جودة البيانات ودقتها.
* تسريع إجراءات الفحص الصحي.
* دعم اتخاذ القرار على المستوى الاتحادي.
* تحسين التنسيق بين الجهات الحكومية.
* إنشاء سجل صحي موحد للمسافر عبر جميع المنافذ.

> **ملاحظة معمارية:** يُفضل أن يتم تنفيذ جميع عمليات التكامل عبر **Integration Service** أو **API Gateway** داخل المنصة، بحيث لا تتصل الوحدات الداخلية مباشرة بالأنظمة الخارجية. هذا يسهل الصيانة، ويعزز الأمان، ويسمح بإضافة أو تغيير أي نظام حكومي مستقبلاً دون التأثير على بقية مكونات المنصة.
