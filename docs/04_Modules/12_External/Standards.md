# هيئة المواصفات والمقاييس - Standards & Metrology Authority

## 1. الهدف
ربط منصة NQP مع نظام هيئة المواصفات والمقاييس للحصول على المواصفات القياسية للمنتجات الغذائية بشكل آلي، لمقارنة نتائج المختبرات مع الحدود المسموحة واتخاذ قرار المطابقة أو عدم المطابقة تلقائياً.

## 2. نقاط التكامل (Integration Points)

| الاتجاه | البيانات المرسلة | التوقيت | البروتوكول | التنسيق |
| :--- | :--- | :--- | :--- | :--- |
| **من Standards → NQP** | المواصفات القياسية للمنتجات (الحدود المسموحة للملوثات، المواد المضافة). | عند الطلب | REST API | JSON |
| **من NQP → Standards** | (اختياري) تقارير عن العينات التي لم تطابق المواصفات. | شهري | REST API | JSON |

## 3. نموذج المواصفات القياسية (Standards JSON)
```json
{
  "product": "لحم بقري مجمد",
  "test_type": "البكتيريا القولونية",
  "unit": "CFU/g",
  "min_value": null,
  "max_value": 10,
  "reference_standard": "SS 123:2024"
}

4. آلية العمل

    عند استلام نتيجة عينة غذائية من المختبر (بوابة 6)، يقوم نظام NQP بإرسال طلب إلى هيئة المواصفات للحصول على المواصفات القياسية للمنتج ونوع الفحص.

    تتلقى NQP المواصفات (الحدود الدنيا والعليا) وتقارنها بالقيمة المقاسة.

    إذا كانت القيمة ضمن الحدود المسموحة، يتم تصنيف النتيجة كـ (مطابق) تلقائياً.

    إذا كانت القيمة خارج الحدود المسموحة، يتم تصنيف النتيجة كـ (غير مطابق) مع عرض تقرير للمفتش.

5. الأمان

    المصادقة: مفتاح API لهيئة المواصفات.

    التشفير: TLS 1.3.

    التخزين المؤقت (Caching): يتم تخزين المواصفات القياسية مؤقتاً في Redis لمدة 24 ساعة لتقليل الطلبات المتكررة.

6. نقاط النهاية (API Endpoints)
الطريقة	المسار	الوصف
GET	/api/v1/integration/standards/get	جلب المواصفات القياسية لمنتج معين.
