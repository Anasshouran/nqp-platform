# شركات الطيران - Airlines

## 1. الهدف
إدارة التكامل مع شركات الطيران (وكذلك شركات النقل البحري والبرية) لتبادل قوائم الركاب (Passenger Manifest)، جداول الرحلات، والإشعارات الصحية، مما يضمن تحديث بيانات المسافرين قبل وصولهم إلى المنافذ.

## 2. نقاط التكامل (Integration Points)

| الاتجاه | البيانات المرسلة | التوقيت | البروتوكول | التنسيق |
| :--- | :--- | :--- | :--- | :--- |
| **من Airline → NQP** | قائمة الركاب (Manifest) للرحلة (بيانات المسافرين، المقاعد). | قبل 24 ساعة من الوصول | REST API (أو SFTP) | JSON / CSV |
| **من Airline → NQP** | تحديث جداول الرحلات (إضافة، تعديل، إلغاء). | عند التغيير | REST API | JSON |
| **من NQP → Airline** | الإشعارات الصحية (متطلبات دخول جديدة، تعليق رحلات). | عند التغيير | REST API / Email | JSON / PDF |
| **من NQP → Airline** | تأكيد استلام قائمة الركاب (مع تقرير الأخطاء). | فوري (بعد المعالجة) | REST API | JSON |

## 3. نموذج قائمة الركاب (Manifest JSON)

5. آلية العمل

    يقوم ممثل شركة الطيران برفع قائمة الركاب عبر بوابة الناقل (3) أو عبر API التكامل.

    يقوم نظام NQP بمعالجة القائمة (تحقق، مقارنة مع قاعدة البيانات، تسجيل الأخطاء).

    يعود النظام بتقرير (عدد الركاب، الأخطاء، عدد المسجلين مسبقاً).

    يتم إرسال إشعار لشركة الطيران في حال وجود أخطاء (لتصحيحها) أو في حال وجود إشعارات صحية جديدة تؤثر على الرحلة.

6. الأمان

    المصادقة: مفتاح API لكل شركة طيران (يتم توفيره عبر بوابة الناقل).

    التشفير: TLS 1.3.

    سجل التدقيق: تسجيل كل قائمة ركاب مستلمة في (Audit Log) مع (الشركة، الوقت، عدد الركاب).

7. نقاط النهاية (API Endpoints)
الطريقة	المسار	الوصف
POST	/api/v1/integration/airlines/manifest	استقبال قائمة الركاب من شركة الطيران.
POST	/api/v1/integration/airlines/flights	تحديث جداول الرحلات.
GET	/api/v1/integration/airlines/notices	استرجاع الإشعارات الصحية النشطة.
