
# 03_Carrier_Portal - بوابة شركات الطيران ووسائل النقل

## 1. الهدف الاستراتيجي
توفير واجهة إلكترونية آمنة ومخصصة لممثلي شركات الطيران (الجوية والبحرية والبرية) لإدارة كافة البيانات المتعلقة برحلاتهم ومسافريهم بشكل مسبق، مما يتيح للمنصة:

- **الاستعداد المسبق**: معرفة أعداد المسافرين القادمين وتفاصيلهم الصحية قبل وصولهم.

- **التخطيط للطاقة الاستيعابية**: توزيع الموارد (الكوادر، أجهزة الفحص) بناءً على حجم الرحلة.

- **الامتثال للوائح**: التأكد من التزام شركات الطيران بتقديم بيانات الركاب (Passenger Manifest) كشرط أساسي للهبوط أو الرسو.

## 2. الممثلون (Actors)
- **ممثل شركة الطيران (Carrier Representative)**: المستخدم الأساسي (مسجل من قبل الإدارة الاتحادية).

- **مسؤول الإدارة الاتحادية (Federal Admin)**: يدير حسابات شركات الطيران ويمنحها صلاحيات الوصول.

- **نظام المنصة (NQP)**: يستقبل البيانات، يتحقق من صحتها، ويُحدِث قاعدة البيانات.

## 3. الميزات الرئيسية (Key Features)
| الميزة | الوصف | الأولوية |
| :--- | :--- | :--- |
| **إدارة الشركات** | عرض وتحديث بيانات الشركة (الاسم، جهات الاتصال، IATA Code). | عالية |

| **إدارة الرحلات** | إضافة، تعديل، وحذف جداول الرحلات القادمة والمغادرة. | عالية |

| **رفع قائمة الركاب** | رفع ملف (CSV/Excel/JSON) بقائمة الركاب، مع التحقق الآلي من صحته. | عالية |

| **التكامل عبر API** | ربط أنظمة شركات الطيران مباشرة مع NQP لإرسال البيانات آلياً. | عالية |

| **الإشعارات الصحية** | استلام الإشعارات الرسمية من وزارة الصحة (تعليق الرحلات، متطلبات جديدة). | متوسطة |
| **التقارير** | عرض إحصائيات عن أداء الشركة وامتثالها للتوجيهات. | متوسطة |

## 4. دورة حياة الرحلة في البوابة (Flight Lifecycle)
```mermaid
flowchart LR
    A[إنشاء رحلة جديدة] --> B[تحديد وقت الوصول والمغادرة]
    B --> C[رفع قائمة الركاب]
    C --> D[التحقق الآلي من صحة البيانات]
    D --> E{البيانات صحيحة؟}
    E -- لا --> F[إشعار بالخطأ + طلب التصحيح]
    F --> C

    H --> I[تحديث حالة الرحلة إلى "جاهزة للاستقبال"]

# الوحدة 3: بوابة شركات الطيران ووسائل النقل

 الوحدة المنطقية:  بوابة شركات الطيران (Carrier Portal)  
 التطبيقات التقنية (Django Apps):  `integration` (لإدارة الرحلات والـ Manifest)  
 المستخدمون:  شركات الطيران، وكلاء الشحن، مشغلو وسائل النقل.

## الأهداف

- إدارة شركات الطيران المسجلة.
- إدارة جداول الرحلات (إضافة، تعديل، إلغاء).
- رفع قوائم الركاب (Passenger Manifest) بشكل آلي (API أو يدوي).
- توفير إشعارات صحية للركاب عبر شركات الطيران.

## المكونات الرئيسية

1.  إدارة الشركات:  تسجيل شركة طيران، جهة اتصال، مفتاح API.
2.  إدارة الرحلات:  جدول زمني للرحلات القادمة والمغادرة.
3.  رفع الـ Manifest:  استقبال ملف JSON أو CSV يحتوي على قائمة الركاب.
4.  التقارير:  إحصائيات الرحلات والركاب.

## الجداول المرتبطة (في init.sql)

- `flight_manifests`
- `api_integration_logs` (لتسجيل طلبات API الواردة)

## نقاط API الرئيسية

| الطريقة | المسار | الوصف | الصلاحية |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/integration/manifest/` | استقبال كشف المسافرين (JSON) | مفتاح API خاص بالشركة |
| `GET` | `/api/integration/flights/` | قائمة الرحلات | مصادق (موظف/شركة) |

## الاعتماديات (Dependencies)

- تعتمد على `travelers` (لربط المسافرين بالرحلات).
- تعتمد على `core` (لتوثيق API و Audit Log).
--------------------------------------------
صحيح، وهذا هو التوجه المتبع عالميًا.

معظم **شركات الطيران** لديها بالفعل أنظمة تشغيل خاصة بها، لذلك لا ينبغي أن يقوم نظام الحجر الصحي بإدخال بيانات الرحلات يدويًا، بل يعتمد على **التكامل (Integration)** مع أنظمة شركات الطيران.

يمكن تعديل البند ليصبح:

# 4. التكامل مع أنظمة شركات الطيران (Airline Systems Integration)

## الهدف

ربط نظام الحجر الصحي مع أنظمة شركات الطيران لتبادل بيانات الرحلات وقوائم المسافرين إلكترونيًا قبل وصول الرحلة، دون الحاجة إلى إعادة إدخال البيانات.

---

## آلية التكامل

يقوم نظام شركة الطيران بإرسال:

* بيانات الرحلة.
* قائمة المسافرين (Passenger Manifest).
* بيانات أفراد الطاقم.
* وقت الوصول المتوقع.
* تحديثات حالة الرحلة.

إلى نظام الحجر الصحي عبر:

* REST API
* Web Services
* تبادل ملفات آمنة (CSV / XML / JSON)
* أو أي بروتوكول معتمد بين الجهات.

---

## البيانات المستلمة

### بيانات الرحلة

* رقم الرحلة.
* شركة الطيران.
* مطار المغادرة.
* مطارات التوقف.
* وقت الإقلاع.
* وقت الوصول.
* بوابة الوصول.

### بيانات المسافرين

* الاسم.
* رقم الجواز.
* الجنسية.
* تاريخ الميلاد.
* الجنس.
* رقم المقعد.

### بيانات الطاقم

* اسم عضو الطاقم.
* رقم الجواز.
* الوظيفة.
* الجنسية.

---

## عمل نظام الحجر الصحي

بعد استلام البيانات يقوم النظام تلقائيًا بـ:

1. إنشاء الرحلة.
2. إنشاء قائمة المسافرين.
3. مطابقة المسافرين مع التسجيل المسبق (إن وجد).
4. تجهيز قوائم الفحص الصحي قبل وصول الرحلة.
5. إرسال تنبيه لموظفي المنفذ بقرب وصول الرحلة.

---

## عند وصول الطائرة

يقوم موظف الحجر الصحي فقط بـ:

* مسح QR Code (إذا كان المسافر سجل مسبقًا).
* أو قراءة الجواز.
* إجراء الفحص الصحي.
* تسجيل القرار.

---

## الفوائد

* عدم تكرار إدخال البيانات.
* تقليل الأخطاء.
* تسريع إجراءات الوصول.
* معرفة عدد المسافرين قبل وصول الرحلة.
* تحسين توزيع الكوادر في المنفذ.
* رفع كفاءة التنسيق بين شركات الطيران والحجر الصحي.

## تكاملات مستقبلية

يمكن أيضًا ربط النظام مع:

* **إدارة الجوازات والهجرة** للتحقق من بيانات السفر.
* **سلطة الطيران المدني** للحصول على جدول الرحلات وحالة التشغيل.
* **شركات الطيران** للحصول على قوائم الركاب وأفراد الطاقم.
* **أنظمة المطارات** لمعرفة بوابات الوصول وأوقات الرحلات الفعلية.

بهذا يصبح نظام الحجر الصحي مستهلكًا للبيانات (Consumer) وليس منتجًا لها، ويعتمد على التكامل مع الأنظمة القائمة بدلاً من تكرار الوظائف الموجودة لديها.
