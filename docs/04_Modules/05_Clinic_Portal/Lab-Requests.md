# طلبات المختبر (Laboratory Requests)

## 1. الهدف
تمكين الطبيب من إرسال طلبات فحوصات مخبرية (مسحات، دم، بول، إلخ) إلى بوابة المختبرات (6)، مع ربط العينة بزيارة المريض، وتتبع حالة العينة حتى ظهور النتيجة.

## 2. مكونات الصفحة

### 2.1. نموذج طلب فحص جديد (New Lab Request)
- **نوع العينة (Sample Type)**:
  - قائمة منسدلة: (مسحة أنفية، مسحة حلقية، عينة دم، عينة بول، عينة براز، عينة سائل نخاعي).
- **الفحص المطلوب (Test Requested)**:
  - قائمة منسدلة (مرتبطة بالأمراض المشتبه بها): (PCR لكوفيد-19، مزرعة بكتيرية، فحص دم شامل، اختبارات وظائف الكبد، إلخ).
- **الأولوية (Priority)**:
  - (عادي، عاجل، فوري).
- **ملاحظات إضافية للفني**: (نص حر) - (مثل: "يرجى إجراء الفحص بسرعة، المريض يعاني من أعراض حادة").

### 2.2. قائمة الطلبات المعلقة (Pending Requests)
- عرض جدول بجميع الطلبات التي تم إرسالها ولم تظهر نتيجتها بعد:
  - الأعمدة: (نوع العينة، الفحص المطلوب، التاريخ، الأولوية، حالة العينة (مسجلة، قيد التحليل)).
- **زر**: "تحديث" (للتحقق من حالة العينة).

### 2.3. استلام النتائج (Receiving Results)
- عند اعتماد النتيجة من قبل المختبر (6)، تظهر تلقائياً في لوحة الطبيب كإشعار.
- **بطاقة النتيجة**:
  - (اسم المريض، نوع العينة، الفحص، النتيجة (إيجابي/سلبي/غير محدد)، القيمة الرقمية (إن وجدت)).
  - **زر**: "ربط النتيجة بالتشخيص" (لإضافة النتيجة إلى السجل الطبي وتحديث التشخيص النهائي).

### 2.4. تاريخ الطلبات (Request History)
- عرض جميع الطلبات السابقة مع نتائجها (للرجوع إليها في الزيارات المستقبلية).

## 3. منطق الأعمال (Business Logic)
- **ربط العينة بالزيارة**: يتم ربط الطلب بمعرف الزيارة (`visit_id`) لضمان ربط النتيجة بالمريض الصحيح.
- **الإشعار التلقائي**: عند وصول نتيجة جديدة، يتم إرسال إشعار (WebSocket) للطبيب المعالج.

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/clinic/visits/{visit_id}/lab-requests` | إرسال طلب فحص مخبري جديد. |
| `GET` | `/api/v1/clinic/visits/{visit_id}/lab-requests` | قائمة طلبات المختبر لهذه الزيارة. |
| `GET` | `/api/v1/clinic/visits/{visit_id}/lab-results` | استرجاع نتائج المختبر المعتمدة لهذه الزيارة. |
