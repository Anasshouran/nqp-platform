# العلاج والمتابعة (Treatment & Follow-up)

## 1. الهدف
تمكين الطبيب من وصف العلاج المناسب للمريض (الأدوية، الجرعات، التعليمات)، وتحديد خطة المتابعة المناسبة: إما الإفراج، أو المتابعة المنزلية، أو الإحالة إلى المستشفى.

## 2. مكونات الصفحة

### 2.1. نموذج وصف الأدوية (Prescription Form)
- **البحث عن الدواء**: حقل بحث (متصل بقاعدة الأدوية في نظام إدارة الأمراض).
- **تفاصيل الجرعة**:
  - الجرعة (مثل: 500mg).
  - التكرار (مثل: كل 8 ساعات، مرتين يومياً).
  - المدة (عدد الأيام).
  - تعليمات إضافية (مثل: "يؤخذ بعد الأكل"، "لا يؤخذ مع مضادات الحموضة").

### 2.2. كشف التداخلات الدوائية (Drug Interaction Checker)
- قبل تأكيد الوصفة، يقوم النظام بفحص الدواء الجديد مع قائمة الأدوية الحالية للمريض:
  - **إذا تم اكتشاف تداخل خطير**: يعرض تحذيراً أحمر ويمنع إضافة الدواء حتى يقدم الطبيب مبرراً (نص مفتوح).
  - **إذا تم اكتشاف تداخل بسيط**: يعرض تحذيراً أصفر مع توصيات.

### 2.3. خطة المتابعة (Follow-up Plan)
- **الإفراج (Discharge)**:
  - تحديد ما إذا كان المريض بحاجة إلى متابعة منزلية أم لا.
  - إذا كان بحاجة:
    - **تفعيل المتابعة المنزلية**: زر لإنشاء ملف متابعة في نظام `Health_Follow-up` (مع تحديد المدة الموصى بها).
    - **تعليمات للمريض**: حقل نصي (مثل: "الراحة التامة، شرب سوائل كثيرة، قياس الحرارة يومياً").
  - **طباعة تقرير الإفراج**: زر لطباعة تقرير طبي للمريض (يتضمن التشخيص، الأدوية الموصوفة، والتعليمات).
- **الإحالة إلى المستشفى (Referral to Hospital)**:
  - **سبب الإحالة**: حقل نصي (مثل: "الحالة تتطلب تدخل جراحي عاجل").
  - **اختيار المستشفى**: قائمة منسدلة (مستشفيات تابعة للوزارة).
  - **زر**: "إرسال الإحالة" (يُرسل طلب إحالة إلكتروني إلى المستشفى المختار عبر التكامل الخارجي).

### 2.4. إغلاق الزيارة (Close Visit)
- **الملخص النهائي**: نص يلخص الحالة والعلاج المقدم.
- **زر**: "إغلاق الزيارة" (يُنهي الزيارة ويُغير حالة المريض إلى (مفرج، متابعة، محول للمستشفى) ولا يمكن تعديل البيانات بعد الإغلاق).

## 3. منطق الأعمال (Business Logic)
- **المتابعة الإلزامية**: لا يمكن إفراج مريض تم تشخيصه بمرض معدي دون تفعيل ملف متابعة (إلزامي حسب بروتوكول وزارة الصحة).
- **الإحالة للمستشفى**: في الحالات الحرجة، يتم إرسال إشعار فوري إلى غرفة الطوارئ (9) بالإضافة إلى إرسال الإحالة للمستشفى.

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/clinic/visits/{visit_id}/prescriptions` | وصف دواء جديد. |
| `POST` | `/api/v1/clinic/visits/{visit_id}/check-interactions` | التحقق من التداخلات الدوائية. |
| `POST` | `/api/v1/clinic/visits/{visit_id}/close` | إغلاق الزيارة (مع خطة المتابعة). |
| `POST` | `/api/v1/clinic/visits/{visit_id}/followup` | تفعيل المتابعة المنزلية (إنشاء ملف في نظام المتابعة). |
| `POST` | `/api/v1/clinic/visits/{visit_id}/refer-hospital` | إرسال إحالة إلى المستشفى. |
