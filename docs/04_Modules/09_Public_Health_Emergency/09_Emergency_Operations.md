# 09_Emergency_Operations - بوابة الطوارئ (غرفة العمليات)

## 1. الهدف الاستراتيجي
تزويد الإدارة العامة للطوارئ الصحية ومكافحة الأوبئة (غرفة العمليات - EOC) بأداة رقمية متكاملة للاستجابة الفورية للطوارئ الصحية. تهدف البوابة إلى:
- **الإنذار المبكر**: استقبال التنبيهات الحمراء فوراً (في أقل من 3 ثوانٍ) من جميع مصادر المنصة (الفحص، العيادات، المختبرات).
- **الرؤية الكاملة**: توفير خريطة تفاعلية لحظية لجميع المنافذ مع حالة الإنذار لكل منفذ.
- **الاستجابة السريعة**: تمكين فريق الطوارئ من توجيه فرق الاستجابة السريعة (RRT) وإدارة الموارد الاستراتيجية.
- **الحزم والصرامة**: تفعيل "Kill Switch" لإيقاف المنافذ فوراً في حالات التفشي أو الخطر الداهم.
- **التنسيق الوطني**: ربط جميع جهات الاستجابة (وزارة الصحة، المستشفيات، الفرق الميدانية) في منصة واحدة.

## 2. الممثلون (Actors)
- **مسؤول غرفة العمليات (EOC Operator)**: المستخدم الأساسي (يراقب، يحلل، ويوجه الفرق).
- **مدير الطوارئ (Emergency Director)**: صلاحيات عليا (تفعيل Kill Switch، إعلان حالة الطوارئ الوطنية).
- **فريق الاستجابة السريعة (RRT)**: (مستخدمون ميدانيون) يتلقون التوجيهات من غرفة العمليات عبر التطبيق الميداني.
- **نظام المنصة (NQP)**: مصدر الإنذارات والبيانات.
- **وزارة الصحة**: مستقبل للتقارير العملياتية.

## 3. الميزات الرئيسية (Key Features)
| الميزة | الوصف | الأولوية |
| :--- | :--- | :--- |
| **لوحة الإنذار الفوري** | عرض التنبيهات الحمراء لحظياً مع تحديد الموقع وحالة المريض. | عالية |
| **خريطة المخاطر التفاعلية** | خريطة تفاعلية تعرض حالة كل منفذ (أخضر/أصفر/أحمر) مع إحصائيات سريعة. | عالية |
| **إدارة فرق الاستجابة السريعة (RRT)** | توجيه الفرق الميدانية، تتبع مواقعهم، وتحديث حالة المهمة. | عالية |
| **تتبع المخالطين (Contact Tracing)** | استدعاء بيانات المسافرين في المقاعد المجاورة لحالة إيجابية. | عالية |
| **المخزون الاستراتيجي** | إدارة وتوزيع الأدوية والمستلزمات الطبية على المنافذ المتضررة. | عالية |
| **Kill Switch (مفتاح الإيقاف الطارئ)** | تعليق جميع عمليات الإفراج في منفذ معين فوراً (مع آلية تأكيد أمني). | عالية |
| **الإشعار الجماعي (Mass Alert)** | إرسال رسائل تحذيرية (SMS، Push) لجميع المسافرين في منفذ معين. | متوسطة |
| **التقارير العملياتية** | إنشاء تقارير سريعة عن الحالة (كل 6 ساعات) لرفعها لوزارة الصحة. | متوسطة |

## 4. دورة حياة الإنذار (Alert Lifecycle)
```mermaid
flowchart LR
    A[استقبال إنذار أحمر] --> B[ظهور التنبيه على لوحة الطوارئ]
    B --> C[تقييم أولي من قبل مسؤول EOC]
    C --> D{نوع الحالة}
    D -- حالة فردية --> E[توجيه فريق RRT إلى الموقع]
    E --> F[الفريق يتخذ الإجراءات (عزل، نقل)]
    F --> G[تحديث حالة الإنذار إلى "قيد المعالجة"]
    G --> H[متابعة حتى الاستقرار]
    H --> I[إغلاق الإنذار]
    
    D -- تفشي جماعي --> J[تفعيل Kill Switch للمنفذ المعني]
    J --> K[إرسال إشعارات جماعية للمسافرين]
    K --> L[تشكيل فريق أزمة وتوزيع المهام]
    L --> M[متابعة حتى السيطرة]
    M --> N[إلغاء Kill Switch وإعادة التشغيل التدريجي]

5. المتطلبات التقنية (Technical Requirements)

    الواجهة الأمامية: React + Tailwind CSS (مسار /eoc).

    الخلفية: Django REST Framework (نقاط النهاية تحت /api/v1/eoc/).

    المصادقة: JWT مع صلاحيات صارمة (الدور: EOC_OPERATOR، EMERGENCY_DIRECTOR).

    البيانات اللحظية (Real-time): استخدام WebSocket (باستخدام Django Channels) لنقل الإنذارات والتحديثات فوراً (زمن انتقال أقل من 3 ثوانٍ).

    الخريطة التفاعلية: استخدام مكتبة (Leaflet) أو (OpenLayers) مع طبقات (Tile Layers) مجانية.

    تتبع الفرق الميدانية: (مستقبلي) تكامل مع نظام (GPS) لتتبع مواقع فرق RRT.

6. التكامل مع الأنظمة الأخرى

    بوابة موظفي الحجر (4): استقبال الإنذارات عند اكتشاف حالة مشتبه بها (تصنيف أحمر).

    بوابة العيادات (5): استقبال الإنذارات عند تأكيد حالة حرجة.

    بوابة المختبرات (6): استقبال الإنذارات عند اعتماد نتيجة إيجابية لمرض خطير (PHEIC).

    نظام المتابعة الصحية: استقبال الإنذارات عند تدهور حالة مريض تحت المتابعة المنزلية.

    نظام الإشعارات: إرسال إشعارات جماعية (SMS) للمسافرين والموظفين.

    نظام إدارة المستخدمين: التحقق من صلاحيات مستخدمي الطوارئ.

    نظام التقارير: تغذية التقارير العملياتية.

7. اعتبارات أمنية خاصة

    التحقق المزدوج (Dual Authorization): لا يمكن تفعيل (Kill Switch) إلا بعد موافقة (مدير الطوارئ) و (مسؤول EOC) معاً.

    سجل التدقيق (Audit Log): تسجيل كل إجراء يتم في غرفة العمليات (من قام، متى، ماذا فعل) بشكل مشدد.

    التشفير: جميع البيانات المرسلة عبر WebSocket مشفرة بـ (TLS 1.3).

    النسخ الاحتياطي الفوري: يتم عمل نسخة احتياطية من بيانات الإنذارات كل 5 دقائق في قاعدة بيانات منفصلة (لتجنب فقدان البيانات في حالات الطوارئ).
