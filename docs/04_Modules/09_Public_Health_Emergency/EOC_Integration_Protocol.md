# بروتوكول التكامل لغرفة الطوارئ (EOC Integration Protocol)

## 1. الهدف
توثيق كيفية تبادل البيانات بين غرفة العمليات (EOC) وبقية البوابات وأنظمة الدعم، لضمان استجابة سريعة ومنسقة أثناء الطوارئ الصحية، وتحديد زمن الاستجابة المطلوب لكل نوع من أنواع التكامل.

## 2. مصفوفة التكامل (Integration Matrix)

| النظام المتكامل | نوع التكامل | اتجاه التدفق | البيانات المتبادلة | زمن النقل | البروتوكول |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **بوابة موظفي الحجر (4)** | WebSocket | وارد | إنذار فوري عند اكتشاف حالة مشتبه بها (تصنيف أحمر) مع بيانات المريض والموقع. | < 3 ثوانٍ | WebSocket (JSON) |
| **بوابة العيادات (5)** | WebSocket + REST | وارد | تأكيد حالة حرجة (مريض يحتاج تدخل عاجل) مع السجل الطبي المختصر. | < 3 ثوانٍ | WebSocket |
| **بوابة المختبرات (6)** | WebSocket | وارد | نتيجة إيجابية لمرض مدرج في قائمة (PHEIC) مع بيانات المريض والنتيجة. | < 3 ثوانٍ | WebSocket |
| **نظام المتابعة الصحية** | WebSocket | وارد | تنبيه تدهور حالة مريض تحت المتابعة المنزلية (تصنيف أحمر). | < 5 ثوانٍ | WebSocket |
| **نظام الإشعارات** | REST (غير متزامن) | صادر | إرسال رسائل تحذيرية جماعية للمسافرين في منفذ معين. | خلال 5-15 دقيقة | REST API |
| **نظام إدارة المستخدمين** | REST | ثنائي | التحقق من صلاحيات الطوارئ للمستخدمين. | < 200 مللي ثانية | REST API |
| **نظام الترصد الوبائي** | Batch | صادر | تحديث لوحات المؤشرات بالبيانات المجمعة (كل 6 ساعات). | 6 ساعات | Batch (JSON/CSV) |
| **وزارة الصحة** | REST (أو SFTP) | صادر | إرسال تقرير عملياتي سريع (كل 6 ساعات في الطوارئ). | كل 6 ساعات | REST API / SFTP |

## 3. سيناريو الاستجابة للطوارئ (E2E - End to End)
```mermaid
sequenceDiagram
    participant Officer as موظف الحجر (4)
    participant NQP as منصة NQP
    participant EOC as غرفة الطوارئ (9)
    participant RRT as فريق RRT
    participant MOH as وزارة الصحة

    Officer->>NQP: 1. تسجيل حالة (أحمر) مع بيانات المسافر
    NQP->>EOC: 2. إرسال إنذار فوري (WebSocket) خلال 3 ثوانٍ
    EOC->>EOC: 3. عرض الإنذار على لوحة القيادة + تنبيه صوتي
    EOC->>RRT: 4. توجيه فريق RRT (إشعار SMS + Push)
    RRT-->>EOC: 5. تأكيد استلام المهمة + الوصول إلى الموقع
    EOC->>MOH: 6. إرسال تقرير عملياتي موجز (كل 6 ساعات)

4. متطلبات الأداء (Performance Requirements)
المقياس	القيمة المستهدفة
زمن انتقال الإنذار (من المصدر إلى EOC)	< 3 ثوانٍ
زمن استجابة فريق EOC (من الإنذار إلى التوجيه)	< 2 دقيقة
زمن تحديث لوحة القيادة (WebSocket)	5 ثوانٍ
زمن تحميل لوحة القيادة (الصفحة الرئيسية)	< 2 ثانية
توفر النظام (Uptime)	99.9% (في أوقات الطوارئ)
5. اعتبارات أمنية

    التشفير: جميع الاتصالات (بما في ذلك WebSocket) مشفرة بـ (TLS 1.3).

    المصادقة: التحقق من صلاحية JWT لكل طلب (حتى في WebSocket).

    تسجيل التدقيق: تسجيل كل إنذار وارد وكل إجراء يتم في غرفة العمليات.

    النسخ الاحتياطي الفوري: يتم عمل نسخة احتياطية من بيانات الإنذارات كل 5 دقائق (في قاعدة بيانات منفصلة).
