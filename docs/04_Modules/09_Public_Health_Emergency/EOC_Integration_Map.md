# EOC_Integration_Map - خريطة تكامل غرفة الطوارئ مع المنصة

## 1. الهدف
توثيق كيفية تبادل البيانات بين غرفة العمليات (EOC) وبقية البوابات وأنظمة الدعم، لضمان استجابة سريعة ومنسقة أثناء الطوارئ الصحية.

## 2. مصفوفة التكامل (Integration Matrix)

| النظام المتكامل | نوع التكامل | اتجاه التدفق | البيانات المتبادلة | زمن النقل |
| :--- | :--- | :--- | :--- | :--- |
| **بوابة موظفي الحجر (4)** | WebSocket | وارد | إنذار فوري عند اكتشاف حالة مشتبه بها (حرارة، أعراض) | < 3 ثوانٍ |
| **بوابة المختبرات (6)** | REST API | وارد | نتائج مسحات إيجابية مؤكدة مع بيانات المريض | فور الاعتماد |
| **بوابة المسافرين (2)** | REST API | صادر | طلب سحب بيانات المخالطين (المقاعد المجاورة) | لحظي |
| **نظام المتابعة الصحية** | WebSocket | وارد | تنبيهات تدهور حالة مريض تحت المتابعة المنزلية | < 5 ثوانٍ |
| **نظام الترصد الوبائي** | Batch | صادر | تقارير مجمعة عن اتجاهات التفشي (كل 6 ساعات) | دوري |
| **نظام الإشعارات** | REST API | صادر | إرسال رسائل تحذير جماعية للمسافرين في منفذ معين | فوري |
| **نظام إدارة المستخدمين** | REST API | ثنائي | صلاحيات الطوارئ (تجاوز الصلاحيات العادية) | عند التفعيل |

## 3. سيناريو الطوارئ (Discovery → Response)
1. **الاكتشاف**: بوابة موظفي الحجر ترسل إنذاراً إلى EOC.
2. **التفعيل**: يقوم فريق EOC بتفعيل خطة الاستجابة (Code Red).
3. **التتبع**: يتم استدعاء بيانات المخالطين من بوابة المسافرين.
4. **التنبيه**: يتم إرسال رسائل جماعية للمسافرين في نفس الرحلة.
5. **الإغلاق**: تفعيل Kill Switch لإيقاف الإفراج في المنفذ المصاب حتى التطهير.
