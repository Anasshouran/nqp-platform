# Data_Exchange - آليات تبادل البيانات مع منظمة الصحة العالمية

## 1. نظرة عامة
توثق هذه الوثيقة آليات تبادل البيانات بين منصة NQP ومنظمة الصحة العالمية (WHO) والمركز الوطني للوائح الصحية (IHR Focal Point). تهدف إلى ضمان نقل البيانات بشكل آمن وفي الوقت المناسب وبصيغ معيارية.

## 2. قنوات التبادل (Exchange Channels)
| القناة | الوصف | الحالة |
| :--- | :--- | :--- |
| **REST API** | التواصل الفوري (عند حدوث الحدث). يُستخدم للإبلاغ عن حالات PHEIC. | أساسي |
| **SFTP** | رفع الملفات الكبيرة (التقارير الأسبوعية، ملفات البيانات المجمعة). | أساسي |
| **البريد الإلكتروني المشفر** | (احتياطي) إرسال التقارير إلى المركز الوطني في حال فشل القنوات الرقمية. | احتياطي |
| **Webhook** | استقبال تحديثات ICD-11 من WHO (يُفعّل من قبل WHO). | اختياري (مستقبلي) |

## 3. تنسيقات البيانات (Data Formats)
| التنسيق | الاستخدام | الوصف |
| :--- | :--- | :--- |
| **JSON** | تبادل البيانات الفورية (APIs) ونقاط نهاية FHIR. | خفيف الوزن وسهل المعالجة. |
| **XML** | التقارير الرسمية (IHR) المتوافقة مع معايير WHO. | يُستخدم للتوافق مع الأنظمة القديمة. |
| **CSV** | تصدير البيانات المجمعة للتحليل الإحصائي (اختياري). | يُستخدم للتقارير الداخلية قبل التحويل. |

## 4. جدول تبادل البيانات (Exchange Schedule)
| نوع البيانات | التكرار | القناة | التنسيق |
| :--- | :--- | :--- | :--- |
| تحديثات ICD-11 | يومياً (2 صباحاً) | REST API | JSON |
| تحديثات تصنيفات الدول | كل 6 ساعات | REST API | JSON |
| تقرير الحالات الأسبوعي | أسبوعياً (الأحد 3 صباحاً) | SFTP | XML (IHR Format) |
| تقرير PHEIC الفوري | فوري (عند الحدث) | REST API + بريد إلكتروني | JSON |

## 5. أمان تبادل البيانات (Security)
- **التشفير أثناء النقل**: استخدام (TLS 1.3) لجميع الاتصالات.
- **التشفير عند السكون**: تشفير البيانات في قاعدة البيانات باستخدام (AES-256).
- **المصادقة**: استخدام (API Keys) و (JWT) لكل طلب.
- **إخفاء الهوية (Anonymization)**: يتم إرسال البيانات إلى WHO بشكل مجهول (بدون أسماء المرضى أو أرقام الجوازات). يتم استخدام (UUIDs) بدلاً من ذلك.

## 6. معالجة الأخطاء (Error Handling)
- **فشل الاتصال**: يتم تسجيل الخطأ وإعادة المحاولة 3 مرات (بفترات متزايدة) باستخدام (Celery Retry).
- **بيانات غير صحيحة**: يتم تسجيل الخطأ في (Audit Log) وإرسال إشعار للمسؤول.
- **تجاوز المهلة (Timeout)**: يتم تسجيل الخطأ وتأجيل المهمة إلى الدورة التالية.
