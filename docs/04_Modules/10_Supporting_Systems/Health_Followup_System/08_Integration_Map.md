# 08_Integration_Map - مصفوفة التكامل وتبادل البيانات

## 1. الغرض من هذه الخريطة
توثيق جميع نقاط التكامل (Integrations) بين نظام المتابعة الصحية والبوابات الأخرى وأنظمة الدعم، لتوضيح اتجاه تدفق البيانات والاعتماديات (Dependencies) لفريق التطوير ومسؤولي قواعد البيانات.

## 2. مصفوفة التكامل (Integration Matrix)

| النظام المتكامل معه (Source/Target) | نوع التكامل | اتجاه التدفق | البيانات المتبادلة | الـ Trigger |
| :---  | :---                    | :---              |  :---     | :--- |

| **بوابة العيادات (Clinic Portal - 5)** | REST API (متزامن) | **وارد** (Inbound) | استقبال خطة العلاج (e-Prescription)، التشخيص الأولي، والحالات المزمنة | لحظة إخراج المريض من العيادة |

| **نظام تقييم المخاطر (Risk Engine)** | REST API + Message Queue | **ثنائي** (Two-way) | إرسال القراءات اليومية لتحديث درجة الخطر، واستقبال التصنيف الجديد (أصفر/أحمر) | بعد كل إدخال من المريض |

| **بوابة المسافرين (Traveler Portal - 2)** | GraphQL (قراءة) | **وارد** (Inbound) | سحب الملف الصحي الأساسي (جواز السفر، رقم التواصل، تاريخ السفر) | عند تفعيل ملف المتابعة |

| **نظام المختبرات (Lab Portal - 6)** | REST API | **صادر** (Outbound) | إرسال طلب مسحة منزلية جديدة | عند طلب الطبيب في لوحة المتابعة |

| **نظام المختبرات (Lab Portal - 6)** | Message Queue | **وارد** (Inbound) | استقبال نتيجة المسحة الجديدة (سلبية/إيجابية) | فور اعتماد النتيجة من المختبر |

| **نظام الإشعارات (Notification Engine)** | Message Queue (غير متزامن) | **صادر** (Outbound) | إرسال (SMS، Push، IVR) بمواعيد الجرعات وتذكيرات الإبلاغ | جدول زمني (Scheduler) + أوامر التقييم |

| **نظام الترصد الوبائي (Surveillance)** | Batch ETL (ليلي) | **صادر** (Outbound) | إرسال بيانات مجمعة (مخفية الهوية) عن متوسط مدة الأعراض ومعدلات الاستجابة | منتصف الليل يومياً |

| **غرفة الطوارئ (EOC Portal - 9)** | WebSocket (لحظي) | **صادر** (Outbound) | إرسال إنذار أحمر (حالة حرجة) يحتوي على إحداثيات الموقع ورقم المريض | تفعيل محرك التنبيهات للمستوى الأحمر |

| **نظام التكامل الخارجي (وزارة الصحة)** | SFTP / REST API | **صادر** (Outbound) | إرسال تقارير موجزة عن حالات المتابعة المنزلية (بدون أسماء) | كل 6 ساعات |

## 3. نظرة عامة على المخطط الانسيابي (Sequence Flow)

```mermaid
sequenceDiagram
    participant Clinic as 5. العيادات
    participant FollowUp as نظام المتابعة
    participant Patient as المريض (التطبيق)
    participant Risk as محرك التقييم
    participant EOC as 9. الطوارئ

    Clinic->>FollowUp: إرسال خطة علاج (وصفة + تشخيص)
    FollowUp->>Patient: إشعار تفعيل الحساب + جدول الأدوية
    
    loop كل يوم
        Patient->>FollowUp: إدخال الأعراض والعلامات الحيوية
        FollowUp->>Risk: إرسال البيانات للتقييم
        Risk-->>FollowUp: إرجاع درجة الخطر الجديدة
        
        alt الحالة حمراء
            FollowUp->>EOC: إرسال إنذار فوري (WebSocket)
            EOC-->>Patient: إشعار بالاتصال الوشيك
        else الحالة مستقرة
            FollowUp->>Patient: تغذية راجعة (حالة مطمئنة)
        end
    end

    Note over FollowUp,Patient: انتهاء الدورة
    FollowUp->>Patient: إصدار شهادة التعافي (QR Code)
