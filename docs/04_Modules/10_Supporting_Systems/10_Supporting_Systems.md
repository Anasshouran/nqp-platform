# 10_Supporting_Systems - أنظمة الدعم (المحرك الذكي للمنصة)

## 1. المقدمة
تمثل أنظمة الدعم (Supporting Systems) الطبقة الوسطى في العمارة ثلاثية المستويات للمنصة. هذه الأنظمة هي المسؤولة عن الفصل المنطقي بين واجهات المستخدم (البوابات) ومنطق الأعمال المعقد، مما يضمن أن أي تحديث في خوارزميات التقييم أو تعريفات الأمراض ينعكس فوراً على جميع البوابات دون الحاجة لإعادة نشر التطبيقات الأمامية. صُممت هذه الأنظمة لتكون عديمة الحالة (Stateless) باستثناء قاعدة البيانات، مما يتيح التوسع الأفقي السلس (Horizontal Scaling) باستخدام Django مع Gunicorn و Redis للتخزين المؤقت.

## 2. مكونات أنظمة الدعم
يتكون هذا المجلد من الأنظمة الفرعية التالية، والتي تمثل "العمود الفقري" للمنصة:

| الرقم | النظام الفرعي | المسؤولية الأساسية | البوابات المعتمدة عليه | الملف المرجعي |

| :---         | :---            | :---            | :---        | :--- |

| 1 | إدارة الأمراض | تعريف المعايير التشخيصية للحالات (ICD-11)، وإدارة قواعد الأدوية والتداخلات الدوائية. | 5. العيادات، 6. المختبرات | `Disease_Management/` |

| 2 | محرك تقييم المخاطر | تطبيق خوارزميات الذكاء الاصطناعي (شجرة القرار) لتصنيف المسافرين لحظة وصولهم (أخضر/أصفر/أحمر). | 2. المسافرين، 4. موظفي الحجر | `Risk_Engine/` |

| 3 | الترصد الوبائي | تحليل البيانات المجمعة، رسم الخرائط الحرارية، وإطلاق الإنذارات المبكرة للتفشي. | 8. الإدارة الاتحادية، 9. الطوارئ | `Surveillance/` |

| 4 | محرك الإشعارات | إدارة جميع قنوات الاتصال (SMS، Push، واتساب، البريد الإلكتروني) باستخدام Celery للمهام غير المتزامنة. | 1. الموقع العام، 2. المسافرين، 3. شركات الطيران | `Notifcation_Engine/` |

| 5 | المتابعة الصحية | إدارة الحالات بعد الخروج من الحجر، التقييم الديناميكي (التنبيهات الحمراء)، وشهادات التعافي. | 2. المسافرين، 5. العيادات، 9. الطوارئ | `05_Health_Followup_System/` |

| 6 | التقارير ولوحات المعلومات | توليد التقارير الإدارية والتنفيذية بصيغ متعددة (PDF/Excel) باستخدام Celery للمعالجة الثقيلة. | 8. الإدارة الاتحادية، وزارة الصحة | `Reporting/` |

| 7 | إدارة الوثائق | تخزين واسترجاع الملفات والمستندات (شهادات، جوازات، نتائج فحوصات) مع آليات التوقيع الرقمي. | جميع البوابات (رفع/تنزيل) | `Document_Management/` |

| 8 | التكامل مع منظمة الصحة العالمية | الالتزام بمعايير (IHR 2005)، و(FHIR)، و(ICD-11)، وإعداد التقارير الدولية. | 11. التكامل الخارجي | `who/` |

## 3. مبدأ التكامل (Integration Principle)
- لا تتداخل الأنظمة مباشرة: جميع البوابات تتواصل مع نظام الدعم عبر طبقة الـ API Gateway فقط (باستخدام Django REST Framework).

- معرف واحد للحالة (Single Source of Truth): يتم حفظ الملف الصحي للمسافر في قاعدة البيانات المركزية (PostgreSQL)، ويتم تحديثه بواسطة أنظمة الدعم (مثل تحديث درجة الخطر بواسطة Risk_Engine).

- التخزين المؤقت (Caching): يتم استخدام Redis لتسريع الوصول إلى البيانات الأكثر طلباً (مثل: تعريفات الأمراض، قوائم الدول الموبوءة) لتقليل الضغط على قاعدة البيانات.

- المهام غير المتزامنة: يتم استخدام Celery + Redis للمهام الثقيلة (مثل: توليد التقارير الكبيرة، إرسال الإشعارات الجماعية).
