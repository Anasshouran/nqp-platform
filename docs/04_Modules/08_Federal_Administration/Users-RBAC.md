# إدارة المستخدمين والصلاحيات (Users Management & RBAC)

## 1. الهدف
تمكين مسؤولي النظام (Federal Admin و Super Admin) من إدارة دورة حياة المستخدمين في المنصة (إنشاء، تعديل، تعطيل، حذف) وتعيين الأدوار والصلاحيات (RBAC) لهم بناءً على مبدأ "أقل امتياز (Least Privilege)"، لضمان أمن النظام ومنع الوصول غير المصرح به.

## 2. مكونات الصفحة

### 2.1. قائمة المستخدمين (Users List)
- عرض جدول بجميع المستخدمين المسجلين في المنصة، مع إمكانية التصفية حسب:
  - **الدور (Role)**: (Super Admin، Federal Admin، Sector Manager، Port Officer، Doctor، Lab Tech، Food Inspector، EOC Operator، Carrier Rep).
  - **الحالة (Status)**: (نشط، غير نشط، معلق).
  - **القطاع/المنفذ**: (تصفية حسب القطاع أو المنفذ المرتبط).
- **الأعمدة**:
  - الاسم الكامل.
  - البريد الإلكتروني.
  - رقم الجوال.
  - الدور (مع تاج ملون).
  - المنفذ/القطاع المرتبط.
  - تاريخ آخر دخول.
  - الحالة (نشط/غير نشط) مع أيقونة.
  - **أزرار الإجراءات**: (تعديل، تعطيل/تفعيل، حذف، إعادة تعيين كلمة المرور).

### 2.2. نموذج إضافة / تعديل مستخدم (User Form)
- **الحقول الأساسية**:
  - الاسم الكامل (نص، إلزامي).
  - البريد الإلكتروني (بريد إلكتروني، إلزامي، فريد).
  - رقم الجوال (نص، إلزامي، فريد).
  - كلمة المرور (حقلين: كلمة المرور وتأكيدها، إلزامي للإضافة، اختياري للتعديل).
- **الحقول الإدارية**:
  - **الدور (Role)**: قائمة منسدلة (يتم تحديدها مسبقاً في النظام).
  - **القطاع المرتبط (Sector)**: (اختياري) ربط المستخدم بقطاع معين.
  - **المنفذ المرتبط (Port)**: (اختياري) ربط المستخدم بمنفذ معين (للموظفين الميدانيين).
  - **حالة الحساب (Account Status)**: (نشط / غير نشط).
- **صلاحيات إضافية (Permissions)**:
  - (للمستخدمين المتقدمين) يمكن تعيين صلاحيات دقيقة (Granular Permissions) تتجاوز صلاحيات الدور الأساسي (مثل: السماح لطبيب معين بمشاهدة تقارير منافذ أخرى).

### 2.3. إدارة الأدوار والصلاحيات (Roles & Permissions Management) - للمشرفين فقط
- **قائمة الأدوار**:
  - عرض الأدوار الموجودة (Super Admin, Federal Admin, Sector Manager, Port Officer, Doctor, Lab Tech, Food Inspector, EOC Operator, Carrier Rep).
  - **زر**: "إضافة دور جديد" (للمرونة المستقبلية).
- **صلاحيات الدور (Role Permissions)**:
  - عند النقر على دور، تظهر قائمة بجميع الصلاحيات المتاحة في النظام (مقسمة حسب التطبيق: `users`, `ports`, `screenings`, `clinic`, `lab`, `food`, `reports`).
  - يمكن تفعيل/تعطيل كل صلاحية عبر خانة اختيار (Checkbox).
  - **توصية**: يتم تطبيق (RBAC) عبر مجموعات Django (Groups) و (Permissions).

### 2.4. سجل نشاط المستخدمين (User Activity Log)
- عرض جدول زمني (Timeline) لآخر نشاطات المستخدمين:
  - (مثل: "2024-07-25 10:00 - قام المستخدم أحمد بتسجيل الدخول من IP 192.168.1.1").
  - (مثل: "2024-07-25 10:30 - قام المستخدم سارة بتحديث حالة فحص المسافر X").

## 3. منطق الأعمال (Business Logic)
- **التحقق من التفرد**: البريد الإلكتروني ورقم الجوال يجب أن يكونا فريدين في النظام.
- **كلمة المرور الأولية**: عند إنشاء مستخدم جديد، يتم إرسال كلمة مرور مؤقتة عبر البريد الإلكتروني (أو SMS) ويُطلب من المستخدم تغييرها عند أول دخول.
- **منع الحذف**: لا يمكن حذف المستخدم الذي لديه سجلات نشطة (مثل: فحوصات، إحالات)؛ يمكن فقط تعطيله (تعيين `is_active = False`).

---

# نظام إدارة المستخدمين والصلاحيات (User & Access Management)

## الهدف

إدارة حسابات المستخدمين، والأدوار الوظيفية، والصلاحيات، والتحكم في الوصول إلى أنظمة منصة الحجر الصحي القومي، مع ضمان أمن المعلومات وتتبع جميع العمليات.

---

# الوظائف الرئيسية

## 1. إدارة المستخدمين (User Management)

يتيح النظام:

* إنشاء مستخدم جديد.
* تعديل بيانات المستخدم.
* إيقاف أو تفعيل الحساب.
* حذف الحساب (وفق السياسات المعتمدة).
* إعادة تعيين كلمة المرور.
* قفل الحساب بعد محاولات دخول فاشلة.
* إدارة بيانات الاتصال بالمستخدم.

---

## 2. إدارة الأدوار (Role Management)

يمكن إنشاء أدوار مختلفة مثل:

### الإدارة الاتحادية

* مدير النظام.
* المدير العام للحجر الصحي.
* مدير إدارة الترصد.
* مدير إدارة الأمراض.
* مدير التقارير والإحصاءات.

### إدارة القطاع

* مدير القطاع.
* مشرف القطاع.

### المنفذ

* مدير المنفذ.
* موظف الحجر الصحي.
* طبيب عيادة الحجر الصحي.
* موظف المختبر.
* موظف التسجيل.
* موظف التقارير.

---

## 3. إدارة الصلاحيات (Permission Management)

تحديد الصلاحيات لكل دور، مثل:

### صلاحيات القراءة

* عرض بيانات المسافرين.
* عرض التقارير.
* عرض نتائج المختبر.
* عرض الإحصائيات.

### صلاحيات الإنشاء

* إنشاء استمارة جديدة.
* تسجيل فحص صحي.
* إنشاء إحالة.
* تسجيل نتائج المختبر.

### صلاحيات التعديل

* تعديل بيانات الفحص.
* تحديث الحالة الصحية.
* تعديل بيانات المتابعة.

### صلاحيات الاعتماد

* اعتماد التقارير.
* اعتماد نتائج المختبر.
* اعتماد الإحالات.
* اعتماد القرارات الطبية.

### صلاحيات الإدارة

* إدارة المستخدمين.
* إدارة الأدوار.
* إدارة الصلاحيات.
* إدارة إعدادات النظام.

---

# التحكم في الوصول (Access Control)

يعتمد النظام على:

* **Role-Based Access Control (RBAC)**: صلاحيات حسب الدور الوظيفي.
* **Data Scope**: تقييد الوصول حسب القطاع أو المنفذ.
* **Least Privilege**: منح أقل صلاحيات لازمة لأداء المهام.

---

# تسجيل الدخول

يدعم النظام:

* اسم المستخدم وكلمة المرور.
* تسجيل الدخول الموحد (Single Sign-On) عند توفره.
* المصادقة الثنائية (2FA) للحسابات الحساسة.
* انتهاء الجلسة تلقائيًا بعد فترة من عدم النشاط.

---

# سجل التدقيق (Audit Log)

يقوم النظام بتسجيل:

* تسجيل الدخول والخروج.
* إنشاء المستخدمين.
* تعديل الصلاحيات.
* حذف أو تعطيل الحسابات.
* عرض أو تعديل بيانات المسافرين.
* جميع العمليات الحساسة مع التاريخ والوقت والمستخدم والجهاز.

---

# توزيع الصلاحيات حسب المستوى الإداري

| ----------------- | ---------------------------------------- |

| موظف المختبر      | العينات ونتائج الفحوصات                  |
| موظف التسجيل      | تسجيل المسافرين وتحديث بياناتهم الأساسية |

        │
 ┌──────┴──────────┐
 ▼                 ▼
مدير القطاع      مدير النظام
        │
        ▼
مدير المنفذ
        │
 ┌──────┼─────────────┬──────────────┐
 ▼      ▼             ▼              ▼
موظف   طبيب        موظف المختبر   موظف التسجيل
الحجر   العيادة
