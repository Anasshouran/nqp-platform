# 08_Federal_Administration - بوابة الإدارة الاتحادية

## 1. الهدف الاستراتيجي
تزويد الإدارة العليا في وزارة الصحة والإدارة الاتحادية للمنصة بأداة رقمية مركزية للإشراف الكامل على جميع جوانب المنصة التشغيلية والإدارية. تهدف البوابة إلى:
- **الحوكمة الرقمية**: إدارة المستخدمين والصلاحيات (RBAC) بشكل مرن وآمن.
- **الرقابة التشغيلية**: مراقبة أداء جميع المنافذ والقطاعات عبر مؤشرات الأداء الرئيسية (KPIs) الفورية.
- **التخطيط الاستراتيجي**: توليد تقارير وطنية شاملة لدعم اتخاذ القرار.
- **المرونة الإدارية**: التحكم في إعدادات النظام العامة (بدون الحاجة لتدخل المطورين) وإدارة الهيكل التنظيمي للمنصة (القطاعات والمنافذ).

## 2. الممثلون (Actors)
- **المشرف الاتحادي (Federal Admin)**: المستخدم الأساسي (يدير المستخدمين، المنافذ، ويطلع على التقارير الوطنية).
- **المدير الفني للنظام (Super Admin)**: لديه صلاحيات كاملة (يمكنه تعديل إعدادات النظام الأساسية وإدارة جميع البيانات).
- **مدير القطاع (Sector Manager)**: (صلاحية محدودة) يمكنه الاطلاع على تقارير قطاعه وإدارة منافذه فقط.
- **مدقق الحسابات (Auditor)**: (صلاحية قراءة فقط) يستطيع الاطلاع على سجلات التدقيق (Audit Logs) والتقارير دون إجراء تغييرات.

## 3. الميزات الرئيسية (Key Features)
| الميزة | الوصف | الأولوية |
| :--- | :--- | :--- |
| **إدارة المستخدمين والصلاحيات (RBAC)** | إنشاء، تعديل، تعطيل المستخدمين، وتعيين الأدوار (الأطباء، الموظفين، المشرفين). | عالية |
| **إدارة المنافذ** | إضافة وتعديل المنافذ (المطارات، الموانئ، البرية) مع تحديد موقعها وقطاعها. | عالية |
| **إدارة القطاعات** | إنشاء وتنظيم القطاعات الجغرافية أو التشغيلية (مثل: قطاع الخرطوم، قطاع البحر الأحمر). | متوسطة |
| **مؤشرات الأداء الرئيسية (KPIs)** | لوحة تحكم وطنية تعرض المؤشرات الحيوية (أوقات الفحص، حالات التفشي، نسب الإشغال). | عالية |
| **التقارير الوطنية** | إنشاء وتصدير تقارير شاملة (بيانية وإحصائية) على المستوى الوطني بصيغ (PDF، Excel). | عالية |
| **الإعدادات العامة** | تعديل إعدادات النظام (عتبات التنبيه، فترات الحجر، قوالب الإشعارات، تكاملات البريد الإلكتروني). | متوسطة |
| **سجل التدقيق (Audit Logs)** | عرض جميع عمليات الدخول والتغييرات التي حدثت في النظام لأغراض المراجعة والشفافية. | عالية |

## 4. دورة الحياة الإدارية (Administrative Lifecycle)
```mermaid
flowchart LR
    A[إضافة مستخدم جديد] --> B[تعيين الدور والصلاحيات]
    B --> C[ربط المستخدم بالمنفذ/القطاع]
    C --> D[المستخدم يبدأ العمل على المنصة]
    D --> E[مراقبة أداء المستخدم والمنفذ عبر KPIs]
    E --> F[توليد تقارير دورية للإدارة العليا]
    F --> G[تعديل الإعدادات أو الصلاحيات حسب الحاجة]

5. المتطلبات التقنية (Technical Requirements)

    الواجهة الأمامية: React + Tailwind CSS (مسار /federal-admin).

    الخلفية: Django REST Framework (نقاط النهاية تحت /api/v1/admin/).

    المصادقة: JWT مع صلاحيات صارمة (الدور: FEDERAL_ADMIN، SUPER_ADMIN، SECTOR_MANAGER).

    الصلاحيات الدقيقة (Granular Permissions): استخدام نظام (Django's Permission System) للتحكم في كل إجراء (مثل: add_user, change_port, view_kpis).

    التخزين: يتم تخزين التقارير المصدرة (PDF/Excel) مؤقتاً على (MinIO/S3) للتحميل.

    النسخ الاحتياطي: توفير واجهة لجدولة وإدارة النسخ الاحتياطية لقاعدة البيانات (اختياري).

    سجل التدقيق: تسجيل كل إجراء مهم في جدول audit_logs (من قام، ماذا فعل، متى) مع منع التعديل على هذا الجدول.

6. التكامل مع الأنظمة الأخرى

    جميع البوابات (1-9): تستهلك إعدادات المستخدمين والصلاحيات والمنافذ من هذه البوابة المركزية.

    نظام الإشعارات: يُستخدم لإرسال إشعارات إدارية (مثل: "تم تعيينك كمدير منفذ جديد").

    نظام التقارير ولوحات المعلومات: هو المصدر الرئيسي للبيانات التي تُعرض في هذه البوابة.

    التكامل الخارجي (وزارة الصحة): تصدير التقارير الوطنية إلى وزارة الصحة عبر التكامل المخصص.

# الوحدة 8: بوابة الإدارة الاتحادية

 الوحدة المنطقية:  بوابة الإدارة الاتحادية (Federal Administration)  
 التطبيقات التقنية (Django Apps):  `users`, `reports`  
 المستخدمون:  المدير العام (FEDERAL_MANAGER)، مديرو القطاعات (SECTOR_MANAGER)، ومدير النظام (SUPER_ADMIN).

## الأهداف

- إدارة الهيكل التنظيمي (قطاعات، منافذ، عيادات، متابعة).
- إدارة المستخدمين والصلاحيات (RBAC) على جميع المستويات.
- عرض التقارير الوطنية ومؤشرات الأداء (KPIs).
- إعدادات النظام العامة.

## المكونات الرئيسية

1.  إدارة المستخدمين:  قائمة، إضافة، تعديل، تعطيل، إعادة تعيين كلمة المرور.
2.  إدارة الأدوار والصلاحيات:  تعديل صلاحيات كل دور (مصفوفة صلاحيات).
3.  سجل التدقيق (Audit Log):  عرض جميع العمليات الحساسة التي تمت في النظام.
4.  لوحات التحكم:  عرض إحصائيات وطنية، مقارنة بين القطاعات والمنافذ.

## الجداول المرتبطة (في init.sql)

- `users`
- `roles`, `permissions`, `role_permissions`
- `organizational_units`
- `audit_logs`

## نقاط API الرئيسية

| الطريقة | المسار | الوصف | الصلاحية |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/admin/users/` | قائمة المستخدمين | SUPER_ADMIN / FEDERAL_MANAGER |
| `POST` | `/api/admin/users/` | إضافة مستخدم جديد | SUPER_ADMIN / FEDERAL_MANAGER |
| `PUT` | `/api/admin/users/{id}/role/` | تغيير دور مستخدم | SUPER_ADMIN |
| `GET` | `/api/admin/audit-log/` | عرض سجل التدقيق | SUPER_ADMIN |
| `GET` | `/api/admin/stats/` | إحصائيات وطنية | FEDERAL_MANAGER / SUPER_ADMIN |

## الاعتماديات (Dependencies)

- تعتمد على `core` (للصلاحيات المخصصة `IsSuperAdmin`).
- تعتمد على `organizational_units` لتصفية المستخدمين حسب النطاق.

--------------إذا كان النظام سيستخدم في  وزارة الصحة الاتحادية  ويغطي جميع  القطاعات (الولايات أو الأقاليم) ، فمن الأفضل أن يكون النظام متعدد المستويات (National Health Screening Platform)، بحيث يعمل على المستوى الاتحادي ومستوى القطاع ومستوى المنفذ.

# التقارير الاتحادية

يمكن للإدارة العامة استخراج تقارير مثل:

* عدد المسافرين حسب القطاع.
* عدد المسافرين حسب المنفذ.
* أكثر المنافذ استقبالاً للمسافرين.
* عدد الحالات المحولة للعيادات.
* الحالات التي تحتاج إلى متابعة.
* توزيع الجنسيات.
* توزيع الأمراض.
* أداء كل قطاع.
* مؤشرات الأداء الوطنية (KPIs).

## الميزة الأساسية

هذا التصميم يجعل النظام  هرميًا (Hierarchical Multi-Level System) ، بحيث يرى كل مستخدم فقط البيانات التي تقع ضمن نطاق صلاحياته:

*  الإدارة الاتحادية : ترى بيانات جميع القطاعات والمنافذ.
*  مدير القطاع : يرى بيانات قطاعه فقط.
*  مدير المنفذ : يرى بيانات منفذه فقط.
*  الموظف : يتعامل مع الحالات المسجلة في منفذه فقط.

وهذا يوفر حوكمة جيدة للبيانات، ويضمن سهولة إدارة النظام على المستوى القومي مع الحفاظ على خصوصية البيانات والصلاحيات.
