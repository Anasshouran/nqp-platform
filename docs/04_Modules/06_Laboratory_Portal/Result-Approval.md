# اعتماد النتائج (Result Approval)

## 1. الهدف
تمكين مشرف المختبر من مراجعة النتائج المدخلة من قبل الفنيين، والتأكد من دقتها وسلامتها قبل اعتمادها وإرسالها إلى الجهات المعنية (العيادات، نظام الترصد، وغرفة الطوارئ). تضمن هذه العملية جودة النتائج وتقلل من الأخطاء الطبية.

## 2. مكونات الصفحة

### 2.1. قائمة النتائج بانتظار الاعتماد (Pending Approval List)
- عرض جدول بجميع النتائج التي تم إدخالها وتنتظر اعتماد المشرف:
  - الأعمدة: (الباركود، اسم المريض، الفحص، النتيجة المدخلة، القيمة الرقمية، تاريخ الإدخال، اسم الفني، الأولوية).
  - **زر**: "مراجعة" (لفتح نموذج المراجعة).
  - **زر**: "اعتماد الكل" (للمشرفين المتقدمين) لاعتماد جميع النتائج المعلقة دفعة واحدة (مع تحذير أمني).

### 2.2. نموذج مراجعة النتيجة (Result Review Form)
- **عرض النتيجة المدخلة** (للقراءة فقط):
  - (الباركود، اسم المريض، نوع العينة، الفحص، النتيجة المدخلة، القيمة الرقمية، ملاحظات الفني).
- **قرار المشرف (Supervisor Decision)**:
  - **قائمة منسدلة**: (اعتماد `APPROVE`، رفض `REJECT`).
  - **حقل نصي (سبب الرفض)** - إلزامي إذا تم اختيار `REJECT`:
    - (مثل: "النتيجة غير منطقية، يُرجى إعادة التحليل"، "القيمة الرقمية غير متطابقة مع النتيجة النوعية").
  - **ملاحظات المشرف** (اختياري): حقل نصي لإضافة أي ملاحظات إضافية.
- **زر**: "تأكيد القرار" (حفظ القرار وتحديث حالة العينة).

### 2.3. حالة العينة بعد القرار
- **معتمدة (APPROVED)**:
  - يتم تحديث حالة العينة إلى `APPROVED`.
  - يتم إرسال النتيجة تلقائياً إلى:
    1. **بوابة العيادات (5)**: لتحديث التشخيص وخطط العلاج.
    2. **نظام الترصد الوبائي**: (للإحصائيات المجمعة).
    3. **غرفة الطوارئ (9)**: (إشعار فوري عبر WebSocket إذا كانت النتيجة إيجابية لمرض خطير).
  - يتم إشعار الطبيب المعالج عبر البريد الإلكتروني و/أو الإشعار داخل البوابة.
- **مرفوضة (REJECTED)**:
  - يتم تحديث حالة العينة إلى `REJECTED`.
  - يتم إشعار الفني المسؤول (عبر البريد الإلكتروني والإشعار داخل البوابة) بضرورة إعادة التحليل، مع عرض سبب الرفض.
  - يتم إعادة تعيين العينة إلى الحالة `PROCESSING` (قيد التحليل) لبدء دورة جديدة.

## 3. منطق الأعمال (Business Logic)
- **فصل الصلاحيات**: لا يمكن للفني الذي أدخل النتيجة أن يعتمدها بنفسه (يجب أن يكون المشرف مستخدماً مختلفاً).
- **النتائج الحرجة (Critical Results)**: في حالة النتيجة الإيجابية لمرض خطير (PHEIC)، يتم إرسال إشعار فوري (WebSocket + SMS) للمشرف فور إدخال النتيجة، قبل اعتمادها، لتسريع عملية الاعتماد والإبلاغ.
- **سجل التدقيق (Audit Log)**: يتم تسجيل كل عملية اعتماد أو رفض في سجل التدقيق مع (المشرف، التاريخ، السبب).

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `GET` | `/api/v1/lab/samples/pending-approval` | قائمة النتائج بانتظار الاعتماد. |
| `POST` | `/api/v1/lab/samples/{id}/approve` | اعتماد النتيجة. |
| `POST` | `/api/v1/lab/samples/{id}/reject` | رفض النتيجة (مع سبب). |
