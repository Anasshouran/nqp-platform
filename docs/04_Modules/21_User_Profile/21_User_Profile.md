# إدارة الهوية والوصول الموحّدة — الملف الشخصي للمستخدم (User Profile)

> معرّف الوحدة: 21_User_Profile  
> تاريخ التحديث: 2026-08-08

## 1. المبدأ

تعتمد المنصة **حساباً وصفحة دخول موحّدة لكل المستخدمين**. لا ينشأ لكل نظام
(مطار / ميناء / معبر بري / مطبخ...) ملفّ مستخدم منفصل، بل يوجد **User واحد**
تتحدد صلاحياته عبر:

```text
User
  →  [الحساب والأمان]
EmployeeProfile
  →  [بيانات الموظف + المسمى + الهاتف الداخلي + التفضيلات]
Role
  →  [الدور المحدد: مفتش / كاتب / محاسب ...]
Permissions
  →  [صلاحيات view/add/edit/delete/export لكل مورد]
Organizational Scope
  →  Sector → Department → Station  (من الهيكل الإداري)
```

على سبيل المثال: مفتش حجر صحي في مطار يستخدم نفس الحساب الموحّد بدور
`AIRPORT_INSPECTOR` ونطاق `STATION`، ولا يُنشأ له نظام مستخدمين منفصل.

## 2. بنية البيانات

### 2.1 توزيع المسؤوليات

| الكيان | الملف/النموذج | المسؤولية |
| --- | --- | --- |
| `User` | `apps/accounts` | الحساب والأمان: البريد، كلمة المرور، `is_mfa_enabled`، `account_expires_at`، الجلسات |
| `EmployeeProfile` | `apps/accounts` | بيانات الموظف والتفضيلات والتوقيع الرقمي (OneToOne مع المستخدم) |
| `Role` + `RoleAssignment` | `apps/accounts` | الأدوار والصلاحيات ونطاق الوصول (GLOBAL/SECTOR/DEPARTMENT/STATION) |
| `OrgAssignment` | `apps/organization` | الموقع التنظيمي الفعلي: المنصب/القطاع/الإدارة/المحطة |
| `PermissionAudit` | `apps/accounts` | سجل تدقيق منح/رفض الصلاحيات |

### 2.2 حقول `EmployeeProfile`

- **البيانات الأساسية**: الرقم الوظيفي، الاسم بالعربية/الإنجليزية، الجنس، تاريخ الميلاد.
- **بيانات الوظيفة**: المسمى الوظيفي، تاريخ التعيين، حالة الموظف
  (`ACTIVE / ON_LEAVE / SUSPENDED / TERMINATED`).
- **التواصل**: الهاتف الداخلي، المكتب، وسيلة التواصل المفضلة.
- **التفضيلات**: اللغة (`AR/EN`)، المظهر (`LIGHT/DARK`)، المنطقة الزمنية
  (افتراضياً `Africa/Khartoum`)، مفاتيح الإشعارات (بريد/رسائل/داخل النظام).
- **التوقيع الرقمي**: حالة التوقيع (`UNREGISTERED/REGISTERED/VERIFIED/EXPIRED`)،
  الشهادة، تاريخي الإصدار والانتهاء — لمن يملكون صلاحية الاعتماد.

### 2.3 حقول الأمان على `User`

- `is_mfa_enabled`: تفعيل المصادقة الثنائية.
- `account_expires_at`: تاريخ انتهاء الحساب.
- `last_login` و`created_at` محتجّزان لمؤشرات النشاط.

## 3. نقاط API

من `AuthViewSet` (متوافرة للمستخدم المصادَق على نفسه فقط):

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/v1/auth/profile/` | الملف الموحّد: الحساب + بيانات الموظف + الأدوار/الصلاحيات + النطاق التنظيمي + الأمان |
| `PATCH` | `/api/v1/auth/profile/` | تحديث ذاتي: بيانات الحساب (الاسم/الجوال) + ملف الموظف + التفضيلات |
| `GET` | `/api/v1/auth/me/` | بيانات المستخدم الأساسية (متاح سابقاً) |
| `POST` | `/api/v1/auth/change-password/` | تغيير كلمة المرور (الحد الأدنى 8 أحرف) |

### 3.1 المخرجات الرئيسية لـ `GET /profile/`

```
user                   (الحساب)
profile                (EmployeeProfile)
security               (is_mfa_enabled / account_expires_at / last_login / الحالة)
roles                  (الأدوار المعيّنة مع scope_type/scope_id)
organization           (المناصب من OrgAssignment)
effective_permissions  (كود الصلاحيات الفعلية مثل `food:view`)
scopes                 (النطاقات النشطة)
```

## 4. تطبيق في الواجهة الأمامية

- **صفحة** `/app/profile` — «الملف الشخصي»:
  - الهوية والحساب (تحرير الاسم/الجوال).
  - بيانات الوظيفة (الرقم الوظيفي، المسمى، الأسماء، الجنس، التاريخ).
  - النطاق التنظيمي والأدوار (قراءة فقط).
  - الصلاحيات الفعليةمجموعة حسب المورد (قراءة فقط — لا تُعدَّل من الملف).
  - الأمان (قراءة فقط + توجيه لتغيير كلمة المرور).
  - التوقيع الرقمي (قراءة فقط).
  - التفضيلات (اللغة/المظهر/المنطقة الزمنية/الإشعارات — قابلة للتعديل).
- عنصر «الملف الشخصي» في الشريط الجانبي يظهر **لكل المستخدمين** المصادق عليهم
  بغضّ النظر عن دورهم.

## 5. الفرق عن التصميم القديم

- لا وجود لصفحة دخول بطابع واحد محدد لكل مفتش (تم توحيدها في `/login`).
- تحديد الصلاحيات يتم حصرياً عبر `Role → Permissions → Scope` وليس عبر حقل ملف.
- بيانات الموظف معزوله في `EmployeeProfile` منفصل يسمح بفصل الحساب
  (`User`) عن بيانات الموظف كما في مرجعية جدولتين `users` و`employees`، لكن
  دون كسر الاقترانات الحالية (`RoleAssignment.user`، `OrgAssignment.user`).
