# 07_Offline_Mode - وضع عدم الاتصال (Offline-First)

## 1. الهدف
ضمان استمرارية إدخال البيانات حتى في حال انقطاع الاتصال بالإنترنت، ثم مزامنتها تلقائياً عند عودة الاتصال. هذا أمر بالغ الأهمية في المناطق النائية أو أثناء الأزمات.

## 2. استراتيجية التخزين المحلي (Local Storage Strategy)

### 2.1. قاعدة البيانات المحلية (SQLite)
- **الجداول الأساسية**:
  - `daily_logs` (الإبلاغات اليومية غير المرسلة).
  - `medication_confirmations` (تأكيدات الأدوية).
  - `notifications` (الإشعارات المستلمة).
- **المزامنة**: يتم استخدام (Queue) لتخزين البيانات غير المرسلة، وإرسالها عند عودة الاتصال.

### 2.2. التخزين الآمن (Secure Storage)
- **Access Token** و **Refresh Token**: تُخزن في `flutter_secure_storage` (مشفر).
- **User ID**: تخزين معرف المستخدم للاستمرار في الجلسة.

### 2.3. التخزين المؤقت (Cache)
- **بيانات الملف الشخصي**: تُخزن في (Hive) لتسريع عرض الصفحة.
- **قائمة الأدوية**: تُخزن محلياً لعرضها دون انتظار تحميل.

## 3. تدفق المزامنة (Sync Flow)

```mermaid
flowchart TD
    Start([بداية: المستخدم يفتح التطبيق]) --> Check{هل هناك اتصال؟}
    Check -- نعم --> Step1[المزامنة التلقائية<br/>(إرسال البيانات المعلقة)]
    Step1 --> Step2[جلب البيانات الجديدة<br/>(الحالة، الأدوية، الشهادات)]
    Step2 --> Step3[تحديث التخزين المحلي]
    Step3 --> End([النهاية: التطبيق جاهز])
    
    Check -- لا --> Step4[عرض البيانات المخزنة محلياً]
    Step4 --> Step5[تخزين أي إدخالات جديدة في Queue]
    Step5 --> Step6[إشعار المستخدم: "غير متصل"]
    Step6 --> Step7[عند عودة الاتصال ← المزامنة]
    Step7 --> End

4. التعامل مع تعارض البيانات (Conflict Resolution)

    الأولوية للبيانات الأحدث: إذا كان هناك تعارض (مثلاً: حالة تم تحديثها من الخادم وتحديثها محلياً)، يتم اعتماد البيانات الأحدث تاريخياً (باستخدام updated_at).

    الإشعار: يتم إشعار المستخدم في حال وجود تعارض يحتاج إلى تدخل يدوي (نادر).

5. واجهة المستخدم (UI)

    شريط الحالة العلوي: أيقونة (🟢 متصل / 🔴 غير متصل).

    رسالة عند الإرسال دون اتصال: "تم حفظ الإبلاغ. سيتم رفعه تلقائياً عند عودة الاتصال."

    زر المزامنة اليدوي: (اختياري) للمستخدمين الذين يرغبون في المزامنة فوراً.
