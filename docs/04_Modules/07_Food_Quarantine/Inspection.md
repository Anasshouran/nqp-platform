# التفتيش الظاهري (Visual Inspection)

## 0. النموذج المطبق (`FoodInspection` — حقول مُصنَّفة + القرار)
- **الحقول المُصنَّفة**: `container_condition` / `container_status`, `package_condition`,
  `temperature`, `production_date`, `expiry_date`, `batch_number`, `damaged_count`,
  `sound_count`, `damaged_weight_kg`, `sound_weight_kg`, `notes`.
- **قرار التفتيش** (`FoodInspection.decision`) وتأثيره على حالة الشحنة:

| القرار | الحالة الناتجة | التفسير |
| :--- | :--- | :--- |
| `COMPLIANT` | `RELEASED` (مع `final_decision=COMPLIANT`) | مطابق → إفراج مباشر. |
| `NEEDS_ANALYSIS` | `UNDER_INSPECTION` | يحتاج تحاليل → متابعة العينات ثم القرار. |
| `NON_COMPLIANT` | `AWAITING_DECISION` | غير مطابق → قرار نهائي. |

- لا يُسمح بتكرار التفتيش على نفس الشحنة («تم التفتيش مسبقاً»).
- Endpoint: `POST /api/v1/food/shipments/{id}/inspection` (سيرياليزر `FoodInspectionSerializer`).

## 1. الهدف
تمكين مفتش الحجر الغذائي من تسجيل نتائج التفتيش الظاهري (البصري) للشحنة، بما في ذلك فحص (العبوات، التواريخ، درجة الحرارة، المظهر العام)، واتخاذ قرار أولي (مطابق / غير مطابق) يحدد ما إذا كانت الشحنة بحاجة إلى عينات مخبرية إضافية أم لا.

## 2. مكونات الصفحة

### 2.1. نموذج التفتيش الظاهري (Inspection Form)
- **بيانات الشحنة** (للرجوع السريع):
  - (رقم البيان، المورد، دولة المنشأ، قائمة المنتجات).
- **عناصر التفتيش (Inspection Checklist)**:
  | العنصر | الوصف | الخيارات |
  | :--- | :--- | :--- |
  | **العبوات** | فحص سلامة العبوات (تمزق، ثقوب، تلف). | مطابق، غير مطابق، غير قابل للتطبيق. |
  | **تواريخ الإنتاج والانتهاء** | التحقق من صلاحية المنتجات. | مطابق، غير مطابق (مع إدخال تاريخ الانتهاء الفعلي). |
  | **درجة الحرارة** | قياس درجة حرارة الشحنة (للمنتجات المبردة والمجمدة). | مطابق، غير مطابق (مع إدخال درجة الحرارة المقاسة). |
  | **المظهر العام** | فحص المظهر العام للمنتجات (رائحة، لون، قوام). | مطابق، غير مطابق (مع ملاحظات). |
  | **العلامات التجارية** | التحقق من صحة العلامات التجارية والملصقات. | مطابق، غير مطابق. |
- **ملاحظات إضافية (Inspector Notes)**:
  - حقل نصي (مثل: "تم العثور على بعض العبوات متضررة في الزاوية اليمنى السفلية من الحاوية").
- **صور الشحنة (Shipment Photos)** - اختياري:
  - رفع صور للشحنة (تدعم التحميل المتعدد) لتوثيق حالة العبوات.

### 2.2. قرار التفتيش (Inspection Decision)
- **زران رئيسيان**:
  - **زر**: "مطابق (Compliant)" (يُغير حالة الشحنة إلى `UNDER_INSPECTION` ويسمح بالمتابعة إلى خطوة أخذ العينات).
  - **زر**: "غير مطابق (Non-Compliant)" (يُغير حالة الشحنة إلى `REJECTED`، ويطلب سبباً للرفض، ويُرسل إشعاراً إلى المورد والجمارك).

### 2.3. سجل التفتيش (Inspection History)
- عرض جميع عمليات التفتيش السابقة التي أجريت على الشحنة (إن وجدت).

## 3. منطق الأعمال (Business Logic)
- **الإجراء الإلزامي**: لا يمكن تخطي التفتيش الظاهري؛ يجب تسجيله قبل أخذ العينات.
- **إشعار الجم**: في حال رفض الشحنة، يتم إرسال إشعار فوري إلى المورد ونظام الجمارك (عبر التكامل الخارجي) مع ذكر سبب الرفض.

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/food/shipments/{id}/inspection` | تسجيل التفتيش الظاهري (قرار `COMPLIANT`/`NEEDS_ANALYSIS`/`NON_COMPLIANT`). |
| `GET` | `/api/v1/food/shipments/{id}/inspection` | استرجاع بيانات التفتيش. |
