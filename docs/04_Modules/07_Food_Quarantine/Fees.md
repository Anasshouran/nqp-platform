# الرسوم (Fees Management)

## 0. محرّك الحساب المطبق (compute_fee_breakdown)

### 0.1. بنود الرسوم (`FoodFee`) — قابلة للتعديل من Django Admin
| نوع الخدمة (`fee_type`) | الوحدة | القيمة المزروعة (seed_food_fees) |
| :--- | :--- | :--- |
| `INSPECTION` | لكل شحنة/عينة | 50,000 ج.س |
| `SAMPLE` | لكل عينة | 10,000 ج.س |
| `ANALYSIS` | لكل فحص (ميكرو 25,000 / كيميائي 30,000) | 25,000 ج.س (أدنى صنف نشط) |
| `CERTIFICATE` | لكل شهادة | 15,000 ج.س |
| `ADMIN` | لكل شحنة | 5,000 ج.س |

- المحرّك يقرأ **أول بند نشط** حسب السعر الأصغر لـ `fee_type` عبر `_fee_amount`، بقيمة افتراضية
  في الكود: إدارة 5,000، تفتيش 50,000، عينة 10,000، تحليل 20,000، شهادة 15,000.

### 0.2. القواعد (منطق الأعمال)
- **الكمية = عدد العينات المطلوبة `samples_required`** (من سياسة العينات).
- **إعفاء كلي**: `message_type=RELIEF` → بند واحد «إعفاء كلي (رسالة إغاثة)» بمبلغ 0.
- **إعفاء جزئي**: `message_type=EXEMPT` → تُلغى رسوم إصدار الشهادة (`CERTIFICATE`) فقط.
- **تشكيل البنود** (تجاري/عادي):
  1. رسوم إدارية (`ADMIN`).
  2. إن كانت هناك عينات: رسوم تفتيش لكل عينة + رسوم أخذ العينات + رسوم التحليل المخبري
     (كلها `× samples_required`). عدا ذلك: رسوم تفتيش واحدة فقط.
  3. رسوم إصدار الشهادة (ما لم تكن `EXEMPT`).
- **الإجمالي** = مجموع البنود (Decimal).

### 0.3. الصرف والفاتورة والإيصال
1. `GET /shipments/{id}/fee-preview` يعيد `{exempt, lines[], total, samples}` لحظياً (ويشغّل
   `apply_sampling` أولاً).
2. `POST /shipments/{id}/invoice` ينشئ `FoodInvoice`؛ إن لم تُرسل `items` في الطلب تُعاد تعبئة
   فاتورة تلقائياً من `compute_fee_breakdown`.
3. `POST /shipments/{id}/pay` يسجّل الدفع، يعيّن `fees_paid=true`، وينشئ إيصالاً فريداً
   `RCPT-<hex>` عبر `_unique_receipt()`.

### 0.4. تقرير المحاسب (`GET /shipments/accounting/?period=day|week|month`)
يُرجع: `paid_count`, `pending_count`, `total_collected`, `receipts[]` (رقم الإيصال/الفاتورة/المبلغ/
الوقت/المحصّل/رقم البيان), `payments_by_date[]` (تاريخ/إجمالي/عدد), `by_status`.

> **ملاحظة مرجعية**: التعريفة الرسمية الشرائحية حسب الكمية (الوارد/الصادر) في
> `docs/Data/رسوم-الصادر-وارد.md` ورسوم التحاليل لكل فحص في `docs/Data/رسوم-المعمل.md`
> **غير مطبّقة بعد** — المحرك الحالي بالبنود أعلاه (انظر قسم «حالة التنفيذ» في الملفين).

## 1. الهدف
تمكين إدارة الحجر الغذائي من حساب وتحصيل الرسوم المستحقة على عمليات التفتيش، أخذ العينات، التحليل المخبري، وإصدار الشهادات، مع توفير تقارير مالية شفافة للتسويات مع الجمارك أو الموردين.

## 2. مكونات الصفحة

### 2.1. هيكل الرسوم (Fee Structure) - لإدارة الإعدادات
| نوع الخدمة | الوحدة | الرسوم (بالعملة المحلية) |
| :--- | :--- | :--- |
| **تفتيش شحنة** | لكل شحنة | 50,000 ج.س |
| **أخذ عينة** | لكل عينة | 10,000 ج.س |
| **تحليل ميكروبيولوجي** | لكل فحص | 25,000 ج.س |
| **تحليل كيميائي** | لكل فحص | 30,000 ج.س |
| **إصدار شهادة إفراج** | لكل شهادة | 15,000 ج.س |
| **رسوم إدارية** | لكل شحنة | 5,000 ج.س |
- **واجهة مسؤول**: يمكن تعديل هذه الرسوم من قبل المدير المالي (عبر Django Admin أو واجهة مخصصة).

### 2.2. حساب الرسوم المستحقة (Fee Calculation) - يتم تلقائياً
- عند إتمام عملية الإفراج، يقوم النظام بحساب إجمالي الرسوم المستحقة على الشحنة بناءً على:
  - عدد العينات المأخوذة.
  - عدد الفحوصات المخبرية المطلوبة.
  - رسوم التفتيش والإصدار.
- **عرض تفاصيل الفاتورة**:
  - جدول يوضح كل بند من البنود مع التكلفة.
  - الإجمالي النهائي.

### 2.3. إدارة الفواتير (Invoice Management)
- **قائمة الفواتير**:
  - الأعمدة: (رقم الفاتورة، رقم الشحنة، المورد، تاريخ الإصدار، المبلغ الإجمالي، حالة الدفع (معلقة، مدفوعة)).
- **زر**: "عرض الفاتورة" (لطباعة الفاتورة أو تحميلها بصيغة PDF).
- **زر**: "تسجيل الدفع" (لتحديث حالة الفاتورة إلى "مدفوعة" مع إدخال مرجع الدفع).

### 2.4. التقارير المالية (Financial Reports)
- **تقارير يومية/شهرية/سنوية**:
  - إجمالي الإيرادات من الرسوم.
  - توزيع الإيرادات حسب نوع الخدمة.
  - الفواتير المعلقة (المتأخرة).
- **زر**: "تصدير تقرير مالي بصيغة Excel".

## 3. منطق الأعمال (Business Logic)
- **الدفع الإلزامي**: لا يمكن إصدار شهادة الإفراج أو القرار النهائي إلا بعد تسجيل
  الدفع (الفاتورة مدفوعة و `fees_paid=true`).
- **مسؤولو الرسوم**: الكاتب/المحاسب يُصدر الفاتورة، والمحاسب يُحصّل الدفع ويُصدر الإيصال.
- **التكامل مع الجمارك**: (مستقبلي) يمكن ربط الفواتير مع نظام الجمارك لتسوية الرسوم قبل الإفراج النهائي.

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/food/shipments/{id}/invoice` | إصدار فاتورة الرسوم (المحاسب). |
| `POST` | `/api/v1/food/shipments/{id}/pay` | تسجيل الدفع وإصدار الإيصال (المحاسب). |
| `GET` | `/api/v1/food/shipments/` | قائمة الشحنات (تعرض حالة الرسوم). |
