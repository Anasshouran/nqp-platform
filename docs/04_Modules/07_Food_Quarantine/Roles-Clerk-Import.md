# 👤 الكاتب — حالة 📥 وارد (Import)

> الدور: `CLERK` — وحدة رقابة الأغذية (`04_Modules/07_Food_Quarantine`)
> المرجع العام: [`Roles-Clerk.md`](./Roles-Clerk.md)

عند اختيار الكاتب **📥 وارد**، تكون مهمته إنشاء وتجهيز **طلب وارد غذائي** من لحظة التسجيل وحتى إرساله إلى رئيس القسم للمراجعة.

## 1. إنشاء طلب وارد

يختار:

**📥 طلب وارد جديد**

ويقوم النظام تلقائيًا بإنشاء:

```text
رقم الطلب: IMP-2026-000001
نوع الطلب: وارد
المحطة: محطة المستخدم
القطاع: قطاع المستخدم
الكاتب: المستخدم الحالي
التاريخ: تلقائي
الحالة: مسودة
```

---

## 2. البيانات الأساسية للوارد

### 🚢 بيانات الشحنة

| الحقل              | الإدخال |
| ------------------ | ------- |
| الرقم الجمركي      | ✏️      |
| رقم شهادة الاعتماد | ✏️      |
| تاريخ الوصول       | 📅      |
| اسم الباخرة        | 🔽      |
| ميناء الشحن        | 🔽      |
| ميناء الوصول       | تلقائي  |
| رقم البوليصة       | ✏️      |
| اسم المخلص         | 🔽 / ✏️ |
| نوع الرسالة        | 🔽      |

**نوع الرسالة:**

* تجارية
* إغاثة
* إعفاء
* أخرى

---

## 3. بيانات المورد / المستورد

```text
المستورد
├── الاسم
├── الرقم التعريفي
├── العنوان
├── الهاتف
└── البريد الإلكتروني

المورد
├── الاسم
├── الدولة
├── العنوان
└── بيانات الاتصال
```

إذا كان المستورد أو المورد مسجلاً سابقًا، يستخدم الكاتب **البحث والاختيار** بدل إعادة إدخال البيانات.

---

## 4. إضافة الأصناف

يضغط الكاتب:

**+ إضافة صنف**

ويظهر النموذج:

| البيان         | القيمة   |
| -------------- | -------- |
| الصنف          | 🔽       |
| الماركة        | 🔽       |
| بلد المنشأ     | 🔽       |
| الوزن          | ✏️       |
| وحدة الوزن     | kg / ton |
| عدد العبوات    | ✏️       |
| نوع العبوة     | 🔽       |
| رقم التشغيلة   | ✏️       |
| تاريخ الإنتاج  | 📅       |
| تاريخ الانتهاء | 📅       |

### أنواع العبوات

* جوال
* خزانات
* طرد
* براميل
* جركانات
* عنابر
* باخرة
* مخازن
* غربال
* عربات
* برادات

## 5. جدول الأصناف

بعد الإضافة:

```text
┌────┬──────────┬────────┬──────────┬────────┬────────┬─────────┐
│ #  │ الصنف    │ الماركة│ المنشأ   │ العبوة │ العدد  │ الوزن   │
├────┼──────────┼────────┼──────────┼────────┼────────┼─────────┤
│ 1  │ أرز      │ ABC    │ الهند    │ جوال   │ 500    │ 25 طن   │
│ 2  │ سكر      │ XYZ    │ البرازيل │ جوال   │ 300    │ 15 طن   │
└────┴──────────┴────────┴──────────┴────────┴────────┴─────────┘

                    [+ إضافة صنف]
```

الكاتب يستطيع:

**تعديل ✏️ | حذف 🗑️**

ولكن فقط طالما الطلب **مسودة**.

---

## 6. المستندات

قسم:

**📎 المستندات المطلوبة**

مثلاً:

* شهادة المنشأ
* الفاتورة التجارية
* بوليصة الشحن
* الشهادة الصحية
* قائمة التعبئة
* شهادة المطابقة
* مستندات إضافية

ويظهر أمام كل مستند:

```text
✅ مرفوع
❌ غير مرفوع
⚠️ مطلوب
```

ولا يسمح النظام بإرسال الطلب إذا كانت هناك مستندات **إلزامية ناقصة**.

---

## 7. الرسوم

الكاتب لا يدخل الرسوم يدويًا.

النظام يحسبها:

```text
الوزن
   ↓
نوع الطلب = وارد
   ↓
نوع الرسالة
   ↓
جدول الرسوم المعتمد
   ↓
حساب الرسوم
```

ويعرض:

```text
رسوم الكشف             00,000 SDG
رسوم التفريغ           00,000 SDG
دعم الشهادة             00,000 SDG
رسوم المراقبة           00,000 SDG
رسوم أخرى               00,000 SDG
────────────────────────────────
الإجمالي                00,000 SDG
```

---

## 8. سياسة العينات 🧪

بعد إدخال الأصناف، النظام يطبق سياسة العينات **تلقائيًا**:

```text
الصنف
 ↓
درجة الخطورة
 ↓
وزن الشحنة
 ↓
سياسة العينات
 ↓
نسبة أخذ العينة
 ↓
عدد العينات
 ↓
حجم العينة
```

مثلاً:

```text
الصنف: أرز
درجة الخطورة: المجموعة الأولى
نسبة العينة: 100%
عدد العينات: 5
حجم العينة: 500 g
الحالة: إلزامي
```

الكاتب **لا يستطيع تغيير النتيجة** إلا إذا كانت لديه صلاحية خاصة.

---

## 9. التحقق قبل الإرسال

زر:

### **🔍 مراجعة الطلب**

النظام يفحص:

* البيانات الأساسية ✅
* المستورد ✅
* المورد ✅
* الأصناف ✅
* الوزن ✅
* المستندات الإلزامية ✅
* الرسوم ✅
* سياسة العينات ✅

ثم:

```text
✅ الطلب مكتمل وجاهز للإرسال
```

أو:

```text
⚠️ يوجد 3 أخطاء يجب تصحيحها

1. شهادة المنشأ غير مرفوعة
2. بلد المنشأ للصنف رقم 2 غير محدد
3. الوزن للصنف رقم 3 غير مدخل
```

---

## 10. إرسال الطلب

عند الضغط:

**📤 إرسال للمراجعة**

يتغير:

```text
DRAFT
  ↓
SUBMITTED
```

ويصبح الطلب **للقراءة فقط بالنسبة للكاتب**.

ينتقل إلى:

**رئيس قسم رقابة الأغذية**

للمراجعة والتوجيه.

---

## 11. إذا أعاد رئيس القسم الطلب

```text
UNDER_REVIEW
      ↓
   RETURNED
      ↓
     الكاتب
```

ويظهر للكاتب:

```text
⚠️ طلب مرتجع

السبب:
يرجى تعديل رقم البوليصة وإرفاق
الشهادة الصحية.
```

فيستطيع الكاتب التعديل ثم:

```text
SAVE
 ↓
RESUBMIT
```

---

## 🎯 الخلاصة

دورة **الوارد عند الكاتب** تكون:

```text
📥 إنشاء طلب وارد
        ↓
🚢 بيانات الشحنة
        ↓
👥 المستورد / المورد
        ↓
📦 إضافة الأصناف
        ↓
📎 المستندات
        ↓
💰 حساب الرسوم تلقائيًا
        ↓
🧪 تطبيق سياسة العينات تلقائيًا
        ↓
🔍 التحقق
        ↓
📤 إرسال
        ↓
👨‍💼 رئيس القسم
```

وهذا يجعل الكاتب **بوابة إدخال البيانات فقط**، بينما القرارات الرقابية والحسابات الحساسة يتم التحكم فيها من النظام والأدوار الأعلى.
