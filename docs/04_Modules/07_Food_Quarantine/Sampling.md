# أخذ العينات (Sampling)

## 0. السياسة الآلية المطبقة (`SamplingPolicy` + `compute_sampling`)

### 0.1. النموذج `SamplingPolicy`
| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `scope` | انتخاب | `IMPORT` / `EXPORT` / `BOTH`. |
| `benchmark` | انتخاب | `WEIGHT` (كغ) أو `PACKAGES` (عدد العبوات) — للسياسات الاحتياطية. |
| `threshold` | رقم | العتبة (كغ أو عدد عبوات) لمسار الاحتياطي العام. |
| `samples_per_unit` | عدد | نسبة للاحتياطي العام. |
| `max_samples` | عدد | سقف أقصى لعدد العينات. |
| `product_key` | نص | اسم الصنف الرسمي (لمطابقة أصناف الشحنة). |
| `package_size` | نص | حجم العبوة (جوال / عبوات صغيرة/كبيرة…). |
| `risk_group` | انتخاب | `R1` (100%) / `R2` (75%) / `R3` (25%). |
| `rate_pct` | عدد | نسبة سحب الرسائل حسب المجموعة. |
| `quantity` / `quantity_num` | نص / عدد | كمية (عدد) العينة لكل صنف. |
| `sampling_conditions` | نص | شروط السحب الخاصة بالصنف. |
| `default_reason` | انتخاب | `ROUTINE` / `SUSPECTED` / `FIRST_ENTRY`. |
| `is_active` | منطقي | التفعيل. |
| `name_ar` / `order` | نص / ترتيب | الاسم وعامل الترتيب. |

### 0.2. الحساب (`compute_sampling` / `apply_sampling`)
- **المسار الصنفي (مفعل أولاً):** لكل صنف في الشحنة تُطابِق `_match_product_policy` اسم
  المنتج مع `product_key` (تطبيع ثم تطابق جزئي `key in name or name in key`)؛ عند تعدّد
  المطابقات (نفس الصنف بعدة عبوات) يُختار **الأكبر كمية** تحفظاً. إن طابَق أي صنف:
  - `_risk_hit`: **R1 ⇒ سحب كل الرسائل**؛ R2/R3 ⇒ اختيار حاسم ثابت عبر
    `hash(shipment_id, policy.id) < rate_pct` (متكرر النتيجة)، ويُفرض السحب عند
    `SUSPECTED`/`FIRST_ENTRY`.
  - عدد العينات = `quantity_num` (أو `samples_per_unit`)، والنتيجة
    `{required, reason, basis:'RISK_GROUP', policy, rate_pct}`.
- **المسار الاحتياطي (لا صنف مطابق):** أول سياسة بلا `product_key` مناسبة لنوع الشحنة
  مرتبة `order, threshold`؛ `required = min(ceil((value/threshold) × samples_per_unit), max_samples)`.
- يُحفظ `samples_required` في الشحنة عند الإنشاء و`submit` و`fee-preview`.

### 0.3. السياسات المزروعة (`manage.py seed_sampling`)
- ✅ **146 صنفاً رسمياً** من `docs/Data/تطبيق-سياسة-العينات.md`
  (بيانات في `apps/food_quarantine/data/official_sampling_policy.json`):
  R1: 54 / R2: 69 / R3: 22 + سيانتان احتياطيتان (وارد عينة لكل 500 كغ حد 5؛
  صادر عينة لكل 100 عبوة حد 3). الأمر تحديثي (`update_or_create` بمفتاح
  `product_key+package_size`) ويحذف سياسات البذر القديمة بلا صنف.

> **مُلاحظة**: عند إدخال صنف غير مطابق حرفياً (مثل «سكر أبيض» مقابل الرسمي «السكر»)
> يُستخدم الاحتياطي العام — يُنصح بإدخال الاسم كما ورد في الجدول الرسمي.

## 1. الهدف
تمكين مفتش الحجر الغذائي من أخذ عينات عشوائية من الشحنة الغذائية (بعد اجتيازها التفتيش الظاهري)، وتسجيلها في النظام مع ربطها بباركود فريد، وإرسالها إلى المختبر لتحليلها مخبرياً (ميكروبيولوجي، كيميائي، فيزيائي).

## 2. مكونات الصفحة

### 2.1. نموذج تسجيل عينة جديدة (New Sample Registration Form)
- **بيانات الشحنة** (للرجوع السريع):
  - (رقم البيان، المورد، قائمة المنتجات).
- **المنتج المأخوذ منه العينة (Product)**:
  - قائمة منسدلة من منتجات الشحنة.
- **نوع العينة (Sample Type)**:
  - قائمة منسدلة: (ميكروبيولوجي، كيميائي، فيزيائي، حسي).
- **الفحص المطلوب (Test Requested)**:
  - قائمة منسدلة (يتم جلبها من هيئة المواصفات أو إدخالها يدوياً):
    - (مثال: فحص البكتيريا القولونية، فحص السالمونيلا، فحص المبيدات، فحص الرطوبة، فحص المعادن الثقيلة).
- **عدد العينات (Number of Samples)**:
  - حقل رقمي (عدد العينات المأخوذة من نفس المنتج).
- **مكان أخذ العينة (Sampling Location)**:
  - (مثل: "الطبقة العلوية من الحاوية، الجانب الأيمن").
- **ملاحظات إضافية (Notes)**:
  - حقل نصي (مثل: "تم أخذ العينات من دفعات مختلفة للتأكد من التجانس").

### 2.2. توليد الباركود (Barcode Generation)
- بعد حفظ العينة، يقوم النظام بتوليد باركود فريد لكل عينة (أو مجموعة عينات).
- **زر**: "طباعة ملصقات العينات" (ملصقات تحتوي على (اسم المنتج، نوع العينة، الباركود، التاريخ) لوضعها على العينات الفعلية).

### 2.3. قائمة العينات المأخوذة (Samples List)
- عرض جدول بجميع العينات المأخوذة من الشحنة:
  - الأعمدة: (الباركود، المنتج، نوع العينة، الفحص المطلوب، الحالة (بانتظار الإرسال، أرسلت للمختبر، النتيجة قيد التحليل، مكتمل)).
- **زر**: "إرسال العينات إلى المختبر" (لتغيير حالة العينات إلى `SENT_TO_LAB` وإشعار بوابة المختبرات (6) بوجود عينات جديدة بانتظار التسجيل).

## 3. منطق الأعمال (Business Logic)
- **العينات الإجبارية**: يتم تحديد عدد العينات المطلوبة بناءً على نوع المنتج وحجم الشحنة (وفقاً لبروتوكول هيئة المواصفات).
- **ربط العينة بالمختبر**: يتم إرسال بيانات العينة (نوع الفحص، المنتج، الشحنة) تلقائياً إلى بوابة المختبرات (6) لتسجيلها هناك.
- **حالة العينة المبدئية**: `PENDING` (بانتظار الإرسال للمختبر).

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/food/shipments/{id}/samples` | تسجيل عينة جديدة (يقبل `sampling_reason`: `ROUTINE`/`SUSPECTED`/`FIRST_ENTRY`). |
| `GET` | `/api/v1/food/shipments/{id}/samples` | قائمة العينات للشحنة. |
| `PATCH` | `/api/v1/food/samples/{id}/send-to-lab` | تحديث حالة العينة إلى `SENT_TO_LAB`. |
| `GET/POST` | `/api/v1/food/sampling-policies/` | إدارة سياسات أخذ العينات (نموذج `SamplingPolicy`). |
> هذه الوثيقة تحتوي جدول حالة تنفيذ مدمج أسفلها (سياسات `SamplingPolicy` مطبَّقة بالكامل: نطاق/معيار/عتبة/حد أقصى، وتُطبق آليًا عند إنشاء الشحنة، مع SLA 48 ساعة على العينات في لوحات القطاع).
