# إدارة الشحنات (Shipment Management)

## 0. التنفيذ الحالي (تم البناء)
نموذج **`FoodShipment`** + **`FoodOrderItem`** مع دورة «الكاتب → المحاسب → مدير القسم → المفتش».

### 0.1. حقول التسجيل الفعلية (بالإضافة إلى الحقول القديمة)
| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `customs_number` | نص | رقم البيان الجمركي. |
| `certificate_no` | نص | رقم الشهادة (إن وُجدت). |
| `vessel_name` | نص | اسم الوسيلة الناقلة. |
| `clearing_agent` | نص | وكيل التخليص. |
| `exporter_name` | نص | اسم المُصدِّر. |
| `message_type` | انتخاب | `COMMERCIAL` / `RELIEF` (إغاثة) / `EXEMPT` (إعفاء) — يتحكم في الإعفاء. |
| `loading_port` | نص | ميناء التحميل. |
| `bill_of_lading` | نص | بوليصة الشحن. |
| `total_weight_kg` | رقم | يُحسب تلقائياً = مجموع `items.weight_kg`. |
| `samples_required` | عدد | يُحسب تلقائياً بسياسة العينات. |
| `inspection_required` | منطقي | مطلوب تفتيش. |
| `submitted_at` | وقت | لحظة `submit`. |
| `items` (علاقة) | `FoodOrderItem[]` | الأصناف: `product_name`, `brand`, `origin`, `weight_kg`, `package_count`, `package_type`. |

### 0.2. دورة الحياة عند الكاتب/مدير القسم
1. **الكاتب** ينشئ الشحنة (`POST /shipments/` مع `items`) → الحالة `RECEIVED`،
   و`total_weight_kg`/`samples_required`/`fee_preview` تُحسب فوراً.
2. **الكاتب** يرسل الطلب (`POST /shipments/{id}/submit`) → `FEES_DUE` + `submitted_at`.
3. **مدير القسم** يستعرض ويراجع (`POST /shipments/{id}/review`):
   `APPROVE` → `AWAITING_INSPECTION`، أو `RETURN` → إرجاع الشحنة لحالة `RECEIVED`.

### 0.3. دوال الحساب الآلي
- وزن الأصناف: `FoodOrderItem.weight_kg` تُجمع في `total_weight_kg` (`_replace_items`).
- العينات: `apply_sampling(shipment)` — سياسة أولى نشطة (انظر `Sampling.md`).

## 1. الهدف
تمكين مفتش الحجر الغذائي من تسجيل وإدارة جميع الشحنات الغذائية الواردة إلى المنفذ (والصادرة منه)، مع ربطها ببيانات المورد، المنتجات، وتاريخ الوصول، وتتبع حالتها طوال دورة حياتها.

## 2. مكونات الصفحة

### 2.1. قائمة الشحنات (Shipments List)
- عرض جدول بجميع الشحنات المسجلة مع إمكانية التصفية حسب:
  - **الحالة**: (الكل، وارد، تحت التفتيش، بانتظار النتائج، مفرج، مرفوض).
  - **الفترة الزمنية**: (من تاريخ إلى تاريخ).
  - **نوع الشحنة**: (وارد، صادر).
- **الأعمدة**:
  - رقم البيان (Manifest Number).
  - المورد (Supplier Name).
  - دولة المنشأ (Origin Country).
  - تاريخ الوصول.
  - الحالة (مع تمييز بالألوان).
  - **زر**: "عرض التفاصيل" (لفتح صفحة تفاصيل الشحنة).
  - **زر**: "بدء التفتيش" (إذا كانت الحالة `RECEIVED`).

### 2.2. نموذج تسجيل شحنة جديدة (New Shipment Registration Form)
- **نوع الشحنة (Shipment Type)**:
  - (وارد `IMPORT`، صادر `EXPORT`).
- **رقم البيان (Manifest Number)**:
  - حقل نصي (إلزامي، يُستخدم للتكامل مع الجمارك).
- **المورد (Supplier Name)**:
  - حقل نصي (إلزامي).
- **دولة المنشأ (Origin Country)**:
  - قائمة منسدلة من `countries`.
- **قائمة المنتجات (Product List)**:
  - إضافة منتجات بشكل ديناميكي (صفوف قابلة للإضافة/الحذف):
    - اسم المنتج (نص).
    - الكمية (رقم).
    - الوحدة (قائمة منسدلة: كجم، طن، لتر، عبوة، إلخ).
- **تاريخ الوصول (Arrival Date)**:
  - منتقي تاريخ (افتراضي: اليوم الحالي).
- **معلومات الاتصال بالمورد (Supplier Contact)** - اختياري:
  - (الهاتف، البريد الإلكتروني، العنوان).
- **مستندات إضافية (Additional Documents)** - اختياري:
  - رفع ملفات (فواتير، شهادات منشأ، شهادات صحية من بلد المنشأ).

### 2.3. صفحة تفاصيل الشحنة (Shipment Detail)
- **معلومات الشحنة الأساسية**:
  - (رقم البيان، المورد، دولة المنشأ، تاريخ الوصول، النوع، الحالة).
- **قائمة المنتجات**:
  - جدول يوضح (اسم المنتج، الكمية، الوحدة).
- **سجل التغييرات (Activity Log)**:
  - عرض جدول زمني (Timeline) لجميع الإجراءات المتخذة على الشحنة:
    - (مثل: "2024-07-25 10:00 - تم تسجيل الشحنة (المفتش: أحمد)").
    - (مثل: "2024-07-25 10:30 - بدء التفتيش الظاهري (المفتش: أحمد)").
    - (مثل: "2024-07-25 11:00 - تم أخذ عينات (المفتش: سارة)").
    - (مثل: "2024-07-25 14:00 - صدرت شهادة الإفراج رقم FQ-2024-001").

### 2.4. تحديث حالة الشحنة (Update Shipment Status)
- **زر**: "تحديث الحالة" (يفتح نافذة منبثقة لتغيير الحالة):
  - (مثل: `UNDER_INSPECTION`، `AWAITING_LAB_RESULTS`، `RELEASED`، `REJECTED`).
- **سبب التغيير**: حقل نصي إلزامي (مثل: "بانتظار نتائج المختبر"، "تم إصدار شهادة الإفراج").

## 3. منطق الأعمال (Business Logic)
- **منع التكرار**: لا يمكن تسجيل شحنة بنفس رقم البيان (Manifest Number) في نفس المنفذ.
- **التحقق من صحة البيانات**: التأكد من أن دولة المنشأ مختلفة عن دولة الوصول (في حالة الصادر).
- **حالة الشحنة المبدئية**: `RECEIVED` (وارد).
