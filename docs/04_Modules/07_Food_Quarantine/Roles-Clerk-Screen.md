### مصدر البيانات — `clerk-stats` (حقيقي 100%)
`GET /api/v1/food/shipments/clerk-stats/` يعيد `stats` مُقيَّدة بمُسجِّل
المعاملة (`recorded_by=request.user`) + `recent` (آخر 10 معاملات):

| المفتاح | التعريف |
| :--- | :--- |
| `drafts` | `status=DRAFT` |
| `submitted` | `(RECEIVED أو FEES_DUE) ولم تُسدد رسومها` — لدى المحاسب |
| `under_review` | `FEES_DUE` بعد سداد الرسوم — بانتظار مراجعة مدير القسم |
| `inspection` | `AWAITING_INSPECTION + UNDER_INSPECTION` |
| `sampling` / `lab_testing` | `AWAITING_LAB_RESULTS` |
| `final_review` | `AWAITING_DECISION` |
| `rejected` | القرارات النهائية `REJECTED/DESTROY` |
| `completed_today` | حُسم قرارها اليوم |
| حقول التوافق | `awaiting_fees`, `in_progress`, `total` |

## 🔄 حالات الشحنة الحقيقية وخريطة الألوان

| الحالة | التسمية | اللون | تصنيف العرض |
| :--- | :--- | :--- | :--- |
| `DRAFT` | مسودة | رمادي | تبويب «المسودات» — تعديل/حذف/إرسال |
| `RECEIVED` | مستلم | أزرق | تبويب «بانتظار الرسوم» (إن لم تُسدد) |
| `FEES_DUE` | بانتظار الرسوم | برتقالي | قبل السداد → «بانتظار الرسوم»؛ بعده → «بانتظار المراجعة» |
| `AWAITING_INSPECTION` | بانتظار التفتيش | أزرق | تبويب «قيد الفحص» |
| `UNDER_INSPECTION` | قيد التفتيش | أزرق | تبويب «قيد الفحص» |
| `AWAITING_LAB_RESULTS` | بانتظار نتائج المعمل | أزرق فاتح | تبويب «قيد الفحص» |
| `AWAITING_DECISION` | بانتظار القرار | برتقالي | — |
| `RELEASED` / `CONDITIONAL_RELEASE` / `RE_EXPORT` | نهائية | أخضر | تبويب «المُفرج عنها» |
| `REJECTED` / `DESTROYED` | نهائية | أحمر | تبويب «المرفوضة» |
| `HOLD` | محجوز | برتقالي | — |

### قاعدة الصلاحية على مستوى الصف
```text
DRAFT   → ✏️ تعديل + 🗑️ حذف + 📤 إرسال (submit)
غير ذلك → 👁️ عرض تفصيلي فقط (Dialog)
```

## 📋 العرض التفصيلي للطلب (`ShipmentDetailView`)

Dialog يظهر عند فتح أي طلب غير مسودة (وأيضًا متاح للمسودة)، ويعرض:

1. **شريط الحالة**: Chip الحالة + وقت الإرسال + شارة «✅ الرسوم مسددة» إن `fees_paid`
2. **البيانات الأساسية**: المنفذ، الطرف المقابل، المنشأ، الوصول، الباخرة، البوليصة
3. **الأصناف**: لكل صنف اسم/ماركة/منشأ/عبوة/عدد/وزن + شارة إجمالي العينات المطلوبة على مستوى الشحنة (`samples_required`)
4. **المستندات**: المرفقات الفعلية + تنبيه الإلزامي الناقص (فاتورة/شهادة منشأ)
5. **الرسوم**: من `fee_preview` — بنود + إجمالي، أو شارة «معفاة» حسب نوع الرسالة

## ➕ Wizard إنشاء الطلب (6 خطوات)

`نوع الطلب → البيانات → الأصناف → المستندات → الرسوم والعينات → المراجعة`

| الخطوة | المحتوى | التحقق |
| :--- | :--- | :--- |
| 1 | وارد/صارد (بطاقتا اختيار) | — |
| 2 | بيان/جمركي/اعتماد/وصول/باخرة/طرف/منشأ/مخلص/**منفذ**/بوليصة | إلزامي: منفذ، الطرف، المنشأ، التاريخ |
| 3 | أصناف باقتراحات ذكية + سياسة عينات لحظية (`resolveSamplingPolicy`) | إلزامي: الاسم والعدد |
| 4 | مستندات (واجهة تمهيدية — لا رفع فعلي بعد) | — |
| 5 | رسوم تقديرية + سياسة العينات لكل صنف | تلقائي 🤖 |
| 6 | مراجعة ثم تأكيد | Dialog تأكيد |

عند الإرسال: `POST shipments/ {…, as_draft:true}` ثم `submit` → FEES_DUE.
(بدون `as_draft`: الإنشاء يسجل مباشرة ويطبق سياسة العينات — مسار «تسجيل فوري»).

## 🔐 الصلاحيات الدقيقة (الكاتب مقابل بقية النظام)

```text
كاتب
├── إنشاء معاملة (مسودة أو تسجيل فوري)   ✅
├── تعديل/حذف                             ✅ DRAFT فقط
├── submit (→ FEES_DUE)                   ✅
├── refer (استقبال إحالة معبر بري)        ✅
├── invoice/pay/decide/assign-inspector   ❌ (محاسب/مدير قسم)
└── inspection/samples                    ❌ (مفتش)
```
