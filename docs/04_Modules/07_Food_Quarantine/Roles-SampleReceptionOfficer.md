# 👤 موظف استلام العينات — Sample Reception Officer

> الدور: `LAB_RECEPTIONIST` — نظام معلومات المختبر (FCLIS) (`04_Modules/07_Food_Quarantine`)

مسؤول عن **أول نقطة دخول للعينة** في المختبر: إنشاء السجل، فحص الحالة، واتخاذ قرار القبول/الرفض قبل دخول العينة إلى دورة التحليل.

## 🎯 لوحة مكتب الاستلام (Hub)

يفتح مباشرة على **مكتب استلام العينات** (`/app/reception`) — واجهة استقبال سريعة مصممة خصيصاً لدور الاستلام، وتضم:

* 🏠 **الرئيسية**: مؤشرات KPI (عينات اليوم، قيد الاستلام بانتظار القرار، مقبولة، مرفوضة، عاجلة/بانتظار المراجعة، عينات مرجعية، متوسط زمن القرار) + ملخص سير العمل والتنبيهات.
* 📥 **استلام**: معالج الاستلام بثلاث خطوات + جدول أحدث العينات.
* 🧪 **العينات**: جدول كامل ببيانات الوصول (المنفذ، العلامة، الكمية، الحرارة، القرار، الحالة، الأولوية، القسم).
* 📦 **المرجعية**: العينات المرجعية المرتبطة بالعينة الأصلية + تسجيل عينة مرجعية جديدة.
* 🔎 **التتبع**: سلسلة الحيازة **قراءة فقط** (Timeline).
* 📊 **التقارير**: ملخص إحصائي لعمليات الاستلام.
* 🔔 **التنبيهات**: العينات العاجلة/عالية الأولوية بانتظار قرار الاستلام.

## ✅ معالج الاستلام السريع — 3 خطوات

```text
① الطلب ────────────► ② فحص العينة ────────────► ③ القبول + طباعة Barcode
```

| الخطوة | الحقول |
| ------ | ------ |
| **① الطلب** | مصدر العينة (إلزامي)، نوع/اسم العينة (إلزامي)، رقم طلب التحليل، الجهة الطالبة، التصنيف، المنفذ/المحطة |
| **② فحص العينة** | اسم المفتش، العلامة التجارية، بلد المنشأ، رقم الدفعة، تاريخ الإنتاج/الانتهاء، الكمية+الوحدة، عدد الوحدات، نوع التغليف، حالة التغليف، درجة الحرارة |
| **③ القبول + باركود** | نموذج فحص العينة (Checklist)، قرار الاستلام، ملاحظات، ثم طباعة الباركود مباشرة |

القواعد الصارمة داخل المعالج:
* **لا يُقبل** أي طلب بدون استكمال **جميع** بنود نموذج الفحص قبل القبول.
* **لا يُرفض** أي طلب بدون اختيار **سبب الرفض** من القائمة + ملاحظات (الواجهة، والنظام خلفياً يرفض الطلب بخطأ 400 عند غياب السبب).

أزرار الانتقال: **التالي ←** بين الخطوات، **السابق** للعودة، وفي الخطوة الثالثة **قبول وتسجيل العينة** / **تسجيل الرفض**.

## 🔒 قاعدة أساسية

> **موظف الاستلام هو حارس البوابة الأولى للعينة — يُدخل بيانات الاستلام ويقرر القبول/الرفض، ولا يتجاوز إلى دائرة التحليل أو الاعتماد.**

النظام يحجب عنه تقنيًا (`_block_non_analyst_role`):
* أزرار إدخال/تقييم النتيجة (`enter-result` / `save-result` / `start`).
* أزرار المراجعة والاعتماد والتصحيح وإعادة التحليل ومراجعة QC (`review` / `approve` / `revise` / `return-result` / `mark-qc`).
* صلاحيات إضافة/تعديل نتائج المختبر والأصناف على مستوى RBAC.

## 🔄 Workflow موظف الاستلام

```text
  وصول العينة إلى المختبر
            ↓
 ① الطلب: المصدر + النوع + رقم الطلب + المنفذ
            ↓
 ② فحص العينة: البيانات الواردة كما وصلت
            ↓
 ③ نموذج الفحص (Checklist اكتمل؟)
            ↓
  ┌── قبول/قبول مشروط ──► طباعة Barcode/QR
  │
  └── رفض ──► سبب رفض إلزامي + ملاحظات
            ↓
   سلسلة الحيازة (قراءة فقط) ← تسليم للدورة
   (عينة مرجعية مرتبطة بالعينة الأصلية عند الحاجة)
```

## 🖥️ شاشات مكتب الاستلام

* **معالج الاستلام**: نموذج ثلاثي الخطوات (انظر الجدول أعلاه) — يحول البيانات مباشرة إلى `createLabSample` ثم `accept/conditional-accept/reject`.
* **العينات**: جدول مفصّل ببيانات الوصول + أزرار (فتح التفاصيل، طباعة الباركود).
* **تسجيل عينة مرجعية**: نافذة ربط العينة المرجعية بالعينة الأصلية (رقم العينة الأصلية، الكمية، درجة حرارة التخزين، سبب ومدة الاحتفاظ، الختم).
* **التنبيهات**: قائمة العينات العاجلة بانتظار القرار مع زر اتخاذ القرار.

## 🖨️ طباعة Barcode / QR

تُطبع ملصقة العينة (باركود CODE128 أو QR) من بيانات السجل مباشرةً بعد القبول، وتشمل: رقم العينة، الباركود، نوع العينة، تاريخ الاستلام — لتوضع على العينة ضمن دورة الحيازة.
