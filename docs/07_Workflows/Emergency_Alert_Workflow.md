# WF-16: مسار الإنذار من الكشف إلى الإغلاق (Alert Lifecycle)

## 1. الهدف
توثيق دورة حياة الإنذار (Alert) بدءاً من اكتشاف الحالة (بواسطة بوابة الفحص أو العيادات أو المختبرات)، مروراً بتصنيفها وإرسالها إلى EOC، وانتهاءً بإغلاقها بعد الاستجابة.

## 2. الممثلون (Actors)
- **مصدر الإنذار**: (بوابة 4، 5، 6).
- **نظام NQP**: يستقبل الحدث ويصنفه.
- **غرفة الطوارئ (EOC)**: يتلقى الإنذار ويتخذ الإجراءات.

## 3. تدفق العملية

```mermaid
flowchart TD
    Start([بداية: اكتشاف حالة]) --> Step1[1. أي بوابة تكتشف حدثًا:<br/>- فحص (أحمر) في (4)<br/>- حالة حرجة في (5)<br/>- نتيجة إيجابية (PHEIC) في (6)]
    Step1 --> Step2[2. النظام يُصنف الحدث تلقائياً:<br/>- أحمر (عاجل)<br/>- أصفر (مراقبة)]
    Step2 --> Decision1{هل التصنيف أحمر؟}
    Decision1 -- لا --> End1([النهاية: تسجيل فقط])
    
    Decision1 -- نعم --> Step3[3. توليد إنذار في جدول emergency_alerts<br/>الحالة: NEW]
    Step3 --> Step4[4. إرسال WebSocket فوري إلى غرفة الطوارئ (9)]
    Step4 --> Step5[5. ظهور الإنذار على لوحة EOC (مع تنبيه صوتي)]
    Step5 --> Step6[6. مسؤول EOC يفتح تفاصيل الإنذار]
    Step6 --> Step7[7. تقييم الحالة واتخاذ الإجراء:<br/>- توجيه فريق RRT<br/>- تفعيل Kill Switch (إن لزم)]
    Step7 --> Step8[8. تحديث حالة الإنذار إلى PROCESSING]
    Step8 --> Step9[9. فريق RRT يتولى الحالة]
    Step9 --> Step10[10. متابعة حتى استقرار الحالة]
    Step10 --> Step11[11. تحديث حالة الإنذار إلى RESOLVED]
    Step11 --> Step12[12. إغلاق الإنذار (تسجيل وقت الإغلاق)]
    Step12 --> End2([النهاية: إغلاق])

4. حالات الإنذار (Alert States)
الحالة	الوصف	الإجراء التلقائي
NEW	تم اكتشاف الإنذار ولم يتم التعامل معه بعد.	إرسال WebSocket، إشعار صوتي، ظهور أعلى القائمة.
PROCESSING	يتم التعامل مع الإنذار (تم توجيه فريق).	إخفاء التنبيه الصوتي، بقاؤه في قائمة المتابعة.
RESOLVED	تم حل المشكلة.	يُنقل إلى أرشيف الإنذارات المغلقة.
5. نقاط النهاية الخلفية (API Endpoints)
الطريقة	المسار	الوصف
GET	/api/v1/eoc/alerts/active	قائمة الإنذارات النشطة.
PATCH	/api/v1/eoc/alerts/{id}/status	تحديث حالة الإنذار.
POST	/api/v1/eoc/alerts/{id}/close	إغلاق الإنذار.
