# WF-10: معالجة قوائم الركاب (Carrier Manifest Processing)

## 1. الهدف
توثيق كيفية استقبال نظام NQP لقوائم الركاب (Passenger Manifest) من شركات الطيران (عبر بوابة الناقل 3 أو API التكامل)، والتحقق من صحتها، ومعالجتها (غير متزامن عبر Celery)، وربطها بالرحلات والمسافرين، وإعداد التقارير اللازمة للمنافذ.

## 2. الممثلون (Actors)
- **ممثل شركة الطيران (Carrier Rep)**: يرفع الملف.
- **نظام NQP (Django Backend)**: يستقبل الملف، يتحقق منه، ويعالجه في الخلفية.
- **موظف الحجر (Port Officer)**: يطلع على القائمة المعالجة في بوابة الفحص (4).

## 3. تدفق العملية

```mermaid

4. منطق معالجة المسافرين (Business Logic)

    تحديد المسافر: يتم البحث باستخدام (رقم الجواز) + (تاريخ الميلاد) لتجنب التكرار.

    المسافر غير موجود: يتم إنشاء ملف مسافر جديد (بحالة PENDING_DOCUMENTS) ويُطلب منه التسجيل عبر بوابة المسافرين.

    المسافر موجود: يتم ربطه بالرحلة مباشرة.

    التكرار: لا يمكن ربط نفس المسافر بنفس الرحلة مرتين (قيود UNIQUE في قاعدة البيانات).

5. نقاط النهاية الخلفية (API Endpoints)
الطريقة	المسار	الوصف
POST	/api/v1/carrier/flights/{id}/manifest/upload	رفع الملف (غير متزامن).
GET	/api/v1/carrier/flights/{id}/manifest/status	الاستعلام عن حالة المعالجة.
GET	/api/v1/carrier/flights/{id}/manifest/report	تحميل تقرير المعالجة.
