# شاشة إدارة الشركة (Company Management)

## 1. الهدف
تمكين ممثل الشركة من عرض وتحديث بيانات شركته (معلومات الاتصال، الشعار)، وإدارة مفاتيح API الخاصة بالتكامل.

## 2. مكونات الشاشة

### 2.1. تبويبات التنقل (Tabs)
- **ملف الشركة** (🏢): المعلومات الأساسية.
- **مفاتيح API** (🔑): إدارة مفاتيح التكامل.

### 2.2. التبويب الأول: ملف الشركة (Company Profile)
- **صورة الشعار**: معاينة للشعار الحالي مع زر "تغيير الشعار" (يرسل رابط الشعار مباشرة).
- **نموذج المعلومات (للقراءة والتعديل)**:
  - اسم الشركة (للقراءة فقط).
  - رمز IATA (للقراءة فقط).
  - البريد الإلكتروني الرسمي (قابل للتعديل).
  - رقم الهاتف (قابل للتعديل).
  - العنوان (قابل للتعديل).
- **زر**: "حفظ التغييرات" (يظهر فقط إذا تم تعديل أي حقل).

### 2.3. التبويب الثاني: مفاتيح API (API Keys)
- **عرض المفتاح الحالي**: (مخفى جزئياً، مثلاً: `nqp_*******`).
- **زر**: "إنشاء مفتاح جديد" (يُبطل المفتاح القديم ويُولد مفتاحاً جديداً مع تنبيه أمني).
- **معلومات الاستخدام**: آخر استخدام وتاريخ إنشاء المفتاح.

## 3. حالات واجهة المستخدم (UI States)
- **حالة نجاح الحفظ**: ظهور رسالة (Toast) خضراء "تم حفظ التغييرات بنجاح".
- **حالة خطأ**: رسالة حمراء مع تفاصيل الخطأ.

## 4. نقاط النهاية الخلفية (API Calls)
| الطريقة | نقطة النهاية | الغرض |
| :--- | :--- | :--- |
| `GET` | `/api/v1/carriers/company/profile/` | جلب بيانات الشركة. |
| `PUT` | `/api/v1/carriers/company/profile/` | تحديث بيانات الشركة (الحقول الأساسية محمية: name, iata_code, icao_code). |
| `POST` | `/api/v1/carriers/company/logo/` | تحديث رابط الشعار (يتطلب `logo_url` في الطلب). |
| `GET` | `/api/v1/carriers/company/api-key/` | استرجاع مفتاح API الحالي (مخفى) مع معلومات آخر استخدام. |
| `POST` | `/api/v1/carriers/company/api-key/regenerate/` | إعادة توليد مفتاح API (يبطل المفتاح القديم). |

> **ملاحظة**: إدارة المستخدمين الداخليين للشركة يتم عبر مسؤول الإدارة الاتحادية (Admin) فقط، وليس من بوابة ممثل الشركة.
