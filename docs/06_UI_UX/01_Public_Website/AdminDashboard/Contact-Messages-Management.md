# إدارة رسائل الاتصال (Contact Messages Management)

## 1. الهدف
تمكين مسؤولي الموقع من قراءة وإدارة جميع الرسائل الواردة من نموذج "اتصل بنا" في الموقع العام، مع إمكانية تصنيفها، الرد عليها، وحذفها بعد المعالجة، لضمان عدم ضياع أي استفسار أو شكوى من المواطنين والمسافرين.

## 2. مكونات الشاشة

### 2.1. قائمة الرسائل (Messages List)
- **عرض جدولي (Table)** يحتوي على الأعمدة التالية:
  - **حالة القراءة**: (📩 غير مقروءة / 📨 مقروءة).
  - **المرسل**: (الاسم الكامل).
  - **البريد الإلكتروني**.
  - **نوع الطلب**: (استفسار، شكوى، اقتراح، دعم فني، بلاغ طارئ).
  - **الموضوع**.
  - **تاريخ الإرسال**.
  - **الإجراءات**: (👁️ عرض التفاصيل، 🗑️ حذف).
- **أدوات التصفية**:
  - قائمة منسدلة لتصفية (نوع الطلب، حالة القراءة).
  - منتقي تاريخ (من - إلى).
- **زر**: "تحديد الكل كمقروء".

### 2.2. صفحة تفاصيل الرسالة (Message Detail) - تظهر في نافذة منبثقة
- **معلومات المرسل**:
  - (الاسم، البريد الإلكتروني، رقم الجوال، نوع الطلب).
- **الموضوع**: (نص).
- **الرسالة**: (نص كامل).
- **حالة المعالجة**: (قائمة منسدلة: جديد، قيد المعالجة، تم الرد، مغلق).
- **ملاحظات الموظف**: (حقل نصي) لتسجيل أي ملاحظات داخلية حول كيفية التعامل مع هذه الرسالة.
- **زر**: "الرد عبر البريد الإلكتروني" (يفتح عميل البريد الإلكتروني الافتراضي لكتابة الرد).

## 3. منطق الأعمال (Business Logic)
- **الإشعار الفوري**: عند استلام رسالة جديدة، يتم إرسال إشعار (بريد إلكتروني + إشعار داخل لوحة التحكم) لفريق الدعم.
- **الرد التلقائي**: (اختياري) إرسال بريد إلكتروني تأكيدي للمرسل فور استلام الرسالة ("شكراً لتواصلك معنا...").
- **التصنيف الذكي**: يمكن إعداد قواعد لتوجيه الرسائل تلقائياً إلى الفريق المختص (مثل: الرسائل التي تحتوي على كلمة "طارئ" تظهر بعلامة حمراء).

## 4. نقاط النهاية الخلفية (API Endpoints)
| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `GET` | `/api/v1/admin/cms/messages/` | قائمة الرسائل (مع التصفية). |
| `GET` | `/api/v1/admin/cms/messages/{id}/` | تفاصيل رسالة. |
| `PATCH` | `/api/v1/admin/cms/messages/{id}/` | تحديث حالة الرسالة (مقروءة، قيد المعالجة). |
| `DELETE` | `/api/v1/admin/cms/messages/{id}/` | حذف رسالة. |
