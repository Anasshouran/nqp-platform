# شاشة إدارة المستخدمين والصلاحيات (Users & RBAC Management)

## 1. الهدف
تمكين مسؤولي النظام (Super Admin و Federal Admin) من إدارة دورة حياة المستخدمين في المنصة (إنشاء، تعديل، تعطيل، حذف) وتعيين الأدوار والصلاحيات (RBAC) لهم بناءً على مبدأ "أقل امتياز (Least Privilege)"، لضمان أمن النظام ومنع الوصول غير المصرح به.

## 2. مكونات الشاشة

### 2.1. تبويبات التنقل (Tabs)
- **المستخدمون** (👥): لإدارة حسابات المستخدمين.
- **الأدوار والصلاحيات** (🔑): لإدارة الأدوار المحددة مسبقاً وصلاحياتها (للمشرفين المتقدمين).

### 2.2. التبويب الأول: المستخدمون (Users)
- **شريط الأدوات**:
  - **زر**: "إضافة مستخدم جديد" (باللون الأزرق).
  - **حقل بحث**: للبحث عن مستخدم بالاسم أو البريد الإلكتروني.
  - **قائمة منسدلة للتصفية**: (الدور: الكل، Super Admin، Federal Admin، Port Officer، إلخ).
  - **قائمة منسدلة للتصفية**: (الحالة: الكل، نشط، غير نشط).
- **جدول المستخدمين**:
  - الأعمدة: (الاسم الكامل، البريد الإلكتروني، الدور (مع تاج ملون)، المنفذ/القطاع المرتبط، تاريخ آخر دخول، الحالة (🟢 نشط / 🔴 غير نشط)).
  - **الإجراءات**: (✏️ تعديل، 🔒 إعادة تعيين كلمة المرور، 🚫 تعطيل/تفعيل، 🗑️ حذف (للمشرفين فقط)).

### 2.3. نموذج إضافة / تعديل مستخدم (User Form) - نافذة منبثقة (Modal)
- **الحقول الإلزامية**:
  - الاسم الكامل (نص).
  - البريد الإلكتروني (بريد إلكتروني، فريد).
  - رقم الجوال (نص، فريد).
  - الدور (قائمة منسدلة).
  - المنفذ المرتبط (قائمة منسدلة - اختياري، يظهر حسب الدور).
  - القطاع المرتبط (قائمة منسدلة - اختياري).
  - كلمة المرور المؤقتة (للإضافة فقط، تُرسل للمستخدم عبر البريد الإلكتروني).
- **الحالة**: (خانة اختيار: نشط).
- **زر**: "حفظ".

### 2.4. التبويب الثاني: الأدوار والصلاحيات (Roles & Permissions)
- **جدول الأدوار**: (اسم الدور، الوصف، عدد المستخدمين).
- **عند النقر على دور**: تظهر قائمة بجميع الصلاحيات المتاحة في النظام (مقسمة حسب التطبيق: `users`, `ports`, `screenings`, `clinic`, `lab`, `food`, `reports`).
- **خانات اختيار (Checkboxes)**: لتفعيل/تعطيل كل صلاحية.
- **زر**: "حفظ التغييرات" (يظهر فقط للمشرفين المتقدمين).

## 3. حالات واجهة المستخدم (UI States)
- **حالة نجاح الإضافة**: رسالة خضراء "تم إضافة المستخدم بنجاح، تم إرسال كلمة المرور إلى البريد الإلكتروني".
- **حالة نجاح التعديل**: رسالة خضراء "تم تحديث بيانات المستخدم بنجاح".
- **حالة تعطيل المستخدم**: نافذة تأكيدية "هل أنت متأكد من تعطيل هذا المستخدم؟".
- **حالة فشل البريد الإلكتروني المكرر**: رسالة خطأ حمراء "هذا البريد الإلكتروني مستخدم بالفعل".

## 4. نقاط النهاية الخلفية (API Calls)
| نقطة النهاية (Endpoint) | الغرض |
| :--- | :--- |
| `GET /api/v1/admin/users/` | قائمة المستخدمين (مع التصفية والبحث). |
| `POST /api/v1/admin/users/` | إنشاء مستخدم جديد. |
| `GET /api/v1/admin/users/{id}/` | تفاصيل مستخدم. |
| `PUT /api/v1/admin/users/{id}/` | تحديث بيانات المستخدم. |
| `PATCH /api/v1/admin/users/{id}/toggle-status/` | تفعيل/تعطيل مستخدم. |
| `POST /api/v1/admin/users/{id}/reset-password/` | إعادة تعيين كلمة المرور. |
| `GET /api/v1/admin/roles/` | قائمة الأدوار (مع صلاحياتها). |
| `PUT /api/v1/admin/roles/{id}/permissions/` | تحديث صلاحيات دور. |
