# سير عمل المحاسب وشاشاته – نظام رقابة الأغذية (Food Safety)

> **الإصدار 2 — محدَّث ليطابق النظام المُنفَّذ فعلياً** (النماذج، نقاط النهاية، الحالات، وتنسيقات الأرقام كما في الكود).
>
> دور المحاسب يستلم المعاملات المُرسلة من الكاتب بحالة `FEES_DUE`، يُصدر الفاتورة من البند المحسوب تلقائياً (`compute_fee_breakdown`)، ويؤكّد التحصيل عبر `pay`، فتتحول المعاملة تلقائياً إلى مرحلة التفتيش (`AWAITING_INSPECTION`). لا يملك المحاسب أي صلاحيات فنية على الشحنة أو المنتجات — عمله مالي فقط.

---

## 1. هوية المستخدم

تظهر في القائمة الجانبية المشتركة (`GenericRoleLayout`) تلقائياً من حساب المستخدم:

- دور النظام: `ACCOUNTANT` (مستخدم تجريبي في بيئة التطوير: `kamal@gmail.com`).

## 3. الحالات المالية (كما هي مُنفَّذة)

| الحالة | أين تعيش | الوصف |
|---|---|---|
| `FEES_DUE` | `FoodShipment.status` | المعاملة بانتظار إصدار الفاتورة والتحصيل (يصلها الكاتب عبر `submit`) |
| `PENDING` | `FoodInvoice.status` | الفاتورة صدرت ولم تُحصَّل |
| `PAID` | `FoodInvoice.status` | تم الدفع — مع رقم إيصال `RCPT-…` |
| `AWAITING_INSPECTION` | `FoodShipment.status` | بعد التحصيل مباشرة: جاهزة لتعيين مفتش |

> ⚠️ لا توجد حالة شحنة اسمها `AWAITING_PAYMENT` أو `PAID` على الشحنة؛ الدفع يُتتبع على مستوى **الفاتورة** وحقل `shipment.fees_paid`.

### تنسيقات الأرقام الفعلية

```text
رقم المعاملة:   IMP-2026-00001 / EXP-2026-00001   (manifest_number)
رقم الفاتورة:   INV-ACFAEC837C                    (INV- + hex10)
رقم الإيصال:    RCPT-ACA9219663                   (RCPT- + hex10، يتولد تلقائياً)
```

## 4. لوحة تحكم المحاسب

**المسار:** `/app/accountant-dashboard` — تبويب «الرئيسية»

- **بطاقات إحصائية** (مصدرها `GET /api/v1/food/shipments/accounting/?period=day|week|month`):
  - بانتظار التحصيل ← `pending_count`
  - مدفوعة اليوم ← `paid_count`
  - إجمالي المحصل ← `total_collected` (SDG)
- **جدول «أحدث المعاملات المالية»**: أول 6 فواتير من `GET /api/v1/food/invoices/` (رقم الفاتورة، المعاملة، الإجمالي، الحالة، زر عرض).
- النقر على بطاقة «بانتظار التحصيل» ينقل لتبويب التحصيل.

---

## 5. قائمة التحصيل

**تبويب «التحصيل» داخل نفس الصفحة** — المصدر: `GET /api/v1/food/shipments/?status=FEES_DUE`

| رقم المعاملة | النوع | المستورد/المصدر | المنفذ | الفاتورة | إجراء |
|---|---|---|---|---|---|
| IMP-2026-00001 | وارد | شركة الأمل | مطار بورتسودان | INV-… | [إصدار فاتورة] ثم [تحصيل] |

- **بدون فاتورة؟** زر «إصدار فاتورة» → `POST /food/shipments/{id}/invoice/` (بنود فارغة = يحسبها النظام من التعرفة). تعرض النافذة بنود `fee_preview` للمراجعة قبل الإصدار.
- **مع فاتورة PENDING؟** زر «تحصيل» يفتح نافذة تأكيد التحصيل.

---

## 6. نافذة تأكيد التحصيل

```
┌────────────────────────────────────────────┐
│  تأكيد عملية التحصيل                       │
├────────────────────────────────────────────┤
│  رقم المعاملة: IMP-2026-00001              │
│  المبلغ المستحق: 190,000 SDG               │
│  طريقة الدفع*: [ نقدي ▼ ]                  │
│  ملاحظات: [...................]            │
│  رقم الإيصال: يتولد تلقائياً (RCPT-…)      │
│                                            │
│  [ تأكيد الدفع ]  [ إلغاء ]                │
└────────────────────────────────────────────┘
```

**طرق الدفع المدعومة** (`FoodInvoice.PaymentMethod`): `CASH` نقدي · `BANK_CARD` شبكة بنكية · `BANK_TRANSFER` تحويل بنكي · `ELECTRONIC` إلكتروني.

**استدعاء API:**

```http
POST /api/v1/food/shipments/{id}/pay/
{ "payment_method": "CASH", "notes": "دفع نقدي" }
```

**ماذا يحدث بعد التأكيد (في الخادم):**

1. `invoice.status = PAID` + توليد `receipt_number` فريد.
2. حفظ `payment_method`, `paid_notes`, `paid_by`, `paid_at`, `payment_reference`.
3. `shipment.fees_paid = True` و `shipment.status = AWAITING_INSPECTION`.
4. كتابة سجل تدقيق `AuditLog` بحدث `confirm_payment` (انظر §10).
5. الواجهة تُظهر toast برقم الإيصال وتحدِّث الجداول.

الدفع المزدوج مرفوض (400: «الفاتورة مدفوعة مسبقاً»)، وطريقة دفع غير معروفة مرفوضة أيضاً.

---

## 7. الفواتير والإيصالات

**تبويبا «الفواتير» و«المدفوعات»:**

- الفواتير: `GET /api/v1/food/invoices/` (عرض فقط) مع بحث `?search=` برقم الفاتورة/الإيصال/المعاملة/المورد، وفلتر `?status=PENDING|PAID`.
- عرض الفاتورة يبين: رقم الفاتورة، المعاملة، بنود الرسوم، الإجمالي، وبعد الدفع: رقم الإيصال، طريقة الدفع، وقت الدفع، اسم المحاصل.
- سجل المدفوعات مصدره `accounting.receipts` (إيصال، فاتورة، معاملة، مبلغ، طريقة الدفع، التاريخ، المحصل).

> الطباعة/PDF و QR وإرسال الإيصال بالبريد: **مستقبلاً** (غير مُنفَّذ).

---

## 8. التقارير المالية

**تبويب «التقارير»** — `GET /api/v1/food/shipments/accounting/?period=day|week|month`

- عدد المدفوعات، المعلقة، الإجمالي المحصل خلال الفترة.
- جدول الحركة اليومية: `payments_by_date[]` ({date, count, total}).

## 9. حدود صلاحيات المحاسب

| العملية | المسموح؟ | ملاحظة تنفيذية |
|---|---|---|
| عرض المعاملات المالية | ✅ | `shipments?status=FEES_DUE`, `invoices` |
| إصدار فاتورة | ✅ | `POST shipments/{id}/invoice/` — البنود من التعرفة |
| تأكيد الدفع/التحصيل | ✅ | `POST shipments/{id}/pay/` |
| إدخال طريقة الدفع والملاحظات | ✅ | حقول `payment_method` / `paid_notes` |
| تعديل الرسوم أو إنشاء قواعد | ❌ | `compute_fee_breakdown()` للقراءة فقط |
| تعيين مفتش / تفتيش / عينات / مختبر / قرار نهائي / شهادات | ❌ | حالات غير مالية خارج نطاق الدور |
| حذف مسودة أو تعديل الشحنة | ❌ | الحذف مقصور على DRAFT للكاتب |

```json
  "action": "UPDATE",
  "object_type": "FoodInvoice",
  "object_label": "تأكيد تحصيل INV-ACFAEC837C — IMP-2026-00001",
  "detail": {
    "event": "confirm_payment",
    "amount": "190000.00",
    "payment_method": "CASH",
    "receipt_number": "RCPT-ACA9219663",
    "manifest": "IMP-2026-00001"
  }
}
```
