## 📱 شاشة تسجيل الدخول - تطبيق الجوال (Mobile Login Screen)

### 1. الهدف
توفير واجهة دخول سريعة وآمنة لمستخدمي تطبيق الجوال (المسافرين، المرضى، وأحياناً الموظفين في الحالات الميدانية). تم تصميم هذه الشاشة لتكون **بسيطة، بديهية، وسهلة الاستخدام**، مع دعم خيارات المصادقة البيومترية (بصمة الإصبع / التعرف على الوجه) لتسريع عملية الدخول للمستخدمين المتكررين.

### 2. تصميم الشاشة (Layout) - Mobile-First

#### 2.1. الهيكل العام (Single Column - ملء الشاشة)
- **خلفية**: لون موحد (أبيض أو أزرق فاتح جداً) مع شعار المنصة في الأعلى.
- **المحتوى**: يتمركز في منتصف الشاشة عمودياً (Centered Vertically).

#### 2.2. مكونات النموذج (Form Components)

1.  **شعار المنصة** (في أعلى النموذج):
    - صورة الشعار (مصغرة) مع اسم "NQP" أو "منصة الحجر الصحي".
    - **حجم مناسب**: 80x80 بكسل للشعار، و 20px للخط.

2.  **عنوان الصفحة**: "مرحباً بعودتك" أو "تسجيل الدخول" (بخط كبير وواضح).

3.  **نص ترحيبي فرعي**: "سجل دخولك لمتابعة حالتك الصحية" (اختياري، خط صغير).

4.  **حقل البريد الإلكتروني أو رقم الجوال**:
    - أيقونة (📧 أو 📱) في بداية الحقل (لون رمادي).
    - Placeholder: "البريد الإلكتروني أو رقم الجوال".
    - **حجم الحقل**: ارتفاع 50px على الأقل (لتناسب اللمس).
    - **نوع الإدخال**: `email` أو `tel` مع لوحة مفاتيح مناسبة.
    - **التحقق**: عند فقدان التركيز (Blur)، يتم التحقق من صيغة البريد الإلكتروني أو رقم الجوال.

5.  **حقل كلمة المرور**:
    - أيقونة (🔒) في بداية الحقل.
    - Placeholder: "كلمة المرور".
    - **زر إظهار/إخفاء**: (👁️) في نهاية الحقل (لإظهار أو إخفاء النص).
    - **دعم (Caps Lock)**: تنبيه إذا كانت مفتوحة.

6.  **خيارات إضافية** (صف واحد):
    - **الجهة اليمنى**: خانة اختيار (Checkbox) "تذكرني" (مع نص صغير).
    - **الجهة اليسرى**: رابط "نسيت كلمة المرور؟" (نص صغير، باللون الأزرق).

7.  **زر تسجيل الدخول**:
    - زر رئيسي باللون الأزرق (يملأ عرض الشاشة تقريباً).
    - النص: "تسجيل الدخول" (بخط عريض).
    - **ارتفاع الزر**: 55px.
    - **حالة التحميل**: يظهر (Spinner) ويتم تعطيل الزر.

8.  **خيارات المصادقة البيومترية** (Biometric Authentication) - أسفل زر تسجيل الدخول:
    - **زر**: "🔐 دخول بصمة الإصبع" أو "👤 دخول بالوجه" (يظهر فقط إذا كان الجهاز يدعمها وتم تفعيلها مسبقاً).
    - **حجم الزر**: أصغر من زر تسجيل الدخول الرئيسي، بلون رمادي فاتح.

9.  **رابط التسجيل (للمسافرين الجدد)**:
    - في أسفل الشاشة: "ليس لديك حساب؟ سجل الآن" (يؤدي إلى صفحة التسجيل المسبق - Pre-Registration).

10. **تبديل اللغة**: زر (🌐) في أعلى الشاشة (يمين أو يسار) لتغيير اللغة بين العربية والإنجليزية.

### 3. تدفق التفاعل (Interaction Flow)

```mermaid
flowchart TD
    A[فتح التطبيق] --> B[شاشة تسجيل الدخول]
    B --> C{هل تم تفعيل المصادقة البيومترية؟}
    C -- نعم --> D[طلب المصادقة البيومترية (بصمة/وجه)]
    D -- نجاح --> E[تسجيل الدخول التلقائي]
    D -- فشل --> F[الانتقال إلى نموذج الدخول اليدوي]
    C -- لا --> F
    F --> G[إدخال البريد الإلكتروني/الجوال]
    G --> H[إدخال كلمة المرور]
    H --> I[الضغط على زر تسجيل الدخول]
    I --> J[التحقق من صحة البيانات]
    J -- بيانات غير صحيحة --> K[عرض رسالة خطأ]
    K --> G
    J -- بيانات صحيحة --> L[إرسال طلب إلى API]
    L -- 401 Unauthorized --> K
    L -- 200 OK --> M[استلام JWT Token]
    M --> N[تخزين التوكن بشكل آمن]
    N --> O[تحديد دور المستخدم]
    O --> P[التوجيه إلى الشاشة الرئيسية للمستخدم]
```

#### 3.1. حالات إعادة التوجيه حسب الدور (Mobile App Roles)

| الدور | الشاشة المستهدفة |
| :--- | :--- |
| **المسافر (Traveler)** | `Dashboard` (الشاشة الرئيسية للمتابعة) |
| **موظف الحجر (Port Officer)** | `PortHealthDashboard` (لوحة الفحص - نادراً ما يستخدم على الجوال) |
| **طبيب (Doctor)** | `ClinicDashboard` (نادراً ما يستخدم على الجوال) |

#### 3.2. حالات الخطأ (Error States)

| حالة الخطأ | الرسالة المعروضة | الإجراء التلقائي |
| :--- | :--- | :--- |
| **حقل البريد الإلكتروني/الجوال فارغ** | "يرجى إدخال البريد الإلكتروني أو رقم الجوال." | تمييز الحقل باللون الأحمر + اهتزاز خفيف (Haptic Feedback). |
| **حقل كلمة المرور فارغ** | "يرجى إدخال كلمة المرور." | تمييز الحقل باللون الأحمر + اهتزاز خفيف. |
| **بيانات دخول غير صحيحة** | "البريد الإلكتروني أو كلمة المرور غير صحيحة. حاول مرة أخرى." | ظهور (Toast) أحمر في أسفل الشاشة، مسح حقل كلمة المرور. |
| **الحساب معطل** | "هذا الحساب معطل. يرجى التواصل مع الدعم الفني." | ظهور (Toast) أحمر، تعطيل زر الدخول. |
| **مشكلة في الاتصال بالخادم** | "تعذر الاتصال بالخادم. تحقق من اتصالك بالإنترنت." | ظهور (Toast) أحمر مع زر "إعادة المحاولة". |
| **فشل المصادقة البيومترية** | "فشل التعرف. يرجى استخدام كلمة المرور." | الانتقال إلى نموذج الدخول اليدوي تلقائياً. |

#### 3.3. حالات النجاح (Success States)
- ظهور (Toast) أخضر "مرحباً [اسم المستخدم]!" مع إعادة توجيه تلقائي بعد 1 ثانية.
- تخزين الـ JWT Token في (Secure Storage) الخاص بالجهاز (مثل: Keychain في iOS، Keystore في Android).

### 4. اعتبارات أمنية خاصة بالجوال (Mobile Security Considerations)

1.  **تخزين آمن للتوكنات**: استخدام (Flutter Secure Storage) أو ما يعادله لتخزين (Access Token) و (Refresh Token) بشكل مشفر.
2.  **المصادقة البيومترية**: استخدام (Local Authentication) في Flutter لدعم بصمة الإصبع والتعرف على الوجه.
3.  **حماية من هجمات (Man-in-the-Middle)**: استخدام (Certificate Pinning) (اختياري للمستقبل).
4.  **تقييد عدد المحاولات الفاشلة**: بعد 5 محاولات فاشلة، يتم تأخير المحاولة التالية لمدة دقيقة (مع ظهور مؤقت).
5.  **مدة الجلسة**: جلسة قصيرة (15-30 دقيقة) مع إمكانية التجديد التلقائي (Refresh Token) في الخلفية.
6.  **تسجيل الخروج التلقائي**: عند إغلاق التطبيق لفترة طويلة، يتم تسجيل الخروج تلقائياً.

### 5. واجهة المستخدم (UI) - التفاصيل البصرية للجوال

#### 5.1. الألوان
- **الخلفية**: لون أبيض أو أزرق فاتح جداً (`#F5F9FF`).
- **النموذج**: خلفية بيضاء مع ظل خفيف (Box Shadow) وحواف مستديرة (Border Radius: 16px).
- **الأزرار**: اللون الأساسي للمنصة (أزرق غامق `#0D47A1`) مع hover (أزرق أفتح).
- **رسائل الخطأ**: أحمر (`#C62828`).
- **رسائل النجاح**: أخضر (`#2E7D32`).

#### 5.2. الخطوط
- **الخط العربي**: Tajawal أو Dubai Font.
- **الخط الإنجليزي**: Inter.
- **أحجام الخطوط** (للجوال):
  - العنوان الرئيسي: 22px (وزن 700).
  - النص الفرعي: 14px (وزن 400).
  - التسميات (Labels): 14px (وزن 500).
  - رسائل الخطأ: 13px (وزن 400).

#### 5.3. الصور والأيقونات
- **شعار المنصة**: في أعلى النموذج (حجم مناسب 60x60).
- **أيقونات الحقول**: من (Material Icons) أو (FontAwesome) بحجم 20px.
- **خلفية**: (اختياري) صورة خلفية بسيطة مع تراكب شفاف لتسهيل القراءة.

### 6. اعتبارات تجربة المستخدم (UX) على الجوال

| العنصر | الاعتبار |
| :--- | :--- |
| **حجم الأزرار** | يجب أن لا يقل ارتفاع الأزرار عن 48px لتسهيل النقر بالإبهام. |
| **حجم الحقول** | يجب أن لا يقل ارتفاع الحقول عن 50px لتسهيل الكتابة. |
| **المسافات (Spacing)** | استخدام مسافات كافية بين العناصر (16-24px) لتجنب النقر الخطأ. |
| **لوحة المفاتيح** | استخدام (TextInputType.emailAddress) و (TextInputType.phone) لعرض لوحة المفاتيح المناسبة. |
| **اللمس (Haptic Feedback)** | توفير ردود فعل لمسية خفيفة عند النقر على الأزرار (Vibration). |
| **التنبيهات (Toasts)** | ظهور التنبيهات في أسفل الشاشة (Bottom Sheet) أو (Snackbar) لتكون في متناول الإبهام. |
| **وضع عدم الاتصال (Offline)** | إذا لم يكن هناك اتصال بالإنترنت، يتم عرض رسالة "أنت غير متصل بالإنترنت. يرجى الاتصال للمتابعة." |
| **إدارة الجلسة** | في حال انتهاء صلاحية (Access Token)، يتم استخدام (Refresh Token) تلقائياً في الخلفية دون إزعاج المستخدم. |

### 7. التكامل مع واجهات برمجة التطبيقات (API Integration)

| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/auth/login/` | المصادقة وإرجاع (Access Token) و (Refresh Token) وبيانات المستخدم. |
| `POST` | `/api/v1/auth/refresh/` | تحديث (Access Token) باستخدام (Refresh Token) (يُستخدم في الخلفية). |
| `POST` | `/api/v1/auth/logout/` | تسجيل الخروج (إبطال Refresh Token). |
| `POST` | `/api/v1/auth/biometric/` | (اختياري) تسجيل بيانات المصادقة البيومترية (للمرة الأولى). |

**نموذج طلب (Login Request):**
```json
{
  "email_or_phone": "user@example.com",
  "password": "SecurePass123!"
}
```

**نموذج استجابة (Login Response) - 200 OK:**
```json
{
  "status": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 1800,
    "user": {
      "id": "uuid",
      "full_name": "محمد أحمد",
      "role": "TRAVELER"
    }
  }
}
```

### 9. ملخص النقاط الرئيسية

| العنصر | الوصف |
| :--- | :--- |
| **الغرض** | توفير بوابة دخول سريعة وآمنة لمستخدمي تطبيق الجوال. |

| **التجاوب** | مصمم خصيصاً للهواتف الذكية (iOS و Android). |
| **التقنية** | Flutter (Cross-Platform) كما هو محدد في هيكل المشروع. |
