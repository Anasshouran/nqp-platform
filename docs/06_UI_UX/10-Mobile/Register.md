### 📄 2. `Register.md` (شاشة إنشاء حساب جديد / التسجيل)

```markdown
# شاشة إنشاء حساب جديد (Register) - تطبيق الجوال

## 1. الهدف
تمكين المسافر الجديد (المريض) من إنشاء حساب في تطبيق المتابعة الصحية بسرعة وسهولة. تتضمن العملية (إدخال البيانات الأساسية، إنشاء كلمة مرور، والموافقة على الشروط). بعد إنشاء الحساب، يتم إرسال رابط التفعيل إلى البريد الإلكتروني (أو يتم تفعيل الحساب تلقائياً إذا كان معتمداً من بوابة المسافرين مسبقاً).

## 2. تصميم الشاشة (Layout) - Mobile-First

### 2.1. الهيكل العام (Single Column - ملء الشاشة مع تمرير)
- **خلفية**: لون موحد (أبيض أو أزرق فاتح جداً) مع شعار المنصة في الأعلى.
- **المحتوى**: يتمركز في منتصف الشاشة مع إمكانية التمرير (Scroll) إذا كان المحتوى طويلاً.
- **عدد الخطوات**: نموذج واحد طويل (أو مقسم إلى خطوتين حسب رؤية التصميم، ولكنني سأقدمه كنموذج واحد طويل مع أقسام).

### 2.2. مكونات النموذج (Form Components)

#### القسم 1: المعلومات الشخصية (Personal Information)
- **شعار المنصة** (مصغر) في أعلى النموذج.
- **عنوان الصفحة**: "إنشاء حساب جديد" (بخط كبير).
- **نص فرعي**: "أدخل بياناتك لبدء متابعة حالتك الصحية."
- **حقل الاسم الكامل**:
  - أيقونة (👤) في بداية الحقل.
  - Placeholder: "الاسم الكامل".
  - نوع الإدخال: `text`.
- **حقل البريد الإلكتروني**:
  - أيقونة (📧) في بداية الحقل.
  - Placeholder: "البريد الإلكتروني".
  - نوع الإدخال: `email`.
- **حقل رقم الجوال**:
  - أيقونة (📱) في بداية الحقل.
  - Placeholder: "رقم الجوال".
  - نوع الإدخال: `phone` (مع رمز الدولة +249).
- **حقل رقم جواز السفر** (اختياري في التطبيق، لكن قد يكون مطلوباً للمزامنة مع بوابة المسافرين):
  - أيقونة (🛂) في بداية الحقل.
  - Placeholder: "رقم جواز السفر (اختياري)".
  - نوع الإدخال: `text` (حروف وأرقام كبيرة).

#### القسم 2: كلمة المرور (Password)
- **حقل كلمة المرور**:
  - أيقونة (🔒) في بداية الحقل.
  - Placeholder: "كلمة المرور".
  - زر إظهار/إخفاء (👁️) في نهاية الحقل.
  - متطلبات كلمة المرور: (8 أحرف على الأقل، حروف كبيرة وصغيرة، أرقام، رموز) - تظهر كـ (Checklist) أسفل الحقل.
- **حقل تأكيد كلمة المرور**:
  - أيقونة (🔒) في بداية الحقل.
  - Placeholder: "تأكيد كلمة المرور".
  - زر إظهار/إخفاء (👁️) في نهاية الحقل.

#### القسم 3: الموافقة والشروط (Agreement)
- **خانة اختيار**: "أوافق على شروط الاستخدام وسياسة الخصوصية." (نص قابل للنقر لفتح الشروط).
- **خانة اختيار**: "أوافق على تلقي الإشعارات والتذكيرات الصحية." (اختياري).

#### القسم 4: زر التسجيل (Sign Up)
- **زر**: "إنشاء حساب" (باللون الأزرق، يملأ عرض الشاشة).
- **زر**: "تسجيل الدخول" (في الأسفل، نص أزرق: "لديك حساب؟ تسجيل الدخول").

## 3. تدفق التفاعل (Interaction Flow)

```mermaid
flowchart TD
    A[فتح شاشة التسجيل] --> B[إدخال البيانات الشخصية]
    B --> C[إدخال كلمة المرور وتأكيدها]
    C --> D[الموافقة على الشروط]
    D --> E[الضغط على زر "إنشاء حساب"]
    E --> F[التحقق من صحة جميع الحقول]
    F -- بيانات غير صحيحة --> G[عرض رسائل الخطأ بجانب كل حقل]
    G --> B
    F -- بيانات صحيحة --> H[إرسال طلب إلى API]
    H -- 409 Conflict (بريد إلكتروني مكرر) --> I[عرض رسالة "البريد الإلكتروني مستخدم بالفعل"]
    I --> B
    H -- 201 Created --> J[استلام تأكيد إنشاء الحساب]
    J --> K[إرسال رابط التفعيل إلى البريد الإلكتروني]
    K --> L[عرض رسالة نجاح "تم إنشاء الحساب بنجاح. يرجى تفعيل حسابك عبر البريد الإلكتروني."]
    L --> M[إعادة التوجيه إلى شاشة تسجيل الدخول]
```

### 3.1. حالات الخطأ (Error States)

| حالة الخطأ | الرسالة المعروضة | الإجراء التلقائي |
| :--- | :--- | :--- |
| **الاسم الكامل فارغ** | "يرجى إدخال الاسم الكامل." | تمييز الحقل باللون الأحمر. |
| **البريد الإلكتروني غير صحيح** | "يرجى إدخال بريد إلكتروني صحيح." | تمييز الحقل باللون الأحمر. |
| **رقم الجوال غير صحيح** | "يرجى إدخال رقم جوال صحيح (مثال: 0912345678)." | تمييز الحقل باللون الأحمر. |
| **كلمة المرور ضعيفة** | "كلمة المرور يجب أن تحتوي على 8 أحرف على الأقل، حروف كبيرة وصغيرة، أرقام، ورموز." | تمييز الحقل باللون الأحمر وعرض المتطلبات. |
| **كلمتا المرور غير متطابقتين** | "كلمتا المرور غير متطابقتين." | تمييز الحقلين باللون الأحمر. |
| **عدم الموافقة على الشروط** | "يجب الموافقة على شروط الاستخدام وسياسة الخصوصية." | تمييز خانة الاختيار باللون الأحمر. |
| **البريد الإلكتروني مستخدم بالفعل** | "البريد الإلكتروني مستخدم بالفعل. يرجى تسجيل الدخول أو استخدام بريد آخر." | تمييز الحقل باللون الأحمر. |
| **رقم الجوال مستخدم بالفعل** | "رقم الجوال مستخدم بالفعل. يرجى استخدام رقم آخر." | تمييز الحقل باللون الأحمر. |

### 3.2. حالات النجاح (Success States)
- ظهور (Toast) أخضر "✅ تم إنشاء الحساب بنجاح. يرجى تفعيل حسابك عبر البريد الإلكتروني."
- إعادة التوجيه التلقائي إلى شاشة تسجيل الدخول بعد 3 ثوانٍ.

## 4. اعتبارات أمنية (Security Considerations)

1.  **تشفير كلمة المرور**: يتم تشفير كلمة المرور في الخادم باستخدام (bcrypt).
2.  **التحقق من البريد الإلكتروني**: إرسال رابط تفعيل إلى البريد الإلكتروني (لتأكيد ملكية البريد). الحساب غير نشط حتى يتم التفعيل.
3.  **حماية من هجمات (Brute Force)**: إضافة (Rate Limiting) على واجهة التسجيل (منع إنشاء حسابات متعددة من نفس الـ IP).
4.  **التحقق من صحة البيانات**: يتم التحقق من جميع الحقول في الخادم (Server-Side Validation) بالإضافة إلى التحقق في العميل (Client-Side).
5.  **تسجيل محاولات التسجيل الفاشلة** في (Audit Log) لأغراض أمنية.

## 5. واجهة المستخدم (UI) - التفاصيل البصرية للجوال

### 5.1. الألوان
- **الخلفية**: لون أبيض أو أزرق فاتح جداً (`#F5F9FF`).
- **الأزرار**: اللون الأساسي للمنصة (أزرق غامق `#0D47A1`).
- **رسائل الخطأ**: أحمر (`#C62828`).
- **رسائل النجاح**: أخضر (`#2E7D32`).

### 5.2. الخطوط
- **الخط العربي**: Tajawal أو Dubai Font.
- **الخط الإنجليزي**: Inter.
- **أحجام الخطوط** (للجوال):
  - العنوان الرئيسي: 22px (وزن 700).
  - النص الفرعي: 14px (وزن 400).
  - التسميات (Labels): 14px (وزن 500).
  - رسائل الخطأ: 13px (وزن 400).

### 5.3. متطلبات كلمة المرور (Password Requirements Checklist)
- **عرضها كقائمة أسفل حقل كلمة المرور**:
  - ☑️ 8 أحرف على الأقل.
  - ☑️ حرف كبير واحد على الأقل.
  - ☑️ حرف صغير واحد على الأقل.
  - ☑️ رقم واحد على الأقل.
  - ☑️ رمز واحد على الأقل.
- **تحديث الحالة**: يتغير لون النص من الرمادي إلى الأخضر عند تحقق الشرط.

## 6. نقاط النهاية الخلفية (API Endpoints)

| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/v1/auth/register/` | إنشاء حساب جديد (إرسال بيانات التسجيل). |
| `POST` | `/api/v1/auth/activate/` | تفعيل الحساب باستخدام رمز التفعيل المرسل عبر البريد الإلكتروني. |
| `POST` | `/api/v1/auth/resend-activation/` | إعادة إرسال رابط التفعيل (في حال لم يصل). |

**نموذج طلب (Register):**
```json
{
  "full_name": "محمد أحمد",
  "email": "user@example.com",
  "phone": "+249123456789",
  "password": "SecurePass123!",
  "password_confirmation": "SecurePass123!",
  "passport_number": "A1234567", // اختياري
  "agree_to_terms": true,
  "agree_to_notifications": true // اختياري
}
```

**نموذج استجابة (Register) - 201 Created:**
```json
{
  "status": "success",
  "message": "تم إنشاء الحساب بنجاح. تم إرسال رابط التفعيل إلى بريدك الإلكتروني.",
  "data": {
    "user_id": "uuid",
    "email": "user@example.com"
  }
}
```

**نموذج استجابة خطأ (409 Conflict - بريد إلكتروني مكرر):**
```json
{
  "status": "error",
  "message": "البريد الإلكتروني مستخدم بالفعل.",
  "errors": {
    "email": "هذا البريد الإلكتروني مسجل بالفعل في النظام."
  }
}
```
