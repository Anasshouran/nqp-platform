# شاشة إدخال النتائج (Results Entry)

## 1. الهدف
تمكين فني المختبر من إدخال نتيجة التحليل المخبري بعد إتمام التحليل، مع إمكانية إضافة قيم رقمية (مثل: Ct Value) وملاحظات إضافية، قبل إرسال النتيجة للمراجعة والاعتماد من قبل المشرف.

## 2. مكونات الشاشة

### 2.1. رأس النموذج (Form Header)
- **الباركود** و **اسم المريض** و **نوع العينة** و **الفحص المطلوب**.
- **حالة العينة**: (🟧 قيد التحليل / 🟦 مسجلة).

### 2.2. نموذج إدخال النتيجة (Result Entry Form)
- **النتيجة النوعية**: (أزرار اختيار (Radio Buttons) كبيرة وواضحة):
  - 🟢 **إيجابي (Positive)**.
  - 🔴 **سلبي (Negative)**.
  - 🟡 **غير محدد (Inconclusive)**.
- **القيمة الرقمية (Numeric Value)** - اختياري:
  - (حقل رقمي مع وحدة قياس (قائمة منسدلة) مثل: `copies/mL`, `mg/dL`).
  - **مثال**: (Ct Value = 32.5).
- **تاريخ ووقت التحليل**: (منتقي تاريخ ووقت، يُملأ تلقائياً ولكن يمكن تعديله).
- **ملاحظات الفني**: (حقل نصي، مثل: "تم إجراء الفحص مرتين للتأكد من النتيجة").

### 2.3. أزرار الإجراء (Action Buttons)
- **زر**: "حفظ النتيجة" (يُغيّر حالة العينة إلى `RESULTS_ENTERED` ويُرسل إشعاراً للمشرف).
- **زر**: "إلغاء" (للعودة إلى قائمة العينات دون حفظ).

### 2.4. قائمة النتائج المدخلة مؤخراً (Recently Entered)
- **جدول** يعرض آخر 5 نتائج تم إدخالها (للفني):
  - الأعمدة: (الباركود، اسم المريض، النتيجة المدخلة، تاريخ الإدخال).

## 3. حالات واجهة المستخدم (UI States)
- **حالة نجاح الحفظ**: رسالة خضراء "تم حفظ النتيجة بنجاح، في انتظار اعتماد المشرف".
- **حالة فشل الحفظ**: رسالة حمراء مع سبب الفشل (مثل: "النتيجة المختارة غير متوافقة مع الفحص المطلوب").
- **حالة النتيجة الحرجة**: إذا كانت النتيجة إيجابية لمرض خطير (PHEIC)، يظهر تحذير أحمر: "⚠️ نتيجة إيجابية لمرض مدرج في قائمة الطوارئ. سيتم إشعار المشرف فوراً."

## 4. نقاط النهاية الخلفية (API Calls)
| نقطة النهاية (Endpoint) | الغرض |
| :--- | :--- |
| `POST /api/v1/lab/samples/{id}/results/` | إدخال النتيجة (إنشاء سجل نتيجة). |
| `GET /api/v1/lab/samples/{id}/results/` | استرجاع النتيجة المدخلة (إن وجدت). |
| `PUT /api/v1/lab/samples/{id}/results/` | تحديث النتيجة (قبل الاعتماد). |
