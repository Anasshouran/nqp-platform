# تحليل نظام NQP — المنصة القومية للحجر الصحي

> تاريخ التحليل: 2026-08-02## 1. نظرة عامة

منصة رقمية متكاملة لإدارة الحجر الصحي والفحوصات والترصد الوبائي في منافذ دخول السودان
(المطارات والموانئ والمعابر البرية)، مع واجهة عامة للمواطنين وواجهة إدارية للعاملين
الصحيين.

## 2. الحالة الراهنة

| العنصر | الحالة |
|---   |---|
| الخوادم | متوقفة (لا خوادم تطبيق تعمل؛ PostgreSQL يعمل) |
| قاعدة البيانات | 69 جدولاً، 7 مستخدمين، 5 أدوار، 70 صلاحية |
| اختبارات Backend | 158/158 نجاح (pytest) |
| بناء Frontend | يمر بنجاح (tsc + vite) |
| ESLint | غير مفعّل (لا يوجد ملف إعداد) |

## 3. المعمارية

```
Public Website (9 صفحات) + Traveler (3) + Admin (8) + Auth (2)
                │  REST (envelope {status,data}) + JWT Bearer
Backend: 19 تطبيق Django (accounts, travelers, screening, laboratory,
         food_quarantine, emergency_eoc, risk_engine, clinic, carriers, ...)
                │
PostgreSQL 16 + PostGIS  |  Redis + Celery  |  MinIO (مستندات)
```

- الواجهة الخلفية: Python 3.11، Django 5.0، DRF 3.15، SimpleJWT
- الواجهة الأمامية: React 19، TypeScript، Vite، MUI 6، Tailwind، Redux Toolkit،
  React Hook Form + Zod، axios
- النشر: Docker، Kubernetes، GitHub Actions (غير مفعّل فعلياً)

## 5. نقاط القوة

1. **توحيد API**: غلاف استجابة `{status, data}` عبر `EnvelopeRenderer` مع
   `StandardPagination` المرن (عبر `page_size`).
2. **RBAC مكتمل**: 5 أدوار + 70 صلاحية، صفحة إدارة الأدوار والصلاحيات في الواجهة،
   تعيين الدور والصلاحيات الإضافية للمستخدمين، أمر `seed_rbac` القابل لإعادة التشغيل.
3. **مكتبة مكونات احترافية**: `DataTable` (بحث/فلترة/فرز/ترقيم/تصدير CSV مع BOM
   للغة العربية)، `StatusChip`، `AppButton`، `ConfirmDialog`.
4. **واجهة RTL كاملة** بخط Cairo وثيم MUI مخصص ودعم `prefers-reduced-motion`.
5. **فصل نظيف للمجالات**: كل وحدة (طوارئ، غذاء، مخاطر، ميناء صحي) بنماذجها الخاصة.
6. **توثيق موسّع**: `docs/` تغطي البنية، UML، APIs، سير العمل، الأمان، ADR.
7. **أمان**: لا أسرار في الكود، JWT + قائمة سوداء للرموز، `IsAdmin` للعمليات
   الإدارية، حماية PROTECT على حذف الأدوار المرتبطة بمستخدمين.

## 6. نقاط الضعف والفجوات (المطلوب معالجتها)

1. **تغطية اختبارات غير متوازنة**: 6 من 16 تطبيقاً فقط مختبرة.
   التطبيقات غير المختبرة: `clinic`, `ports`, `carriers`, `notifications`,
   `integration`, `risk_engine`, `reporting`.
   ولا توجد اختبارات Frontend رغم توفر Vitest.
2. **CI غير مفعّل**: `.github/workflows/` فارغ، و`npm run lint` بلا إعداد ESLint
   (نصّ placeholder).
3. **إعدادات تطوير كإعداد افتراضي**: `DEBUG=True` و`CORS_ALLOW_ALL_ORIGINS` عند
   غياب متغيرات البيئة.
4. **ازدواجية مكتبات الرسم**: chart.js + recharts + ag-grid معاً (~380KB إضافية).
5. **لوحة التحكم/التقارير مبسطة**: تقرير مبني على أول 100 سجل أو بيانات مرجعية،
   لا يعكس العمليات الفعلية لكل الوحدات.
6. **استقرار الخدمة**: الخوادم تتوقف عند انقطاع PostgreSQL/الجلسة؛ لا يوجد سكربت
   تشغيل موحّد (systemd/Docker) موثّق للتشغيل المحلي.
7. **التكاملات غير متصلة**: `integration`, `risk_engine`, `airport_health`,
   `carriers`, `clinic` معرّفة لكنها غير متصلة بالواجهة الإدارية الحالية.
   > تم الربط: `clinic`، `carriers`، `risk_engine`، `integration`، `airport_health`
   > (كلها متصلة بالواجهة الآن).
   > تم الربط: `clinic`، `carriers`، `risk_engine`، `integration`، `airport_health`
   > (كلها متصلة بالواجهة الآن).
8. **توثيق كلمة مرور التطوير**: كلمة مرور أدمن التطوير `AdminDev123!` لمستخدم
   `admin@nqp.gov.sd` — يجب توثيقها أو استبدالها عند الإنتاج.

## 7. توصيات بأولوية التنفيذ

1. إضافة اختبارات Frontend (Vitest) لمكوّني `DataTable` و`RoleFormDialog` وتغطية
   `clinic/ports/carriers`.
2. تفعيل CI: GitHub Actions (pytest + build + ESLint بإعداد حقيقي).
3. إصلاح الإعدادات الافتراضية: منع `DEBUG=True` في الإنتاج وضغط `ALLOWED_HOSTS`.
4. سكربت تشغيل موحّد (`scripts/dev.sh`) يبدأ PostgreSQL + Backend + Frontend مع
   فحص الصحة.
5. دمج مكتبة رسم واحدة وتقليل حجم الحزمة.
6. ربط الوحدات غير المتصلة (clinic, carriers, risk_engine, integration)
   بالواجهة الإدارية.
   > تم التنفيذ: جميعها مرتكزة بالواجهة الإدارية (انظر سجل التحديثات).
7. إعادة تقييم الوضع بعد كل توصية لضمان عدم تراجع التغطية.
