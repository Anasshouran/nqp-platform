# قياس تغطية الواجهة (Frontend Coverage) — M5-D-J2B

## 1. الهدف

توثيق القياس الشامل لتغطية اختبارات الواجهة، واستبدال النطاق القديم المقتصر على `registry` بنطاق يغطي كل `src/**`، حتى تعكس الأرقام الحالة الحقيقية للتطبيق.

> **تنبيه مهم:** سلسلة CI الحالية تشغّل `npm run test` فقط (`.github/workflows/ci.yml:86`) **بدون** `--coverage`. لذلك عتبات التغطية في `vitest.config.ts` لا تعمل كبوابة CI في الوقت الحالي، بل تحمي تشغيل `npm run test:coverage` محليًا.

## 2. المنهجية

- المزوّد: **v8** (`@vitest/coverage-v8@^2.1.9`).
- النطاق: `src/**/*.{ts,tsx}` مع استبعاد ملفات الاختبار والـmocks وإعلانات الأنواع و`src/test/**`.
- التشغيل: `npm run test:coverage` (بعد التحديث). أُجري القياس لأول مرة بـ`--testTimeout=30000`، ثم ثُبّت هذه القيمة في الإعداد لأن اختبارين تجاوزا حد 10 ثوانٍ تحت الـinstrumentation.
- أُخرِج تقرير `json-summary` وحُلّلت الأرقام منه (لا من تقرير نصي فقط) لحساب الإجماليات المرجّحة لكل مجموعة.

## 6. ملاحظات تفسيرية

- نسبة Functions أقل بكثير من Lines/Branches على مستوى التطبيق كله؛ هذا سلوك معروف لـv8 ولا يعني أن ثلث المنطق غير مختبر بالضرورة. للمقارنة بين الإصدارات، يُفضّل استخدام Lines وBranches.
- في المحاولة الأولى للقياس الشامل بحدّ 10 ثوانٍ، فشل اختباران (`FoodOpsPage` و`SurveillanceModulePage`) بسبب بطء الـinstrumentation فقط (13.7s و10.05s)؛ نجحا بعد رفع الحد إلى 30s. لا علاقة لذلك بصحة الكود.
- التقارير النصية و`lcov` و`html` تُنشأ في `frontend/coverage/` (مستبعدة من Git عبر `.gitignore`).
